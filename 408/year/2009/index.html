本题讲解：打印缓冲区为什么是队列

第一步：抓住题干的关键次序

主机把要打印的数据依次写入缓冲区，打印机再依次取出打印。要保证一份文档先写的先打、页序不乱，缓冲区必须做到：先进入的数据先出去（先进先出，FIFO）。缓冲区本身就是一个线性排队场所，考的就是为「依次进、依次出」选对逻辑结构。

第二步：用四种结构逐一对照

选项结构存取特征是否符合题意
A栈后进先出，最后写入的先被取走，页序颠倒否
B队列先进先出，写入次序等于打印次序是
C树一对多的层次关系，没有排队次序否
D图多对多的网状关系，更无先后次序否

易错点

  • 误选栈：栈适合「后到先服务」的场景（函数调用、括号匹配、撤销操作），打印任务恰恰要求「先到先服务」。
  • 误选树或图：它们描述的是元素之间的层次或关联关系，不是「按到达时间依次排队」的线性结构；缓冲区数据的进出次序是核心，层次和网状关系都帮不上忙。
结论：答案选 B（队列）。凡是「先到先服务、需要保序」的缓冲场景（打印缓冲区、键盘输入缓冲区），逻辑结构都是队列。

答案

答案：C

▶本题解析视频（B 站）

📺 解析视频

本题讲解：由出队顺序反推栈的最小容量

第一步：把题意翻译成进出栈序列

每个元素出栈后立即入队，所以出队顺序就是出栈顺序：b, d, c, f, e, a, g；而入栈顺序固定为 a ~ g。问题变成：支持这组出栈序列的最小栈深是多少。求最小容量的标准策略是按需进栈：想出栈谁，才把它（连同压在它上面的元素）压进来，能不压就不压。

第二步：逐步模拟

操作栈内（右为栈顶）已出队栈深
进 a、进 ba b—2
出 bab1
进 c、进 da c db3
出 d、出 cab d c1
进 e、进 fa e fb d c3
出 f、出 e、出 a空b d c f e a0
进 g、出 g空b d c f e a g1

第三步：看最大栈深

峰值出现在「c、d 连压」和「e、f 连压」两个时刻，都是 3。为什么必须连压：d 要先于 c 出栈，而 c 已入栈，只能压上 d 等 d 先走；f 对 e 同理。容量为 2 时 d 根本进不去，序列无法完成，所以容量至少为 3。

易错点

  • 误算成 2：只盯着「大多数时候栈里只有 1～2 个元素」，忽略了峰值瞬间。
  • 误算成 4 以上：把 a ~ g 全部先压完再出栈，那样出栈序是 g…a，根本得不到要求的序列。
结论：答案选 C（栈的容量至少是 3）。

本题讲解：平衡二叉树的判定

第一步：明确判定标准

平衡二叉树（AVL 树）：任意结点的左、右子树高度之差的绝对值不超过 1（空子树高度记 0）。判定从根往下逐点检查，只要有一个结点失衡，整棵树就不合格。

第二步：逐个候选检查根结点

选项根的左子树根的右子树平衡因子判定
A高 2空（高 0）2失衡
B高 2高 20平衡
C高 1一条 3 层以上的斜链差 ≥ 2失衡
D深达 4 层的左链高 1差 ≥ 2失衡

A 的根只有左子树；C、D 的根都是「一头沉」的形态。

第三步：B 还要检查下层结点

B 的根平衡因子为 0；左孩子的左子树高 1、右子树为空，平衡因子绝对值 1；右孩子对称。所有结点都满足高度差不超过 1，B 是平衡二叉树。

易错点

  • 只看根不看下层：本题的失衡点恰好都能从根看出，但下层同样可能失衡（比如 B 的左孩子若右子树高 2 就失衡了），完整判定必须逐结点检查。
  • 忘记空子树高度记 0：A 中「只有左子树」的根，高度差是 2 而不是 1。
结论：答案选 B。

树森林
choice 2 分

将森林转换为对应的二叉树，若在二叉树中，结点 u 是结点 v 的父结点的父结点，则在原来的森林中，u 和 v 可能具有的关系是__。

I. 父子关系

II. 兄弟关系

答案

答案：B

6
📺 解析视频

本题讲解：森林转二叉树后的祖孙关系反推

第一步：转换规则是解题钥匙

森林 → 二叉树的规则是「左孩子、右兄弟」：二叉树中某结点的左孩子是它在森林中的第一个孩子，右孩子是它的下一个兄弟。设 v 在二叉树中的父结点为 w，而 w 的父结点是 u（即 u 是 v 在二叉树中的「祖父」）。

第二步：枚举 v、w 各挂在左还是右

v 可能是 w 的左孩子或右孩子，w 也可能是 u 的左孩子或右孩子，共 4 种组合，逐一翻译回森林：

组合二叉树中的位置翻译回森林得到的关系
1v 是 w 的左孩子，w 是 u 的左孩子v 是 w 的第一个孩子，w 是 u 的第一个孩子u 是 v 的祖父，三种关系都不满足
2v 是 w 的右孩子，w 是 u 的左孩子v 是 w 的下一个兄弟，w 是 u 的孩子w、v 同为 u 的孩子 → I 父子关系，可能
3w 是 u 的右孩子，v 是 w 的右孩子w 是 u 的下一兄弟，v 是 w 的下一兄弟u、w、v 是同父的三兄弟 → II 兄弟关系，可能
4w 是 u 的右孩子，v 是 w 的左孩子u 与 w 是兄弟，v 是 w 的第一个孩子u 与 v 是伯侄；u 的父结点与 v 的父结点（w）是父子不是兄弟，III 不成立

第三步：结论

I、II 都能找到合法组合；III 在任何组合下都推不出来——v 的父结点要么就是 w 本身（它与 u 的父结点是父子关系），要么与 u 的父结点是同一个结点（同一人谈不上互为兄弟）。

易错点

  • 漏掉组合 2：只想到「祖父」情形（组合 1），漏掉了 v 挂右边变成兄弟、进而与 u 成父子的可能。
  • 误认为 III 可能：「u 的父结点与 v 的父结点是兄弟」意味着 u 自己只是 v 父结点的兄弟，此时 u 根本当不成 v 的祖父。
结论：答案选 B（I 和 II）。

本题讲解：无向连通图的三条性质

第一步：区分「恒成立」与「可能成立」

判断标准只有两条：要么给出对所有无向连通图都成立的理由，要么举出一个反例把叙述否决。三条叙述逐条过。

第二步：逐条验证

叙述分析判定
I. 所有顶点的度之和为偶数无向图每条边给两个端点各贡献 1 度，度之和 = 2 × 边数，必为偶数（握手定理，与是否连通无关）恒成立
II. 边数大于顶点个数减 1n 个顶点的树就是无向连通图，边数恰好等于 n − 1，并不「大于」不成立
III. 至少有一个顶点的度为 13 个顶点构成三角形（环）：每个顶点的度都是 2，没有度为 1 的顶点不成立

第三步：锁定答案

易错点

  • 误选 II：把「连通图边数至少 n − 1」错记成「大于 n − 1」——树正是取等号的反例。
  • 误选 III：忽略环形与稠密结构——环上每点度数为 2，完全图各点度数更大，都不存在度为 1 的顶点。
结论：答案选 A（只有 I）。

本题讲解：m 阶 B 树定义的正误辨析

第一步：回忆 m 阶 B 树的定义要点

一棵 m 阶 B 树满足：① 根结点最多有 m 棵子树（若非叶则至少 2 棵）；② 除根外，每个非叶结点至少有 ⌈m/2⌉ 棵子树、至多有 m 棵子树；③ 所有叶结点（查找失败的失败结点）出现在同一层；④ 结点内的关键字按升序（或降序）有序排列。题目要找「不符合」的一条。

第二步：逐项对照

选项叙述对照定义
A根结点最多有 m 棵子树与要点①一致，符合
B所有叶结点都在同一层上与要点③一致，符合
C各结点内关键字均升序或降序排列与要点④一致，符合
D叶结点之间通过指针链接定义中没有这一条，不符合

第三步：D 为什么不属于 B 树

「叶子之间用指针串成有序链表」是 B+ 树的标志性特征：B+ 树把全部关键字集中在叶子层并链接起来以支持顺序（范围）查找。m 阶 B 树的关键字分散在所有结点中，叶子（失败结点）之间没有链接指针。

易错点

  • 混淆 B 树与 B+ 树：见「叶子串链表」就想到 B 树，正是本题设的陷阱——那是 B+ 树的特性。
  • 误以为 B 不符合：「所有叶结点在同一层」恰恰是 B 树绝对平衡的体现，是定义原文。
结论：答案选 D。

  • 二路归并：每趟两两归并使有序段长度翻倍（1→2→4），第 2 趟后每 4 个一组各自有序，组间可以无序。

本题讲解：综合考虑等待时间与执行时间的调度算法

答案：D（高响应比优先）。

第 0 步：先立机制——「挑选依据」决定算法看哪些时间

调度算法的差别全在「下一次让谁上 CPU」的挑选依据上，它是否考虑等待时间、执行时间由此直接推出：

  • 时间片轮转：按就绪队列顺序轮流执行固定时间片，不比较任何时间属性——等待时间、执行时间都不参与决策；
  • 先来先服务：按到达先后排队——只有等待时间起作用，执行时间不影响次序，长作业后到也会把短作业「堵死」；
  • 短进程优先：每次挑预计服务时间最短的——只有执行时间起作用，等待时间不参与比较，长作业可能被不断新来的短作业挤得饥饿；

第 1 步：R 的公式为什么算「综合考虑」

等待时间 W 与服务时间 S 同时进入 R 的取值：S 越小 R 越大（短作业相对优先）；W 越大 R 越大（等得久优先级自动升高）。为什么长作业不会饿死——长作业刚到达时 R ≈ 1 排在后面，但 W 随时间流逝持续增大，R 终会反超后来短作业的 R 而被选中；这正是只看 S 的短进程优先缺的那份保险。

  • 记错分子：分子是「等待 + 服务」之和，不是只有等待时间。
记忆锚点：R = 1 + W/S——W 负责「不饿死」，S 负责「短者优先」，两者同时起作用才叫综合考虑。

【答案】

1）算法基本设计思想：

  • 否则， p = p → link ， q = q → link 。

    int data;
    struct LNode *link;
} *LinkList;

int Search_k(LinkList list, int k) {

    int count = 0;
    while (p != NULL) {
        if (count < k) {       // p先前进k步
            p = p->link;
            count++;
        } else {               // 之后p和q同步前进
            p = p->link;
            q = q->link;
        }

本题讲解：单链表倒数第 k 个结点 —— 双指针一次遍历

第 0 步：机制先行——「倒数第 k」为什么难，双指针为什么行

单链表只能沿 link 单向走、不能随机访问，「倒数第 k 个」没有现成地址可算。直觉做法是两趟：先数出表长 n，再从头走 n−k+1 步。但链表一遍走完之前无法先知 n，而题目要求「尽可能高效」——所以要把「倒数」换成另一种度量方式。

双指针的机制一句话：用「距链尾的距离」定义「倒数」。让 p 先走 k 步，在链上制造出一段固定间隔，然后 p、q 同步前进、间隔保持；当 p 越过链尾（p == NULL）时，q 距链尾恰好 k 个结点——这正是倒数第 k 个。

这套机制靠三条推理支撑，也是最容易被追问的三个「为什么」：

  • 为什么间隔是 k？ p 先行阶段每步只动 p 不动 q，p 比 q 多走 1 步/次，走 k 次后两者恰好相差 k 步。
  • 为什么间隔一直不变？（循环不变量）同步阶段 p、q 每轮各前移 1 步，走过的步数始终相同，差值自然保持 k。
  • 为什么 p == NULL 时 q 就是倒数第 k 个？ 设表长 n，p == NULL 说明 p 已越过最后一个结点；q 比 p 落后 k 步，故 q 停在第 n−k+1 个结点，从后往前数正是第 k 个。举例验证：表长 5、k = 2——p 先行 2 步后指向第 3 个结点；同步走 3 步后 p 变 NULL，q 从第 1 个走到第 4 个，倒数第 2 个恰是第 4 个。✔

为什么用 count 判失败？ count 只在 p 先行阶段累加。若表长不足 k，p 没走满 k 步就越过了链尾，循环结束时 count < k——「间隔没能建成」就是 k 非法的信号，返回 0。

问 1：算法的基本设计思想

设 p、q 初始均指向第一个结点。p 先沿链走 k 步（若中途 p 为空，说明 k 超过表长，查找失败）；随后 p、q 同步后移、保持间隔 k；当 p 到达链尾（NULL）时，q 所指即倒数第 k 个结点。全程一遍遍历，时间 O(n)，辅助变量仅常数个——这比两趟法（先求表长再定位）少一整趟扫描，是「尽可能高效」的落点。

  2. 当 p 不为空时循环：若 count < k，只让 p 后移一步、count 加 1（p 先行建间隔）；否则 p、q 同时后移一步（间隔已建成，同步走）。
  3. 循环结束后：若 count = k，q 即倒数第 k 个结点，输出 q 的 data 域并返回 1；若 count < k，说明 k 超出表长，返回 0。

第 0 步：机制先行——CPU 的时间账本怎么记

  1. 每秒中断次数：外设每秒送来 0.5MB = 500 000 B（本题按十进制换算，1MB = 10⁶ B，与参考答案一致），每 4B 触发一次中断 → 500 000 ÷ 4 = 125 000 次。
  2. 每次中断的 CPU 开销：(18 + 2) 条指令 × CPI 5 = 100 个时钟周期。
  3. 每秒总开销：125 000 × 100 = 12 500 000 = 12.5M 个周期。
  4. 占比：12.5M ÷ 500M = 2.5%。

问 2：DMA 方式（5MB/s，块大小 5000B）

  1. 每秒 DMA 次数：5MB = 5 000 000 B，每块 5000B → 5 000 000 ÷ 5000 = 1000 次。
  2. 每次 CPU 的开销：只有预处理 + 后处理的 500 个周期；5000B 的搬运期间 CPU 零开销（无访存冲突假设）。
  3. 每秒总开销：1000 × 500 = 500 000 = 0.5M 个周期。
  4. 占比：0.5M ÷ 500M = 0.1%。

为什么占比从 2.5% 骤降到 0.1%？ 对比两条分子：中断方式把开销摊在每一个 4B 上（每秒 12.5 万次中断 × 每次 100 周期）；DMA 把同样的搬运打包成 1000 块，每块只付一次 500 的固定费用——CPU 的介入次数从 12.5 万次降到 1 千次。数据率虽扩大 10 倍，CPU 负担反而缩小 25 倍，这正是「成块传送、传送期间让位」的 DMA 机制优势。

易错点

  • 漏掉「其他开销折合 2 条指令」：只按 18 条算得每次 90 周期、占比 2.25%。
  • 把 DMA 的数据搬运时间计入 CPU：搬运由 DMA 控制器完成，CPU 只出 500 周期的前后处理；题设无访存冲突，连周期窃取的等待也不计。
  • 单位换算纠结：0.5MB/s 即每秒 0.5 × 10⁶ 字节，主频 500MHz 即每秒 500 × 10⁶ 个周期，都按 10⁶ 口径直接相除即可，不必换算成秒以下的物理时间。
一句话结论：中断 2.5%、DMA 0.1%——占比 = 每秒事件次数 × 每次 CPU 周期数 ÷ 主频；两种方式的差别只在「事件粒度」。

第 0 步：机制先行——单内总线数据通路的运行规则

先看清数据通路图的骨架：R0、R1、PC、IR、MAR、MDR、A、AC 都挂在一条内总线上；ALU 的一个输入端接暂存器 A，另一个输入端直接取自内总线，运算结果送 AC。访存走另一条外部通路：地址由 MAR 送出（题设 MAR 输出一直使能，地址可长期保持），数据经 DB 进出 MDR——所以 MDR 有两套门口：对内的 MDRin/MDRout，对外的 MDRinE/MDRoutE。

由「一条内总线」直接推出列节拍的三条铁律：

  1. 一拍一次总线传送：同一拍不能有两个部件同时往内总线送数，一个部件也不能「既被打入又被读走」。
  2. 访存前地址必须就位：读操作以 MAR 的当前内容为地址，MAR←(R1) 与 MDR←M(MAR) 有数据依赖，不能同拍。
  3. ALU 两端不能都等总线：两个源操作数必须有一个先锁进 A，另一拍另一个操作数才上总线进 ALU。

执行阶段的目标：(R0) + ((R1)) → (R1) 所指主存单元。取指与译码（C1~C4）已完成，剩下的活分三段：取内存操作数 → 相加 → 写回主存。逐拍问「这拍总线上走什么、谁被打入」，方案自然出来。

基本方案（6 拍）：一步一步走

C6MDR ← M(MAR)MemR, MDRinE

逐拍为什么这样安排：

  • C5 → C6：先送地址再访存（铁律 2）。收数走外部通路，故用 MDRinE（从 DB 打入 MDR）配读命令 MemR。
  • C7：操作数已在 MDR，但若下一拍让 MDR 直接上内总线给 ALU，R0 就上不了总线（铁律 1）——所以先把 (MDR) 锁进 A 腾出总线（铁律 3）。

优化方案（5 拍）：C6 并行塞进第二件事

C6 的访存读走「存储器 ↔ DB」这条外部通路，而 R0 → A 走内总线，两条通路互不干扰，目标寄存器也不同（MDR 与 A），无数据依赖——满足相容性，可以同拍并行，省掉单独锁 A 的一拍：

节拍功能有效控制信号
C5MAR ← (R1)R1out, MARin
C6MDR ← M(MAR), A ← (R0)MemR, MDRinE, R0out, Ain
C7AC ← (MDR) + (A)MDRout, Add, ACin
C8MDR ← (AC)ACout, MDRin
C9M(MAR) ← (MDR)MDRoutE, MemW

为什么 C6 不能顺手把加法也做了？ 此刻 MDR 正从 DB 收数，同时又要 MDRout 读它给 ALU——「既打入又读出」违反铁律 1；加法只能等数据落定后的下一拍（C7），此时 A 里是 R0、MDR 里是内存操作数，MDRout 送数上总线即可。

易错点

  • 写回漏 MDRoutE / MemW：写主存必须用外部通路 MDRoutE + MemW；只给 MDRout 是往内总线送数，主存收不到。
  • C8 漏 Add：不给 Add，ALU 不知道本次做加法。
  • 合并依赖拍：把 MAR←(R1) 与 MDR←M(MAR) 并到一拍——读操作用的地址还没就位，违反铁律 2。

一句话结论：基本方案 C5~C10 共 6 拍；利用「访存走外部通路、寄存器走内总线」的相容性把 A←(R0) 并入 C6，优化为 C5~C9 共 5 拍。

问 1：定义哪些信号量——先数清题目里有几类「等待」

信号量的机制：P 申请资源，不够则阻塞等待；V 释放资源，唤醒等待者。定义几个信号量，取决于进程间存在几类「等待关系」。本题一共三类：

  1. 等空位：缓冲区共 N 个单元，P1 放数前必须有空单元。这是一种「资源计数」，初值 N。
  2. 等数据：P2 只取奇数、P3 只取偶数——只知道「缓冲区里有数」不够，必须按奇偶分别计数、分别唤醒。两个信号量，初值都是 0（开局无数据，消费者先等）。
  3. 等进入：缓冲区是被三个进程共享读写的数据结构，同一时刻只允许一人进出。互斥信号量，初值 1。

为什么 odd/even 省不掉、不能合成一个「产品数」？ 若只设一个「有数」信号量，P2 被唤醒后取出的可能是偶数，奇偶配对就乱了。本题比普通生产者-消费者多出的一层是产品分流：每种产品单独计数、单独唤醒对应消费者——这正是 odd 与 even 两个信号量的存在理由。

  • P(empty) 与 P(mutex) 顺序颠倒：满缓冲区时抱锁互等 → 死锁。所有 P 操作都要「先同步、后互斥」，不可交换。

  • 信号量含义没说清：每个信号量的初值、物理含义、「谁 P 谁 V」都要写明，这是本题的给分点。
  • empty 初值写错：它数的是空单元，初值是容量 N，不是 0 也不是 1。
一句话结论：mutex 管互斥，empty 管空位（容量），odd/even 管奇偶配对（同步）；P 操作先同步后互斥，V 操作出临界区后再唤醒。

  2. 查 TLB（10ns）：命中，直接得页框号；未命中也要付这 10ns（题设②规定先查 TLB）。
  3. TLB 未命中 → 查页表（100ns）：有效位 1 → 得到页框号（按题设，其后的 TLB 更新不计时）；有效位 0 → 缺页中断，处理耗时 10⁸ ns（题设已含更新 TLB 和页表），处理完返回重新执行该指令——重执时页已进 TLB，按命中路径重新计时。
  4. 访问主存（100ns）：拿到页框号后拼出物理地址，取数据还要真正访存一次——TLB 只负责「地址翻译」，数据本身在内存。

TLB 的状态随访问序列演变：TLB 初始为空；第一次访问后页 2 进 TLB；1565H 的缺页处理把页 1 写入 TLB。这些状态是后面三次计时的依据。

问 1：三个虚地址逐个计时

2362H：页号 2、位移 362H。TLB 空 → 未命中 10ns；查页表，页 2 有效 → 100ns；拼 254H ∥ 362H 后访存 → 100ns。合计 210ns。此后页 2 进入 TLB（更新时间按题设忽略）。

1565H：页号 1、位移 565H。TLB 未命中 10ns；查页表，页 1 有效位 0 → 100ns；缺页中断处理 10⁸ ns（含把页 1 写入 TLB 与页表）；返回重新执行：TLB 命中 10ns + 访存 100ns。合计 10 + 100 + 10⁸ + 10 + 100 = 100000220ns。

25A5H：页号 2、位移 5A5H。页 2 在第一次访问时已进 TLB，且此后没有被移出——缺页处理换出的是主存驻留集里的页 0，TLB 中页 2 → 254H 的表项不受影响 → TLB 命中 10ns + 访存 100ns = 110ns。

虚地址路径计时
2362HTLB 未命中 → 页表有效 → 访存10+100+100 = 210ns
1565HTLB 未命中 → 页表无效 → 缺页处理 → 重执：TLB 命中 → 访存10+100+10⁸+10+100 = 100000220ns
25A5HTLB 命中 → 访存10+100 = 110ns

问 2：1565H 的物理地址为什么是 101565H

先淘汰谁？ 缺页发生时驻留集已满（固定 2 页：页 0 在 101H、页 2 在 254H），必须先淘汰一页再装入页 1。LRU 选「最久未被访问」的驻留页：页 2 刚被 2362H 访问过，页 0 自始至终没被碰过——牺牲的是页 0（注意不是「淘汰页 1」，页 1 本来就不在内存，谈不上淘汰）。页 1 装入页 0 腾出的页框 101H。

地址怎么拼？ 页框大小 = 页面大小 = 4KB，页内位移直接照抄：物理地址 = 页框号 ∥ 页内位移 = 101H ∥ 565H = 101565H。

易错点

  • 漏算缺页后的「重新执行」：题设③明确返回重执，重执的 TLB 命中 10ns + 访存 100ns 不能漏。
  • LRU 选错牺牲页：在驻留的页 0、页 2 之间选最久未用的页 0；页 1 不在驻留集，不是候选。
  • 误判第三次访问：页 2 的 TLB 表项仍有效，25A5H 走命中路径 110ns，不能再算一次页表 100ns。
  • 页号切错：页内位移位数由页面大小决定，4KB → 低 3 位十六进制；2362H 的页号是 2，不是把 236 当页号。
一句话结论：三次访问依次 210ns、100000220ns、110ns；LRU 淘汰页 0，页 1 入驻 101H，物理地址 101565H。

本题讲解：子网划分与两级路由表配置

第 0 步：机制先行——路由器查表的三条规则

后面三问全都建立在这几条机制上，先立起来：

  1. 掩码匹配：表项匹配的条件是「目的地址 AND 子网掩码 = 表项里的目的网络地址」；掩码中 1 的位数就是前缀长度（/25 → 前 25 位全 1）。
  2. 最长前缀优先：多条表项同时匹配时，取前缀最长的——这条规则解释了为什么 /32 主机路由能压过 /0 默认路由被优先选中。
  3. 直连路由免下一跳：目的网络直接挂在本路由器接口所在的链路上，交付由本机接口完成，下一跳写「直接」。

问 1：划分两个子网——先定主机位，再借子网位

为什么计算要减 2？ 一个子网内主机位全 0 是网络地址、全 1 是广播地址，都不能分配给主机，可用地址数 = 2h − 2。

设主机位为 h：2⁶ − 2 = 62 < 120 不够；2⁷ − 2 = 126 ≥ 120 够 → h = 7。/24 本有 8 个主机位，只用 7 位，剩下 1 位借作子网位 → 前缀 /25，掩码 255.255.255.128。子网位取 0/1，把原 /24 从中间一分为二：

  • 主机路由为什么是 /32：域名服务器 202.118.3.2 是一台主机，题目点名要「主机路由」——掩码 32 位全 1，使该表项只匹配它自己；若写成 /24 匹配的就是整个 202.118.3.0/24 网段，不是主机路由。它不在 R1 的直连链路上，须先交给 R2，故下一跳 = R2 的 L0 地址 202.118.2.2，从 L0 口发出。
  • 默认路由为什么是 0.0.0.0/0：掩码全 0 时「目的地址 AND 0 = 0」对任何地址恒成立——它匹配一切目的地址，是兜底表项；去互联网的流量除以上三条外全部走它，下一跳同样是 R2。它只在其他三条都不匹配时才被选中，这一优先顺序正是由最长前缀规则（规则 2）保证的。

问 3：R2 的聚合路由——为什么能合成一条

R2 到两个局域网的下一跳完全相同（都是 R1 的 L0 接口 202.118.2.1），这是聚合的前提。两个 /25 子网地址连续（0～127 与 128～255）、前 24 位完全相同，合并后边界对齐恰好铺满一个 /24 → 聚合为一条：

聚合后 R2 凡见 202.118.1.x 一律交给 R1，再由 R1 用自己的两条 /25 表项区分两个局域网——聚合只发生在「下一跳相同」的边界处，表项数从两条减为一条，这正是路由聚合的价值所在。

易错点

  • 主机位算少：2⁶ = 64 忘了减 2 → 62 < 120 不满足；必须 2⁷ − 2 = 126 才够。
  • 主机路由掩码写 /24：匹配的是网段不是主机，不符合「主机路由」要求。
  • 聚合掩码写 /25：题目要求「采用路由聚合技术」给出一条路由，须聚合到 /24（255.255.255.0）。
  • 下一跳方向写反：R1 的下一跳指向 R2 的 L0（202.118.2.2），R2 的聚合路由下一跳指回 R1 的 L0（202.118.2.1）。
一句话结论：/25 一切为二（126 ≥ 120）；R1 = 两条直连 + 一条 /32 主机路由 + 一条默认路由；R2 聚合为 202.118.1.0/24 交给 R1。
