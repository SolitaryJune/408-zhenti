答案：B

📺 解析视频

本题讲解：数循环次数求时间复杂度

答案：B（O(n1/2)）。 思路：先弄清"循环体到底执行多少次"，再看这个次数随 n 增长的阶。

第一步：读懂循环条件

x = 0 起步，每轮先判断 n >= (x+1)*(x+1)，成立才执行 x = x + 1。循环体没有任何别的动作，所以 x 能涨到多大，循环就执行多少次——只要求出 x 的终值即可。

第二步：解出 x 的终值

循环一直进行到 (x+1)² > n 为止，即退出时 x + 1 > √n，故 x 的终值约为 √n，循环体执行 ⌊√n⌋ 次。

用 n = 100 验证：x = 0 时判断 100 ≥ 1² ✓，一路执行到 x = 9 时判断 100 ≥ 10² = 100 ✓ 仍执行，x 变成 10 后判断 100 ≥ 11² = 121 ✗ 退出。共执行 10 次，恰好 √100 = 10。

第三步：写出复杂度

基本操作 x = x + 1 执行 f(n) = ⌊√n⌋ 次，判断语句多执行 1 次但同阶，所以 T(n) = O(√n) = O(n1/2)。

易错点

  • 把 x 当成翻倍增长：若循环体是 x = x * 2 才是 O(logn)（A 项的误区来源），本题是每次加 1。
  • 只看循环形式猜阶：见到单个 while 就猜 O(n)（C 项）或被条件里的平方吓到选 O(n²)（D 项），都必须先解出循环变量终值。
  • 纠结判断多执行一次：最后一次失败的判断不计入循环体次数，且与循环体同阶，不影响 O 记号。
口诀：循环变量终值是多少，循环就跑多少次；本题终值约 √n。

本题讲解：树的后根遍历对应二叉树的哪种遍历

答案：B（中序遍历）。 树转二叉树用"左孩子、右兄弟"规则，记住两条对应关系：树的先根遍历 = 二叉树的先序遍历；树的后根遍历 = 二叉树的中序遍历。

第一步：写出转换规则

树 T 的每个结点 X：第一个孩子变成 BT 中 X 的左孩子，其余孩子依次链接为第一个孩子的右兄弟链。因此 BT 的根只有左子树（装着 T 根的所有孩子），右子树为空。

第二步：推导"后根 = 中序"

树的后根遍历：先依次后根遍历 T 的各棵子树，最后访问根 R。在 BT 中看这件事：

  • T 的各子树整体挂在 R 的左子树里（第一棵子树作左孩子，兄弟链向右延伸）；
  • BT 中序 = 左子树中序 → 根 → 右子树（空）。对左子树递归下去，访问次序正好是"先各子树、最后根"。

所以 BT 的中序遍历序列与 T 的后根遍历序列逐个相同。

第三步：小树验证

T 为 R(A(D,E), B, C)，转换后按两种方式各遍历一遍：

遍历序列
T 的后根遍历D E A B C R
BT 的中序遍历D E A B C R
T 的先根遍历R A D E B C
BT 的先序遍历R A D E B C

两组序列完全一致，验证了结论。

易错点

  • 看名字像就选"后序遍历"（C 项）：BT 的后序是"左→右→根"，右兄弟链的访问位置与树的后根对不上，是最常见陷阱。
  • 混淆先/后根：与 BT 先序对应的是树的先根遍历（A 项），不是后根。
  • 以为按层遍历（D 项）也保序：层序在两种结构之间没有这种对应关系。
记忆：左孩子右兄弟——先根对应先序，后根对应中序。

本题讲解：哈夫曼树的结点总数公式

答案：C（58）。 哈夫曼树是"没有度为 1 的结点"的二叉树，抓住这条性质列方程即可。

第一步：哈夫曼树的结构性质

建哈夫曼树时每次取出两棵最小的子树合并，新结点必有两个孩子；n 个叶子两两合并，任何结点都不可能只有 1 个孩子。所以树中只有两类结点：度为 0 的叶子（即 n 个符号）和度为 2 的分支结点。

第二步：列方程求解

设叶子数 n0 = n，度为 2 的结点 n2 个。

  1. 二叉树通用性质：n0 = n2 + 1（叶子比二分支结点多一个），故 n2 = n − 1。
  2. 结点总数：n0 + n2 = 115。

代入：n + (n − 1) = 115 → 2n − 1 = 115 → n = 58。

（可直接背公式：哈夫曼树总结点数 = 2n − 1，n 为叶子数。115 + 1 = 116，÷2 = 58。）

第三步：验证

n = 58 时：叶子 58 个、分支结点 57 个，合计 115 ✓。从 58 个叶子开始两两合并，58 个叶子变成 1 棵树需要 57 次合并，每次合并恰好新增 1 个分支结点，吻合。

易错点

  • 以为存在度为 1 的结点：按普通二叉树三种子结点情况去算会卡住，哈夫曼树没有度为 1 的结点。
  • 公式记错方向：总结点数 = 2n − 1，不是 2n 或 2n + 1；选项 D（60）可用 2×60−1 = 119 ≠ 115 排除。
  • 把 115 当叶子数：115 是总结点数，n 才是叶子数，别反着代入。
结论：哈夫曼树结点总数 = 2 × 叶子数 − 1。

在任意一棵非空平衡二叉树（AVL 树）T1 中，删除某结点 v 之后形成平衡二叉树 T2，再将 v 插入 T2 形成平衡二叉树 T3。下列关于 T1 与 T3 的叙述中，正确的是__。

I. 若 v 是 T1 的叶结点，则 T1 与 T3 可能不相同
II. 若 v 不是 T1 的叶结点，则 T1 与 T3 一定不相同
III. 若 v 不是 T1 的叶结点，则 T1 与 T3 一定相同

答案

答案：A

📺 解析视频

本题讲解：AVL 删除结点后再插入，树形会复原吗

答案：A（仅 I 正确）。 关键认识：删除可能触发旋转改变树形；插入按二叉排序树规则落到叶位，不会把旋转过的树转回去，所以删除与插入不互逆。

第一步：拆命题 I（v 是叶结点，T1 与 T3 可能不相同）

"可能不相同"是存在性命题，举出一个不相同的例子即可成立。设 T1 中 v 是叶结点，其父结点 p 的另一棵子树更高：删除 v 后 p 失衡，AVL 旋转调整，树形改变；再把 v 插回，插入位置沿查找路径落到叶层，插入后平衡因子恢复合法，不会再发生旋转把树转回原样，于是 T3 ≠ T1。当然，若删除不引起旋转，T3 也可以与 T1 相同。所以 I 正确。

第二步：拆命题 II 与 III（互为"一定"，但都可能被反例打倒）

  • II（非叶 → 一定不相同）错：反例——v 只有一个孩子，删除时用该孩子接替 v 的位置，全程无旋转；再插入 v，按 BST 性质恰好落回原来的叶位置，树形完全复原，T3 = T1。
  • III（非叶 → 一定相同）错：反例——v 是内部结点，删除时用前驱/后继填补引发旋转；插入 v 后不再转回，T3 ≠ T1。

两个"一定"各被一个反例否定。

第三步：结论

仅 I 正确，选 A。

易错点

  • 忽略"插入不撤销旋转"：插入引发的旋转只服务于插入路径，不会恢复删除时改变的结构，这是本题的机制核心。
  • 把"可能不相同"读成"一定不相同"：存在性命题只需一个例子，措辞审题要细。
  • 以为删除内部结点一定旋转：用前驱/后继填补后可能并不失衡，旋转是"可能"不是"必然"。
记忆：删除会"变形"，插入只"长叶"，二者不互逆。

本题讲解：AOE 网中活动的最早 / 最迟开始时间

答案：C（12 和 14）。

第 0 步：先立模型——AOE 网里"事件"和"活动"是什么关系

AOE 网用边表示活动（要花时间的工序），用点表示事件（"前面这些工序全部完工"这个状态）。由这个定义直接推出两条铁律：

  • 一个事件要等所有指向它的活动都完成才发生 → 正推求 ve 时多条入边取最大（最慢的一条决定事件何时发生）；
  • 一个事件的最迟发生时间不能拖延任何一条从它出发的活动 → 逆推求 vl 时多条出边取最小（按最紧的后继期限倒排）。

活动挂在边上，两头被事件"卡住"：开工被弧尾（起点）事件卡住，交工被弧头（终点）事件卡住——本题两个公式全部由此而来。

第 1 步：为什么"最早开始 = 弧尾事件的 ve"

活动 d 从事件 2 出发。事件 2 一天不发生，d 一天不能开工（前道工序没干完），所以 d 的最早开工时刻就是 ve(2)——不是"ve(2)+d"（那是 d 的完工时刻），也不是弧头的 ve(4)。

第 2 步：为什么"最迟开始 = 弧头事件的 vl − d"

d 必须赶在事件 4 的最迟发生时刻之前干完，晚一步事件 4 被拖后，整个工程跟着拖后。所以最晚开工时刻 = 交工期限 − 干活时长 = vl(4) − d。

第 3 步：算出各事件的 ve 与 vl

本题 AOE 网：1→2 有 a=3，1→3 有 c=8，3→2 有 b=4，2→4 有 d=7，2→5 有 e=6，3→5 有 f=10，4→6 有 g=6，5→6 有 h=9。

第 4 步：定位活动 d（2→4，d=7）

  • 最早开始 = ve(2) = 12；
  • 最迟开始 = vl(4) − 7 = 21 − 7 = 14；
  • 余量 14 − 12 = 2 > 0，说明 d 不是关键活动（关键活动的余量为 0）。

  • 误选 A（3 和 7）：把两个公式都错套在"弧尾事件"上——ve(2) 只看直连边 a=3 算成 3，vl(2) 只看经 4 的路算成 14，再 14−7=7；实际上最早用 ve(2)=12，最迟要用弧头（事件 4）的 vl 减 d。
  • 误选 B（12 和 12）：把 d 当成关键活动、余量当 0；d 有 2 天富余。
  • 最迟开始忘记减时长：21 是 vl(4)（交工期限），必须再减 d=7 才是最晚开工时刻。
记忆锚点：最早看弧尾 ve，最迟 = 弧头 vl − 活动时长；正推取最大（等所有前道），逆推取最小（不拖任何后继）。

7
📺 解析视频

本题讲解：选择排序算法要考虑哪些因素

答案：D（I、II、III、IV 全部需要考虑）。 这是教材结论型考点：没有万能的排序算法，选型是多因素权衡。

第一步：逐项核对

  • I 数据的规模：要考虑。n 很小时直接插入排序、简单选择排序就够用（实现简单、常数小）；n 很大必须用快速排序、堆排序、归并排序等 O(nlog₂n) 算法。
  • II 数据的存储方式：要考虑。快速排序需要两端相向移动、堆排序靠数组下标映射父子关系，都依赖顺序存储；链式存储只适合插入、选择、归并类算法。
  • III 算法的稳定性：要考虑。关键字上挂着成绩、金额等附加信息时，稳定排序能保证同关键字记录的原有先后次序不乱（如按分数排完再按学院排的场景）。
  • IV 数据的初始状态：要考虑。序列基本有序时直接插入排序可达 O(n)、冒泡排序可提前结束；而快速排序在基本有序时枢轴总落在端点，退化到 O(n²)。

第二步：结论

四个因素都是选择排序算法的现实依据，全选，答案 D。

易错点

  • 漏选 II：以为存储方式与算法无关——快排、希尔、堆排都默认顺序存储，链式结构下难以高效实现。
  • 漏选 IV：以为复杂度只由 n 决定——快排最坏情况恰恰由初始排列（基本有序/基本逆序）触发。
  • 漏选 III：以为稳定与否无所谓——对含附属信息的记录，稳定性是硬需求，且它是很多真题判定"哪趟结果"的工具。
记忆：选型四看——规模、存储、稳定性、初始状态。

第 0 步：先把 FF12H 这个数"读对"——为什么是负数、为什么减 10000H

形式地址 FF12H 是 16 位补码。补码不是另一种数制，它是模运算下的记数方式：16 位一共 65536 个状态（0000H~FFFFH），把这个环从中间掰开——最高位为 0（0000H~7FFFH）表示 0 ~ +32767；最高位为 1（8000H~FFFFH）表示 −32768 ~ −1。

所以判断就一句话：最高位为 1 → 负数；真值 = 无符号解释值 − 65536。

FF12H 按无符号读是 65298，是负数，真值 = 65298 − 65536 = −238 = −EEH。

为什么"减 10000H"是合法的？ 这正是补码的定义：位串 FF12H 代表 −238，是因为 −238 ≡ 65298 (mod 65536)。从位串求真值，减一次模即可。

"取反加一"同样对，还能互相印证：FF12H 取反得 00EDH，加 1 得 00EEH = 238 → 真值 −238。两条路结果必然一致——"取反加一"与"减模"在数学上是同一件事，选顺手的用。

第 1 步：为什么要符号扩展——32 位加法器不吃 16 位输入

EA = (BR) + A，BR = F000 0000H 是 32 位的，加法在 32 位加法器里做，−238 必须先写成 32 位补码：FFFF FF12H（高 16 位全补 1，低 16 位照抄）。

规则：补码扩展 = 左边补符号位——负数补 1，正数补 0。

为什么补符号位数值不变？ 直觉：给一个负补码数往左多写一串 1，它"欠的账"没变。数学上：FF12H ≡ −238 (mod 2¹⁶)，FFFF FF12H ≡ −238 (mod 2³²)——同一个负数在更大模下的化身。

反例正是干扰项 A：若补 0（零扩展），FF12H 变成 0000 FF12H = +65298，数值从 −238 变成 +65298，EA 就算成 F000 FF12H 了。

（正数为什么补 0 没问题？正数没有"欠账"，左边加 0 不改变值——所以规则统一写成"补符号位"。）

  F000 0000H
+ FFFF FF12H
= 1 EFFF FF12H   ← 第 33 位的进位

32 位机器只有 32 位地址线，第 33 位的 1 自然丢弃——模 2³² 运算本来就允许丢进位，丢掉 2³² 不影响 32 位内的余数。EA = EFFF FF12H。

内容12（MSB）34FF00（LSB）

机器脉冲源发出脉冲 → 经整形和分频 → 得到时钟脉冲信号。时钟脉冲的宽度（一个节拍）称为时钟周期，其倒数就是主频（f = 1/T）。时钟周期的下限由相邻两级状态单元之间组合逻辑的最大延迟决定——一个节拍内信号必须走完这段逻辑并稳定下来。

第二步：判断"每来一个脉冲执行一条新指令"对不对

易错点

  • 拿流水线"每周期流出一条"偷换概念：流出一条 ≠ 开始执行一条，更 ≠ 每个脉冲对应一条新指令。
  • 以为主频越高时钟周期越大：主频 = 1/时钟周期，二者成反比。
记忆锚点：一个时钟周期走一步，一条指令占多拍；流水线才可能"一拍流出一条"。

本题讲解：流水线数据冒险的判定

答案：C（I2 和 I4）。

第 0 步：先立机制——数据冒险的本质是"值还没落地就被读走"

五段流水线（取指、译码/取数、执行、访存、写回）里多条指令同时在不同段推进。若后一条指令在取数段就要用某个寄存器的值，而写这个寄存器的前一条指令还没走到写回段，读到的就是旧值——这才是数据冒险。所以判据围绕"写"建立：

  • 前写后读（RAW）：有冒险——读的人要的值还在路上；
  • 读与读相遇：永远不冲突——读操作不改变寄存器内容，谁先谁后读到的都是同一个当前值，互相不干扰；
  • 写与写（WAW）：在本题这种按序五段流水线中，写回仍按程序顺序进行，次序不会乱，相邻指令间实际不会形成 WAW 冒险。

于是只需列出每条指令的"读集、写集"，逐对检查"写"有没有撞上别人的"读"。

第 1 步：列出每条指令读、写的寄存器

指令读取寄存器写入寄存器
I1 add s2, s1, s0s1, s0s2
I2 load s3, 0(t2)t2s3
I3 add s2, s2, s3s2, s3s2
I4 store s2, 0(t2)s2, t2（写主存，不写寄存器）

第 2 步：逐对检查

  • I1 与 I3：I1 写 s2，I3 要读 s2 → RAW，有冒险。
  • I2 与 I3：I2 写 s3，I3 读 s3 → RAW，有冒险。
  • I2 与 I4：I2 写 s3、读 t2；I4 读 s2、t2、写主存。两人唯一同用的是 t2，且都是读——读读相容，不构成冒险；s3 只有 I2 在写、无人读。无数据冒险。
  • I3 与 I4：I3 写 s2，I4 要读 s2 → RAW，有冒险。

  • 把 t2 当成 I2 与 I4 的冲突点：两条指令都只"读" t2，多个读者相容——这正是 C 项成立的根据。

  • 以为 store 会写寄存器：store 的目的地是主存，寄存器只出不进。
记忆锚点：冒险只跟"写"过不去——前写后读才算数，读读永远相容；store 只读寄存器、只写主存。

把目标序列拆开看：奇数位置是 a1,a2,a3,…（前半段按原序），偶数位置是 an,a(n-1),…（后半段按逆序）。单链表只能顺着 next 单向走，取完 a1 想立刻拿 an，就要求 an 已经"排好队等在旁边"——这就是三步分解的全部动机：

  1. 找中点：不切出两段，就谈不上"前半段""后半段"；
  2. 逆置后半段：后半段在原表里是 a(n/2+1)…an 的正序，而 L' 要的是逆序，必须先翻转方向；
  3. 交替合并：把翻转后的后半段逐个插进前半段相邻结点的缝隙里，织出 L'。

为什么不用数组存好顺序再重排？题干第一句就是硬约束：空间 O(1)——只许用常数个指针变量，不许申请新数组、新结点。所以一切操作都必须"在原链表上改指针"。

第 1）问：设计思想（每步的"为什么"）

  • 快慢指针为什么能找中点：p 每轮走 1 步、q 每轮走 2 步，q 是 p 的 2 倍速；当 q 到达表尾（再走就越界）时，p 恰好走完一半路程——停在中间。循环条件写成"先走一步、能走再走第二步"，保证 n 为偶数时 p 停在前半段最后一个结点，切出来的前半段含 ⌈n/2⌉ 个结点、后半段含 ⌊n/2⌋ 个——前半段不短于后半段（奇数时恰多 1 个），这正是交替合并能"每个前半段结点后面都插进一个后半段结点"而不落空的原因。
  • 头插法为什么能逆置：p 当临时表头，每轮从旧链摘下头结点 q、插到 p 之后。摘取顺序是后半段正序 a(n/2+1),…,an，后摘的插在前面，链上顺序自然变成 an,…,a(n/2+1)——逆序。全程只改 next 指针、不建新结点，所以空间 O(1)。
  • 合并为什么先暂存 r：两处改指针都会"剪断"原链，必须先用 r=q->next 记住后继，否则断链后后半段就丢了。

第 2）问：算法实现（与参考答案同口径，函数为 reorderList(node *h)）

  1. 找中点：p=q=h; while(q->next!=NULL){ p=p->next; q=q->next; if(q->next!=NULL) q=q->next; }，p 停在前半段末尾。
  2. 逆置后半段：q=p->next; p->next=NULL; while(q!=NULL){ r=q->next; q->next=p->next; p->next=q; q=r; }——先断链 p->next=NULL 把两段分开，再逐个头插。
  3. 交替合并：s=h->next; q=p->next; p->next=NULL; while(q!=NULL){ r=q->next; q->next=s->next; s->next=q; s=q->next; q=r; }——把后半段结点逐个插进前半段的缝隙，插完 s 经 s=q->next 落到下一个前半段结点。

关键注释点：找中点的边界判断、逆置前的断链、改 q->next 前先用 r 暂存后继。

以 n=6 验证：p 停在 a3，后半段逆置为 a6→a5→a4，交替合并得 (a1,a6,a2,a5,a3,a4)，正是 L'。

第 3）问：复杂度

三步各扫一遍链表，指针只前进不回退，每步都与 n 成正比，时间复杂度 O(n)；全程只用 p、q、r、s 四个指针变量，空间复杂度 O(1)。

易错点

  • 开辅助数组存序再重排：空间 O(n)，直接违反 O(1) 约束，是最大扣分点。
  • 找中点边界错：快指针必须"先走一步、能走再走第二步"；若 p 停到后半段开头，切分与合并全乱。
  • 后半段与前半段的长度关系记反：前半段 ≥ 后半段（奇数时前半段多 1 个），合并以前半段为骨架插后半段，才不漏结点。
  • 逆置前忘断链：不先执行 p->next=NULL，合并时会成环。
  • 合并/逆置时指针更新顺序错：必须先 r=q->next 暂存再改 q->next，否则后半段丢失。
框架记忆：目标序列"前半正序 + 后半逆序"⇒ 快慢找中 → 头插逆置 → 逐个穿插；全程只改指针，空间 O(1)。

本题讲解：空间只增不减、进出皆 O(1) 的队列设计

第 0 步：先立模型——把四条需求翻译成存储结构的语言

需求②③④的机制含义是：入队时可能要扩容（空间可增）；出队后旧结点不释放、留着以后再用（空间只增不减）；这两个动作都必须常数时间完成。

  • 为什么不用顺序存储：循环队列在"满"时扩容必须申请新的更大数组并把全部元素搬过去——搬移是 O(n)，破坏需求④；普通顺序队列出队后，前部空间永远用不上（复用要靠取模回绕，而回绕又以容量固定为前提）。两条路都堵死。
  • 为什么是"循环"链表而不是普通单链表：复用的前提是"出队结点还能被找到"。普通单链表里 front 走过的结点成为不可达的垃圾；把表尾的 next 指回表头构成环，所有结点永远留在环上——环被两个指针分成"数据弧"（front 沿环到 rear 的前驱）与"空闲弧"（rear 沿环绕回 front 之前），出队只是把结点从数据弧让给空闲弧，复用自动完成。
  • 为什么初始要建一个空闲结点：让 front、rear 有公共落点。于是队空表现为 front == rear（数据弧长 0），队满表现为 rear->next == front（空闲弧长 0）——空、满两种状态各占一种纯指针关系，所有操作统一为"写入 rear 所指结点再后移"，不需要任何 NULL 特判。

第 1）问：选什么存储结构

选链式存储结构：用单向循环链表保存队列，设队头指针 front 和队尾指针 rear。理由即第 0 步：扩容 = 挂一个新空闲结点（常数次指针修改），复用 = 结点留在环里，两者都是 O(1)。

初始时只建立一个空闲结点，front 和 rear 都指向它。

  • 队空：front == rear（数据弧为空）。
  • 队满：front == rear->next（rear 的下一个绕回 front，空闲弧为空）。

为什么这样能判满：环上只有数据弧和空闲弧两段，空闲弧为空的几何标志正是"rear 的 next 绕回 front"。

第 3）问：第一个元素入队后的状态

初始结点的 rear->next 是它自身，front == rear->next 成立 → 判满为真 → 在 rear 后插入一个新空闲结点；把 a1 写入 rear 所指结点；rear = rear->next。结果：front 指向存 a1 的结点，rear 指向新挂上的空闲结点，数据弧长 1、空闲弧长 1。

第 4）问：入队 / 出队的基本过程

入队 EnQueue(e)：
if (front == rear->next) {   // 队满：空闲弧为空
    在 rear 后插入一个新的空闲结点;
}
rear->data = e;              // 写入 rear 所指结点
rear = rear->next;           // rear 后移

出队 DeQueue(e)：
if (front == rear) {         // 队空：数据弧为空
    return ERROR;
}
e = front->data;
front = front->next;         // 结点不释放，留在环中转为空闲
return OK;

为什么都是 O(1)：入队最多挂一个结点（常数次指针修改），出队只移动一次 front、不搬移任何元素；结点永不 free，空间只增不减。

易错点

  • 选顺序存储：循环队列满时扩容要整队搬移（O(n)），普通顺序队列出队后前部空间复用不了，都与需求冲突。
  • 队满条件写成 front == rear：那是队空；根源是没分清"数据弧"与"空闲弧"——满的标志是空闲弧消失（rear->next 绕回 front）。
  • 入队不先判满就写数据：会把新元素写进已存元素的结点，破坏队列；必须先判满扩容、再写入、再后移。
  • 出队把结点 free 掉：一旦释放就违背"空间只增不减"，下次入队还得重新申请。
一句话锚点：环上分两条弧——数据弧从 front 到 rear 前，空闲弧从 rear 绕回 front 前；空看 front==rear，满看 front==rear->next，进出皆 O(1)。

本题讲解：递归函数 f1 的机器级代码（五问全解）

第 0 步：先立模型——这次递归在机器上是怎么走起来的

  • 函数调用模型：call 指令做两件事——把返回地址（call 自己的下一条指令地址）压栈，再跳到函数入口；函数体用 ebp+8 访问实参 n；ret 从栈顶弹回返回地址。递归就是这套机制的嵌套：每层调用各有一个栈帧。第 16 行 call 的目标 00401000 正是第 1 行 push ebp 所在的 f1 入口，所以它是递归调用。
  • 相对寻址模型：CPU 取指后 PC 已自动指向下一条指令（顺序执行是默认），所以相对转移的基准是下一条指令地址：目标地址 = 下一条指令地址 + 偏移量；偏移量是带符号补码，负数表示往低地址（向前）跳。
  • 溢出模型：int 是 32 位补码 = 模 2³² 的记数方式，范围 [−2³¹, 2³¹−1]；乘法器内部算的是 64 位真积，写回 32 位寄存器只保留低 32 位，等价于真积 mod 2³²。三个模型立好，五问都是顺推。

第（1）问：调用次数与递归调用指令

f1 只在 n > 1 时执行 return n*f1(n-1)。计算 f(10) 的调用链为 f1(10)→f1(9)→…→f1(1)：n 从 10 逐层减 1，每层进入一次 f1，n=1 走 else return 1 不再 call，所以共调用 10 次；每次递归调用自身都由第 16 行 call 指令完成。

第（2）问：条件转移与必跳转指令

分类机制看"跳不跳由什么决定"：条件转移要先由 cmp（第 11 行）建立标志位，跳不跳看标志；而 call 必须转去函数入口、ret 必须按栈顶返回地址跳回、jmp 是无条件转移——三者的转移目标在指令里已经确定，必然跳转。所以：条件转移只有第 12 行 jle（7E 17，n≤1 时跳向 00401035H 的 else 分支）；一定跳转的是第 16 行 call、第 20 行 jmp、第 30 行 ret。

第（3）问：返回地址、偏移量与大小端

第（4）问：为什么返回 1932053504

int 为 32 位补码，上限 2³¹−1 = 2147483647；而 f(13) = 6227020800 > 2³¹−1，真积已超出 int 表示范围。机器保留 64 位乘积的低 32 位（模 2³²）：6227020800 − 4294967296 = 1932053504，恰为题给返回值（本例低 32 位 < 2³¹，按补码读回仍是正数）。修改办法：把 f1 的形参、局部变量和返回值都改为 double（53 位尾数可精确表示 2⁵³ 内的整数，6227020800 < 2⁵³；或改用足够宽的整数类型如 64 位整数）。

第（5）问：OF=1 的条件与自陷指令

64 位真积 = 高 32 位 : 低 32 位。真积能放进 32 位补码 ⟺ 真积在 [−2³¹, 2³¹−1] ⟺ 把低 32 位算术左"伸"32 位后数值不变，即高 32 位恰是低 32 位的符号扩展。因此判据是：高 32 位不是低 32 位的符号扩展 ⇒ 真积溢出 ⇒ OF=1。为什么还要加指令：OF 只是把"溢出"记在标志位上，imul 本身不会自动触发异常；要让 CPU 在溢出发生点转入异常处理，编译器应在 imul 后加一条溢出自陷指令——它检测到 OF=1 即自陷，转入溢出异常处理程序。

  • 偏移量从本指令地址算起：基准是"下一条指令地址"（=返回地址 0040102AH），不是 call 自身地址。
  • 把 FFFFFFD6H 当正数：它是 −2AH 的 32 位补码，负偏移 = 往低地址跳（跳回函数入口），这正是递归调用的方向。

  • 大小端看错对象：判据是多字节数据（偏移量）在内存里的字节存放顺序，不是指令的排列顺序。
  • OF 判据说成"结果为负"：OF 看的是真积是否超出 32 位补码范围，等价说法是"高 32 位 ≠ 低 32 位的符号扩展"。

本题讲解：页划分与指令 Cache 组相联的地址拆分

第 0 步：先立模型——两个问题都是"切地址"，但切的依据不同

  • 分页模型：地址 = 页号（高位）拼接页内偏移（低位）。页大小 4KB = 2¹²B ⇒ 低 12 位是页内偏移（同一页内地址连续，低 12 位任意变化），高 20 位是页号。判断两地址是否同页，只看高 20 位是否相同——页号 = 地址 ÷ 页大小取整，除以 2¹² 就是"砍掉低 12 位"。
  • 组相联映射模型：组间直接映射 + 组内全相联。主存按块大小切块，块号 = 地址 ÷ 块大小；一块允许放在哪个组由"块号 mod 组数"唯一决定（组间是直接映射，没得选）；放进组内哪一行则随意（组内全相联），靠 tag 记住"我到底是哪一块"。所以地址三段从低位往高位切：块内地址（块大小定位数）→ 组号（组数定位数）→ tag（剩余高位）。这个模型直接回答"为什么组号由地址唯一确定"和"为什么命中还要比 tag"。

第 (3) 问：R 需要提供什么服务

内网全部使用 192.168.1.0/24 的私有地址，这类地址在 Internet 上不可路由。要让 H1～H4 访问 Internet，R 必须提供 NAT（网络地址转换） 服务：出流量把私有地址转换为公网地址（101.1.2.10 对应接口），回程流量再反向转换回来。

第 (4) 问：目的地址 192.168.1.127 谁接收

H3 的地址 192.168.1.66/26 属于子网 192.168.1.64/26，该子网主机位全 1 的直接广播地址正是 192.168.1.127。发往它的数据报只在 LAN2 内以广播帧扩散：

  1. 路由器（设备 1）隔离广播域，不向 LAN1 转发 → H1、H2 收不到；
  2. H3 是发送方，不接收自己发出的数据报；
  3. 同一子网内的另一台主机 H4 会接收该数据报。

易错点

  • IF1 配成 .253：那是 R 的地址；/30 里只剩 .254 可用。
  • 给交换机接口配 IP：无 VLAN 的以太网交换机是链路层设备，接口无 IP。
  • 第 (4) 问答成 H3、H4 都收：发送方不接收自己的广播帧；若再答上 H1/H2，则是忽略了路由器隔离广播域。
设备 1 = 路由器，设备 2/3 = 以太网交换机；IF1 192.168.1.254、IF2 192.168.1.1、IF3 192.168.1.65；R 提供 NAT；只有 H4 接收。
