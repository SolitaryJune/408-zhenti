本题讲解：入栈序列与出栈序列的可能性

第一步：判断“可能性”的唯一工具

给定入栈序列 in 和出栈序列 out，判断 out 是否可能：按 in 的顺序进栈、按 out 的顺序出栈做模拟。这是确定性算法——模拟成功即可能、失败即不可能，不存在“不能判断”的情况。所以 A、B 两个选项的“不能判断”直接排除。

第二步：in 与 out 能否相同（查 C）

可以。设 S 中元素 a、b、c：a 进栈后立即出栈，b 进栈后立即出栈，c 同样——out = a b c = in。「进一个就出一个」让出栈序列与入栈序列完全一样，C 的“一定不同”错。

第三步：in 与 out 能否互为倒序（查 D）

可以。a、b、c 依次全部进栈，再依次出栈：栈顶 c 先出，然后 b、a——out = c b a，恰是 in 的倒序。D 的“可能互为倒序”对。

易错点

  • 把“不确定”当“不能判断”：可能性问题用栈模拟必有唯一答案，A、B 的说法对任何序列都不成立。
  • 以为出栈序列一定不同于入栈序列：忽略了“进一个出一个”这种交错操作，误选 C。
  • 忽略栈的容量无限：本题栈初始为空且无容量限制，“全进再全出”总是可行的。
in 与 out 可能相同、也可能互为倒序；可能性永远可用模拟判定，选 D。

本题讲解：中序相邻 ⇒ 谁是 p 的中序后继

第一步：把条件翻译成“后继”规则

p、q 在中序序列中相邻且 p 在前，等价于 q 恰好是 p 的中序后继。中序后继只有两种来源：① p 有右子树——后继是右子树里最左下的结点；② p 无右子树——沿双亲链向上，找到第一个“p 位于其左子树中”的祖先。

第二步：逐条验证

关系能否相邻理由或反例
I. q 是 p 的双亲可能p 是 q 的左孩子且无右子树：中序为 …, p, q, …
II. q 是 p 的右孩子可能q 无左孩子时，p 的后继正是 q
III. q 是 p 的右兄弟不可能中序必为 …, p 的子树, 双亲, q, …，p 与 q 之间至少隔着双亲
IV. q 是双亲的双亲可能q 的左孩子 r，r 的右孩子 p（叶）：中序为 r, p, q，p 的后继恰为 q

IV 能成立的关键：从 p 向上走到 q 的途中，每个中间结点（r）都“向右拐”（p 是 r 的右孩子），它们都先于 p 输出，插不进 p、q 之间。

易错点

  • 凭直觉认为“隔代必不相邻”：IV 的反例说明走“右拐链”时祖孙可以相邻，别误选 IV。
  • 以为双亲总夹在中间：只在 III（右兄弟）中成立；I 中双亲就是 q，IV 中双亲先于 p 输出。
结论：I、II、IV 都可能，仅 III 不可能，选 B。

本题讲解：三叉树的最小高度

第一步：明确口径与思路

叶结点高度为 1，即高度按“层数”计：最底层叶为 1，向上每层加 1，根的高度等于总层数。

第二步：为什么“最矮”等价于“逐层放满”

核心机制是一个容量上界：每个结点至多有 3 个孩子，所以第 t 层至多 3t−1 个结点（第 1 层 1 个、第 2 层 3 个、第 3 层 9 个……），h 层三叉树最多容纳 1 + 3 + 9 + … + 3h−1 = (3h − 1) / 2 个结点。

由此推出两件事：

  • 下界：若总结点数超过满 (h−1) 层的容量，前 h−1 层就装不下，必有结点被挤到第 h 层——高度至少为 h。换句话说，结点一定时，树越高容量越富余；想最矮，就必须让每一层都不浪费名额（任何有空位的层都在白白消耗高度）。
  • 可达：满 (h−1) 层 + 第 h 层挂若干叶子总能构造出来，所以下界不是空谈。

于是问题变成：244 落在哪一层容量之内。

h（层数）123456
最多结点数141340121364

121 < 244 ≤ 364 ⇒ 满 5 层只装 121 个，244 装不下 ⇒ 高度至少 6；满 6 层装 364 ≥ 244 ⇒ 6 层装得下。最小高度为 6。

第三步：验证可构造性

前 5 层放满 121 个结点，第 6 层再放 123 个叶即可（第 5 层有 81 个结点，至多可挂 81 × 3 = 243 个孩子，放 123 个叶没有问题）。所以高度 6 是可达的。

易错点

  • 误用二叉树公式：拿 2h − 1 ≥ 244 会算出 h ≥ 8（选项 A 的陷阱），题目是三叉树。
  • 搞错高度口径：若按“根高度为 1、叶高度为层数”本题同口径；但若多减一层会误得 5（选项 D）。
  • 只算“满树”才合法：只需容量足够即可构造，不要求每层都放满。
高度至少 6，选 C。记忆锚点：m 叉树 h 层最多 (mh − 1)/(m − 1) 个结点。

本题讲解：哈夫曼树 T1 与定长编码树 T2

第一步：两棵树长什么样——机制先立起来

T1（哈夫曼编码树）的构造机制：每轮挑两棵权值（频次）最小的子树合并。这带来三个必然结果——

  • 为什么频次小的离根远：小权子树总是先被合并，先合并的就往下垫一层，高频字符天然靠近根、码长短；
  • 为什么没有度为 1 的结点：每步都是“两棵合成一棵”，从不出现独生子，树中只有度 2（内部）与度 0（叶）的结点；
  • 为什么结点数恰为 2n − 1：n 个叶合并成一棵树，每合并一次新增 1 个内部结点，共合并 n − 1 次 → n + (n − 1) = 2n − 1。

T2（定长编码树）：每个字符的码长 = 它作为叶的深度。定长编码码长相同 ⇒ 字符叶必然处于同一层；空位可留可补，所以 T2 形状不唯一、结点数不定。

第二步：逐项判断

  • A（结点数相同）：T1 恒为 2n − 1；T2 形状不唯一（n=3 时码长 2，树上可有 6～7 个结点），不一定相等，错。
  • B（T1 一定更高）：T1 是含 n 个叶的二叉树，高度 ≥ ⌈log2 n⌉；T2 高度可取到 ⌈log2 n⌉。n=3、频次 {1, 1, 10} 时 T1 高度为 2，与 T2 相等，“一定大于”不成立，错。
  • C（频次不同必不同层）：反例频次 {2, 2, 3, 3}：合并 2+2=4、3+3=6，四个字符都在第 2 层，频次却有 2 有 3，错。
  • D（T2 中频次不同同层）：定长编码码长与频次无关，所有字符必在同一层，对。

易错点

  • 以为哈夫曼树一定更高：最高频字符码长可以只有 1 位，n=3 时两树同高，B 就错在这里。
  • 只记得 2n − 1：它只属于哈夫曼树（无度为 1 结点），不能套到定长编码树上判断 A。
  • 低估“同层”的可能性：哈夫曼合并中两组不同频次可以同步合并（如 2+2 与 3+3），同层不等于同频次。
定长编码“码长相同 ⇒ 同层”，选 D。

本题讲解：AOE 网中活动的时间余量

第零步：余量的机制——它是"活动能拖延多久而不耽误工期"

事件的最早时刻 ve(j)：事件的含义是"入边的活动全部完成"，所以谁最慢就等谁——正推时取最大。事件的最迟时刻 vl(i)：在不推迟总工期的前提下允许的最晚发生时刻，后继活动各有各的截止线，谁最急就迁就谁——逆推时取最小。

任一活动（起点 i、终点 j）的余量 = vl(j) − ve(i) − 工期，含义是：活动最早可以在 ve(i) 开工，最晚必须在 vl(j) − 工期 开工，两者的差就是它可以拖延的最大时长。余量为 0 的活动就是关键活动，一秒都拖不得；题目问"时间余量最大"，就是找最能拖的那个活动。

第一步：算事件时间

活动与工期：a(1→2)=2、b(1→3)=5、c(2→3)=1、d(2→4)=3、e(3→4)=3、f(3→5)=4、g(3→6)=1、h(4→5)=1、i(4→6)=4、j(5→6)=1。

最早 ve（正推取最大）：ve(1)=0；ve(2)=2；ve(3)=max(0+5, 2+1)=5；ve(4)=max(2+3, 5+3)=8；ve(5)=max(5+4, 8+1)=9；ve(6)=max(8+4, 5+1, 9+1)=12（工期 12）。

最迟 vl（逆推取最小）：vl(6)=12；vl(5)=11；vl(4)=min(12−4, 11−1)=8；vl(3)=min(8−3, 11−4, 12−1)=5；vl(2)=min(5−1, 8−3)=4；vl(1)=min(4−2, 5−5)=0。

第二步：算活动余量

按"终点最迟 − 起点最早 − 工期"逐个代入：

活动abcdefghij
余量2023026202

最大余量 = g（6），选 B。

  • 余量公式漏减工期：必须是“终点最迟 − 起点最早 − 工期”三项，只算前两项会全错。
  • 把关键活动当答案：b、e、i 余量 0，在关键路径上，余量最小而非最大。
  • ve(4) 取错：两条入边 2+3 与 5+3 要取最大值 8，只算一条会连带 e、i 全错。
记忆锚点：余量 = 最迟完成 − 最早开始 − 工期；关键活动余量为 0。

    pmin = (int *)malloc(sizeof(int) * (bt.ElemNum));
    pmax = (int *)malloc(sizeof(int) * (bt.ElemNum));

        }

本题讲解：判定顺序存储的二叉树是否为二叉搜索树

第 0 步：先立机制——BST 的性质是“子树级”的，不是“父子级”的

二叉搜索树的定义最容易被读窄。它要求的不是“每个结点比左孩子大、比右孩子小”，而是比左子树里所有结点都大、比右子树里所有结点都小。树深不超过 1 时两句话等价；树一深，父子局部的检查就会漏判。题目图里的 T2 自己就藏着这样的例子：结点 35 与它的双亲 30 直接比较完全合法（右孩子 35 > 30），但它挂在 50 的右子树里——50 的右子树必须全部大于 50，而 35 < 50。这层“祖孙关系”用“双亲 vs 直接孩子”永远看不见，违规只能顺着子树最值浮上来。

把定义压成可检查的形式：对每个结点，左子树的最大值 < 结点值 < 右子树的最小值——这与 BST 定义完全等价（最大值/最小值把整棵子树压缩成一个数，任何深层违规都会体现在最值上）。算法的全部工作，就是自底向上算出每个结点的子树最值，顺路完成检查。

第 1）问：基本设计思想

  1. 建立与顺序存储数组等长的辅助数组 pmin、pmax：pmin[k]、pmax[k] 记录以 k 号结点为根的子树中的最小值、最大值。初始化 pmin[k] = pmax[k] = SqBiTNode[k]——对叶结点（以及“暂时只看见自己”的结点）来说，子树最值就是它自己。
  2. 从最后一个下标 k = ElemNum−1 向 1 倒序扫描。为什么倒序一定可行：顺序存储里下标 k 的双亲是 (k−1)/2，恒小于 k，也就是说所有孩子都排在双亲后面——倒序处理到任何结点时，它的左右子树的 pmin/pmax 已经算好。
  3. 值为 −1 的空位跳过。为什么可以放心跳过：题目规定结点值均为正整数，−1 只是“此处无结点”的占位符，不是值；拿去比较会凭空制造违规，混进最值更会污染整条传播链（空位自己的 pmin/pmax 虽被初始化为 −1，但因被跳过永远不会上传）。
  4. 对每个非空结点 k，求双亲 m = (k−1)/2。k 为奇数是左孩子：检查 SqBiTNode[m] > pmax[k]（左子树最大值必须小于双亲——为什么看最大值：左子树里唯一可能顶破双亲上界的就是最大值），成立则把 pmin[k] 上传给 pmin[m]；k 为偶数是右孩子：检查 SqBiTNode[m] < pmin[k]（右子树最小值必须大于双亲），成立则把 pmax[k] 上传给 pmax[m]。任一检查失败立即返回 false。
  5. 为什么检查通过后只朝一个方向传播？以左孩子为例：既然双亲值大于左子树的最大值，合并后的子树最大值就是双亲自己，pmax[m] 不用动，只需把最小值接力上去；右孩子对称。根结点无双亲、无检查对象，所以主循环到 k = 1 为止。
  6. 扫描完整结束（一路传到根都通过）返回 true。

第 2）问：算法实现（与参考答案同口径）

  • 初始化：for (k = 0; k < bt.ElemNum; k++) pmin[k] = pmax[k] = bt.SqBiTNode[k];
  • 主循环：for (k = bt.ElemNum - 1; k > 0; k--)，空位用 if (bt.SqBiTNode[k] != -1) 跳过，m = (k - 1) / 2; 求双亲。
  • 左孩子分支：if (k % 2 == 1 && bt.SqBiTNode[m] > pmax[k]) pmin[m] = pmin[k]; —— 奇数下标 2m+1 是左孩子。
  • 右孩子分支：else if (k % 2 == 0 && bt.SqBiTNode[m] < pmin[k]) pmax[m] = pmax[k]; —— 偶数下标 2m+2 是右孩子。
  • 失败出口：else return false;；全部通过后 return true;。

  • 时间：每个元素先与堆顶比 1 次；真正入堆的元素还要在 10 个元素的堆里下沉，至多 3 层（10 个结点的完全二叉树高为 3）。平均有多少元素入堆？第 i 个数入堆当且仅当它是前 i 个数中最小的 10 个之一，概率为 10/i，对 i 求和约为 10·ln(n/10)——n = 10 万时约一百个，额外比较只有几百次的常数。故平均总比较次数约为 n 加小常数，平均时间复杂度 O(n)。
  • 为什么说“比较次数尽可能少”：任何正确算法都至少需要 n−10 次比较——每个落选的数至少得“输”一次才有资格被淘汰；堆法贴着这条下界，而全排序要从 n·log2 n ≈ 170 万次起步。
  • 空间：堆只有固定的 10 个元素，与 n 无关，额外空间复杂度 O(1)。

易错点

  • 用小根堆：小根堆顶是“当前最小”，拿它守门既判不了“够不够小”，也无法快速找到该淘汰的最大者；必须大根堆，让最大的候选守门。
  • 先建 n 个元素的堆：堆规模随 n 增大，空间 O(n)、比较次数也远超 n，违背题目对效率的要求。
  • 忽略“平均”口径：最坏情形（数据递减到来）每个数都入堆、都要下沉，但题目问平均，每元素常数次比较即可。
  • 不初始化堆顶为最大值：就得先取前 10 个数建堆再扫描，思路也正确但表述必须完整；参考答案用最大值初始化更简洁，且不变量从第 0 步就成立。
大根堆守门：比堆顶小才进堆，平均 O(n) 时间、O(1) 空间，比较次数贴着 n−10 的下界。

本题讲解：单总线数据通路上的标志位、暂存器、寄存器堆与取指流程

第 1）问：SF 与 OF 的逻辑表达式

先立机制。FR 里的标志是对 ALU 结果 F 的两种读法：SF 是直读——符号标志的定义就是结果的最高位，而 F 本就是 16 位补码结果，最高位即符号位，所以 SF = F15。OF 是判读——回答“这个补码结果还可信吗”。

补码运算是模 2¹⁶ 的记数，16 位补码表示 −32768 ~ +32767。两个异号数相加永远不溢出：一正一负，和的绝对值被夹在两者之间，出不了范围；只有同号相加才可能越界，而一旦越界，模运算把结果“绕”回来，符号位必然与操作数相反。据此（记 ¬X 为取反、· 为逻辑与、+ 为逻辑或）：

  • A 加 B：操作数同号（A15 = B15）而结果符号相反（F15 = ¬A15）：

OF = ¬A15·¬B15·F15 + A15·B15·¬F15

  • A 减 B：把 A−B 看成 A 加上 (−B)。求补翻转了 B 的符号位，“实际相加的两数同号”就变成 A15 与 B15 相异；一旦溢出，结果符号与 A 相反（F15 = ¬A15）：

OF = ¬A15·B15·F15 + A15·¬B15·¬F15

（用进位判溢出 C15⊕C16 同样正确，但本题限定表达式只含 A15、B15、F15，符号判读法恰好只用这三个量。）

第 2）问：为什么要设置暂存器 Y 和 Z

机制：这是单总线通路——内部总线一个时钟周期只能稳定传送一个数据。而一次 ALU 运算牵涉三个数据：两个输入、一个输出，不可能同时都在总线上：

  • Y 锁存第一个输入：先 Yin 把总线上送来的第一个操作数存入 Y（Y 直连 ALU 的 A 端），下一周期总线腾出来，第二个操作数才能送上 B 端。
  • Z 锁存输出：ALU 是组合逻辑，算出 F 的那个周期总线往往还忙着（正给 B 端送数），且 F 随输入变化、不能长存，必须先打进 Z；总线空闲后再 Zout 送往目的地。

没有 Y，第二个输入无处落脚；没有 Z，结果没有中转站——总线上必然“撞车”。

第 3）问：寄存器个数、rs/rd 来源与 rd 的连接

GPRs 内部为什么“读用多路选择器、写用地址译码器”——因为两个方向的数据流形状不同：读，是 16 个寄存器的输出要汇成一路送内部总线，多路选择器干的就是“多选一”，由 rs 选中哪个寄存器上总线；写，要唯一激活目标寄存器的输入门——译码器把 4 位 rd 翻成 16 条“一字一线”的选通线，只有编号等于 rd 的那一条有效，恰好只有一个寄存器开门接收 GPRin 的数据。所以 rd 应连接地址译码器。

第 4）问：取指阶段的控制信号序列与时钟周期数

先想数据怎么流，再排信号：取指（不考虑 PC 增量）要把 PC 所指的指令从主存搬进 IR，路径为 PC →（内部总线）→ MAR →（系统总线/主存）→ MDR →（内部总线）→ IR。三段中两段走内部总线、一段是主存读出；单总线一次只传一个数据，三段天然串行，没有可合并的余地——这就是“至少”的含义。

本题讲解：磁盘扇区地址、平均访问时间与周期挪用 DMA

第 1）问：扇区地址的 3 个字段与最少位数

先立机制：一个扇区在盘上的位置由三个依次收窄的问题定位——哪个记录面（磁头号/盘面号）、该面的哪一圈磁道（柱面号/磁道号）、这条磁道上的第几个扇区（扇区号）。三段地址各管一维，合起来唯一确定一个扇区。

为什么用“柱面号”而不是“磁道号”：所有盘面上半径相同的磁道构成一个圆柱面，所有磁头都装在同一小车上、同时指向同一柱面——寻道一次，8 个记录面的同号磁道全部就位。用柱面号统一描述“第几圈”，正是这个机械事实的反映。

位数由“至少能区分多少个”决定，一律向上取幂：

字段要区分的个数计算最少位数
柱面号（磁道号）每盘面 20000 道2¹⁴ = 16384 不够，2¹⁵ = 32768 够15 位
磁头号（盘面号）4 个双面盘片 = 8 个盘面2³ = 8 恰好3 位
扇区号每磁道 500 扇区2⁸ = 256 不够，2⁹ = 512 够9 位

第 2）问：一个扇区的平均访问时间

机制：一次访问 = 寻道 + 旋转延迟 + 传输，三项“平均”各有来历。寻道时间题目直接给定平均 5 ms；旋转延迟取决于“磁头到位那一刻，目标扇区在它前方多远”——这个距离在 0 到一转之间均匀分布，平均半转；传输时间是扇区数据扫过磁头的时间——每道 500 个扇区均分一圈，一个扇区就是一转的 1/500。

转速 7200 RPM → 一转 = 60×10³ ÷ 7200 ≈ 8.333 ms，于是：

平均访问时间 = 5 + 8.333/2 + 8.333/500 = 5 + 4.167 + 0.017 ≈ 9.18 ms

第 3）问：DMA 总线请求次数与优先权

周期挪用（周期窃取）DMA 的机制：磁盘把数据送进控制器缓冲区，缓冲区装满一批，DMA 才向 CPU 申请一个存储周期把这一批搬进主存——搬运以缓冲区为单位，不是逐字节。缓冲区 64 位 = 8 B，每扇区 512 B → 512 ÷ 8 = 64 次总线请求。

CPU 与 DMA 同时请求主存时，DMA 可以优先获得总线使用权。为什么让 DMA 先走：磁盘按转速机械地连续吐数据，来多少就得接多少，不能暂停重放；若 DMA 让 CPU 插队一个存储周期，缓冲区里刚到的 8 B 还没搬走，下一批就来了，数据会被覆盖丢失。而 CPU 被推迟一个存储周期对程序执行几乎没有影响。两害相权，周期挪用规则规定冲突时 DMA 优先。

易错点

  • 位数算成“恰好够的幂”：500 个扇区要 9 位（2⁸ 不够），20000 道要 15 位（2¹⁴ 不够），一律向上取幂。
  • 把一整转当旋转延迟：平均旋转延迟是半转——目标扇区初始位置均匀分布所致。
  • 漏加传输时间：9.18 = 5 + 4.167 + 0.017，三项缺一不可。
  • 以为 DMA 一定让 CPU：周期挪用的原则恰恰是 DMA 优先，防的是磁盘数据流不可暂停导致的丢失。
一句话结论：地址 15 + 3 + 9 位；平均访问 ≈ 5 + 4.167 + 0.017 ≈ 9.18 ms；每扇区 64 次总线请求，同时请求时 DMA 优先。

本题讲解：设备选型、冲突域最远距离、DHCP 广播与 802.11 帧地址

第 1 问：设备 1、设备 2 选谁

先立机制——三类设备对帧的转发方式不同，冲突域/广播域的差异全源于此。集线器（Hub）是物理层转发器：把一个端口收到的信号放大后向所有其他端口重发，所有端口共享同一介质，任意两个端口同时发送必然碰撞——整个 Hub 是一个冲突域，且广播、单播一律泛洪，也不隔离广播域。交换机是链路层设备：按目的 MAC 查表把帧送往单一端口，各端口独立跑 CSMA/CD——每个端口一个冲突域，但广播帧仍向所有端口泛洪，不隔离广播域。路由器是网络层设备：广播帧过不了路由器——隔离广播域。

拿机制对线索：H1 与 H2 属于同一个广播域、不属于同一个冲突域 → 设备 1 必须“隔冲突、不隔广播” → 100BaseT 以太网交换机（Hub 会让 H1/H2 同处一个冲突域，路由器会把二者分进不同广播域，均与线索矛盾）。H2 和 H3 属于同一个冲突域 → 设备 2 不隔离冲突域 → 100BaseT 集线器。

第 2 问：H2 与 H3 的最远距离

机制：H2、H3 经 Hub 同处一个冲突域，半双工 CSMA/CD。为什么最小帧长能定距离上限——发送方必须在发完帧之前得知碰撞：碰撞信号从发送端传到冲突点再返回，最远要 2τ；若帧发完了碰撞消息还没回来，发送方会误判成功。所以“最小帧长的发送时间 ≥ 2τ”，反过来看，争用期（2τ 上限）= 最小帧长 ÷ 速率。

  1. 100BaseT 速率 100 Mb/s：争用期 = 64 × 8 bit ÷ 100 Mb/s = 5.12 μs。
  2. 单程上限 τ = 5.12 ÷ 2 = 2.56 μs。这 2.56 μs 里既有线路传播、也含信号过设备 2 的额外 1.51 μs，扣掉后线路传播上限 = 2.56 − 1.51 = 1.05 μs（τ 是单程，H2→H3 单程只穿过设备 2 一次，所以只减一次 1.51）。
  3. 最远距离 d = 1.05 μs × 2×10⁸ m/s = 210 m。

第 3 问：DHCP 报文 M 与广播帧去向

机制：DHCP 的四步交互是 Discover → Offer → Request → ACK。H4 刚接入，还没有 IP 地址，也不知道 DHCP 服务器的 IP 和 MAC——唯一能做的就是“全网喊话”：首先发送 DHCP Discover 报文（M），IP 层目的地址 255.255.255.255，链路层封装为目的 MAC 全 1 的广播帧。

  • H4、AP、交换机 S、路由器 E0 接口、DHCP 服务器同在 192.168.0.0/25 这一个广播域里。S 收到广播帧，按交换机规则从除入端口外的所有端口泛洪 → 路由器 E0 接口能收到封装 M 的以太网帧（DHCP 服务器同样收到）。
  • S 向 DHCP 服务器转发的仍是这个广播帧，目的 MAC = FF-FF-FF-FF-FF-FF。路由器会收下该帧，但不会把这个 IP 受限广播再转发到别的网络。

第 4 问：802.11 帧的地址 1、2、3

机制：802.11 帧最多带 4 个地址字段，具体含义随 To DS / From DS 变化，但骨架不变——地址 1 = 本跳接收者（ACK 发给谁），地址 2 = 本跳发送者（谁负责重传），地址 3 = 端到端的源或目的（无线段只是路径的最后一跳，必须把真正的起点/终点带上，对端才知道来龙去脉）；地址 4 只在无线分布式系统（mesh）中用。

H5 收到的帧由 AP 发往无线站点（“来自 AP”，From DS = 1）：

地址字段角色本题取值
地址 1本跳接收者 = 目的站H5 的 MAC 00-11-11-11-11-E1
地址 2本跳发送者 = AP00-11-11-11-11-C1
地址 3端到端源 = H4H4 的 MAC 00-11-11-11-11-D1

为什么地址 2 不是 H4：最后一跳是 AP 发出的，ACK 与重传都对着 AP；端到端源 H4 放在地址 3。

易错点

  • 第 1 问把设备 1 当成集线器：Hub 连冲突域都不隔离，与“不属于同一个冲突域”直接矛盾。
  • 第 2 问忘扣 1.51 μs：设备延迟也在单程 2.56 μs 的预算里，必须扣除；不扣会得 512 m。
  • 第 2 问忘除 2：5.12 μs 是往返（2τ），单程 τ = 2.56 μs；也不能把 1.51 扣两次（单程只过一次设备 2）。
  • 第 3 问以为 E0 收不到：广播帧被交换机泛洪到所有端口，E0 在链路上必然收到——只是路由器不把该 IP 广播转发出去。
  • 第 4 问地址 2、3 弄反：“来自 AP”的帧地址 2 一定是 AP 自己（00-…-C1），地址 3 才是端到端源 H4（00-…-D1）。
一句话总括：交换机隔冲突不隔广播、Hub 全不隔；5.12 μs 争用期扣设备延迟剩 1.05 μs 得 210 m；DHCP 先发 Discover 全 1 广播；来自 AP 的 802.11 帧 = 地址 1 目的、地址 2 AP、地址 3 源。
