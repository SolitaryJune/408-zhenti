本题讲解：中序序列 …,p,v,q,… 的隐含条件

答案：A（p 没有右孩子，q 没有左孩子）。

第一步：认清 p 和 q 的身份

中序序列形如 …, p, v, q, …，说明 p 是 v 的中序前驱、q 是 v 的中序后继。题干又给了关键条件：v 有两个孩子——这个条件决定了前驱、后继不会沿祖先链去找，而是落在 v 自己的子树里。

第二步：为什么前驱/后继只能在子树里

中序遍历的次序是左子树全部 → 根 → 右子树全部。所以 v 的左子树结点全部排在 v 之前、右子树结点全部排在 v 之后；祖先结点要么早已访问完，要么要等 v 的整棵右子树访问完才轮到——都"够不着"紧贴 v 的位置。于是：

  • 中序前驱 = 左子树中最右边的结点（从左子树根一路向右走到底，它是左子树里最后被访问的）；
  • 中序后继 = 右子树中最左边的结点（从右子树根一路向左走到底，它是右子树里最先被访问的）。

第三步：推出孩子的有无

  • p 是「一路向右」的终点：若 p 还有右孩子，就能继续向右，p 就不是最右结点、当不了前驱 —— 矛盾。所以 p 必定没有右孩子（有无左孩子都可能）。
  • q 是「一路向左」的终点：若 q 还有左孩子，就能继续向左，q 就不是最左结点、当不了后继 —— 矛盾。所以 q 必定没有左孩子（有无右孩子都可能）。

小树验证：v 左子树为 a→右孩子 b 时中序为 a, b, v，前驱 b 无右孩子；右子树为 c→左孩子 d 时中序为 v, d, c，后继 d 无左孩子。

易错点

  • 选 B（q 有左孩子）：把「后继在右子树里」错记成「右子树任意结点」，忽视了要走到最左。
  • 选 C/D（p 有右孩子）：只看到 p 在 v 之前，没想到「有右孩子就能再往右」会推翻前驱身份。
  • 忽略前提：本题结论依赖「v 有两个孩子」；若 v 只有一个孩子，前驱/后继可能要沿祖先链找，结论不成立。
记忆锚点：中序 = 左→根→右；有双孩子的结点，其前驱是左子树最右结点（无右孩子），后继是右子树最左结点（无左孩子）。

第二步：求教材版 next

第三步：修正为 nextval——为什么可以跳传

    degree = (int *)malloc(G.numVertices * sizeof(int));
    for (j = 0; j < G.numVertices; j++) {
        degree[j] = 0;
        for (i = 0; i < G.numVertices; i++) {
            degree[j] += G.Edge[i][j];
        }

    int zero_count, zero_vertex;
    while (count < G.numVertices) {
        zero_count = 0;
        zero_vertex = -1;

                zero_count++;
                zero_vertex = j;

        for (j = 0; j < G.numVertices; j++) {

                degree[j]--;
            }
        }
    }
    free(degree);
    return 1;

第 0 步：机制先行——拓扑序列是怎么一步步生成的，"唯一"卡在哪一环

拓扑序列的生成机制：每一轮从当前图中挑一个入度为 0 的顶点输出，然后删掉它——它的出边随之消失，其后继顶点入度减 1，如此重复直到删空。为什么必须挑入度 0 的？拓扑序要求每条边 u→v 中 u 排在 v 前面，也就是输出任何顶点之前，它的所有前驱都已输出——"入度为 0"正是"所有前驱已输出"在图上的表现。

唯一性恰恰卡在"挑"这个动作上。某一轮若同时有两个入度为 0 的顶点，算法可以任选其一：先排 a、再排 b 能得到一个完整序列，先排 b、再排 a 也能得到另一个——两个候选各自都能扩展成完整拓扑序列，所以序列不唯一。反之，若每一轮都只有一个候选，每一步都被"逼定"，序列自然唯一。

还剩一种情况：某一轮一个入度为 0 的顶点都没有（且顶点没删完）。为什么这就是有环？剩下的每个顶点入度都 ≥ 1，即每个顶点都在等某个同样还没被删掉的前驱先输出——大家互相等，谁也当不上下一个输出者，说明剩余子图里存在回路。有环则拓扑序列根本不存在，更谈不上唯一。

于是判定条件收敛为一句话：每一轮有且仅有一个入度为 0 的顶点，且能这样删满 n 轮——0 个（有环）与多于 1 个（并列）都返回 0。

第（1）问：算法基本设计思想（4 分）

按上面的机制组织成四步作答：

  1. 由邻接矩阵统计全部顶点的入度，存入 degree 数组；
  2. 每轮扫描入度表，统计入度为 0 的顶点个数：若为 0 个，有环，返回 0；若多于 1 个，序列不唯一，返回 0；若恰好 1 个，删除该顶点（其后继入度减 1），继续下一轮；
  3. 若每轮都恰好 1 个、且最终删除了全部 n 个顶点，返回 1。

第（2）问：C 语言描述（9 分）

int uniquely(MGraph G) {
    int *degree, i, j, count = 0;
    degree = (int *)malloc(G.numVertices * sizeof(int));
    for (j = 0; j < G.numVertices; j++) {
        degree[j] = 0;
        for (i = 0; i < G.numVertices; i++) {
            degree[j] += G.Edge[i][j];      // 逐列求和 = 入度
        }
    } // 建立入度表 degree[]
    int zero_count, zero_vertex;
    while (count < G.numVertices) {
        zero_count = 0; zero_vertex = -1;
        for (j = 0; j < G.numVertices; j++) {
            if (degree[j] == 0) {
                zero_count++; zero_vertex = j;
                if (zero_count > 1) break;  // 超过一个入度为 0 的点，退出
            }
        }
        if (zero_count != 1) {              // 0个=有环，多个=不唯一
            free(degree);
            return 0;
        }
        count++;
        degree[zero_vertex] = -1;           // 标记删除该顶点
        for (j = 0; j < G.numVertices; j++) {
            if (G.Edge[zero_vertex][j] > 0) {
                degree[j]--;                // 其后继入度减 1
            }
        }
    }
    free(degree);
    return 1;
}

四个关键处值得先想明白再写：为什么逐列求和就是入度——Edge[i][j] 中 i 是行（起点）、j 是列（终点），所有汇到第 j 列的边都以 j 为终点，列和即 j 的入度；为什么删除用 degree[zero_vertex] = -1——后续扫描条件是 degree[j] == 0，改成 −1 后它永不再命中，等价于把顶点从图里拿掉，还不用真去改矩阵；为什么 zero_count > 1 就 break——本题只需要知道"不止一个"就能判 0，数到 2 即可收工；为什么删除顶点后还要给后继减 1——删点的语义就是"它排在当前位了"，它对后继的约束（一条入边）随之解除。

复杂度：每轮扫描 O(n)、最多 n 轮，共 O(n²)，辅助空间 O(n)。

易错点

  • 只判有环、不判并列：只写"入度为 0 的顶点不存在返回 0"，漏掉"多于 1 个也返回 0"——题目问的是唯一，这是本题最常见丢分点。
  • 逐行求和当入度：邻接矩阵按行是出度、按列才是入度，方向搞反全盘皆错。
  • 删完忘更新后继：只标记被删顶点不给后继减 1，下一轮会误判"0 个入度 0"成有环。
  • 删除标记用 0：入度本来就有可能从 1 减到 0，用 −1 做删除标记才能与"自然变成 0"区分开。
记忆锚点：拓扑排序 = 每轮摘一个入度 0 的顶点；唯一 ⇔ 每轮候选恰好一个；0 个 = 有环、多于 1 个 = 分叉，两者都返回 0。

本题讲解：从位段到控制信号——add/slli/lw 在同一条数据通路上走一遍

第 0 步：机制先行——一条指令如何变成数据通路上的动作

机器指令是位段的拼装：32 位定长，操作码 IR[6:0] 决定"这是哪条指令"（add=0110011、slli=0010011、lw=0000011，三条互不相同），功能码 IR[14:12] 在需要时进一步细分，rd、rs1、rs2 各占 5 位指名寄存器编号；lw 的 IR[31:20] 是 12 位补码偏移 imm，slli 的 IR[24:20] 是移位量 shamt。

取指之后，控制器按位段译码，产生控制信号指挥数据通路这条"流水线"：rs1 读出的内容走 A 进 ALU 左输入；rs2 读出的内容走 B 进多路选择器（MUX）的 0 端；IR[31:20] 先过扩展器（Ext=0 零扩展、Ext=1 符号扩展）再进 MUX 的 1 端；ALUBsrc 决定 MUX 放行哪一路；ALUctr（000 加、001 减、010 逻辑左移）决定 ALU 做什么运算，同时产出 F、OF、SF、ZF、CF。

于是每一问的解法都是同一句口诀：看指令需要什么操作数、什么运算，就把 MUX 拨到对应挡位、给 ALUctr 对应编码。

第（2）问：ALUBsrc 取值、加法结果与标志位（5 分）

add 的功能是 R[rd] ← R[rs1] + R[rs2]：两个操作数都是寄存器内容，第二个操作数要选 rs2 读出的 B，而不是扩展器输出的立即数 → MUX 走 0 端，ALUBsrc = 0。

  • F = 1FDB9753H：ALU 输出端是 32 位结果，第 33 位的进位不进 F；
  • CF = 1：CF 记录的就是"最高位向前的进位"，那个 11FH 里多出来的 1；

第（5）问：A040 A103H 为什么一定是 lw、访存地址是多少（2 分）

  • F 答成 33 位：进位 1 是给 CF 的，ALU 输出端 F 只保留 32 位 1FDB9753H。
  • OF/CF 混用：有符号数溢出看 OF（判据"同号相加得异号"），无符号数溢出看 CF，别答反。

本题讲解：sum+=a[i] 的机器级落地——寻址链、小端读数与分页切分

第 0 步：机制先行——数组寻址公式如何拆成四条指令

sum += a[i] 在机器上要做两件事：先找到 a[i]，再做累加。找元素的通用公式是：地址 = 首地址 + 下标 × sizeof(元素)。int 型元素占 4 字节，而"×4"在硬件上有更便宜的等价动作——左移 2 位（2² = 4），这就是指令序列开头那条 slli 的由来。于是四条指令正好构成一条流水：

slli（算字节偏移 i×4）→ add（加首地址，得元素地址）→ lw（按地址取数）→ add（累加进 sum）。

第（1）问：三个变量各在哪个寄存器（3 分）

顺藤摸瓜，看每条指令"喂进来的是什么、产出的是什么"：

  • slli r4, r2, 2：被移的是 r2，算的是 i×4——只有下标才需要乘 4，所以 r2 存变量 i；
  • add r4, r3, r4：把 i×4 加到 r3 上才凑齐元素地址——加的对象必然是首地址，所以 r3 存数组 a 的首地址；
  • lw r5, 0(r4)：取出的 a[i] 落进 r5；
  • add r1, r1, r5：把 a[i] 累加进 r1——r1 存变量 sum。

即：数组 a 首地址 → r3，变量 i → r2，变量 sum → r1。

第（2）问：地址、机器数、页号与跨页（5 分）

已知 i=5，R[r1] = 0000 1332H（sum），R[r3] = 0013 DFF0H（首地址）。

① a[i] 的地址：R[r3] + i×4 = 0013DFF0H + 14H = 0013 E004H。

② a[i] 的机器数——先想明白小端为什么"倒着拼"：小端规则是数的最低有效字节放在最低地址。看题 44 图：地址 E004~E007 依次是 DC EC FF FF，即最低字节 DC 放在 E004、最高字节 FF 放在 E007。写机器数的习惯是从最高位写到最低位，所以要从高地址往低地址读：FF、FF、EC、DC → FFFF ECDCH。

③ sum 的机器数——为什么必须按补码解释：FFFFECDCH 符号位为 1，是负数，真值 = FFFFECDCH − 1_0000_0000H = −1324H = −4900；sum 旧值 00001332H = 4914，故 sum = 4914 + (−4900) = 14，机器数写 32 位补码 = 0000 000EH。（机器实际做的是 32 位截断加法：0x1332 + 0xFFFFECDC = 0x1_0000_000E，丢弃第 33 位进位后恰是 0000000EH——人算与机算殊途同归，但人必须按补码语义来读。）

④ a[i] 所在页的页号——为什么取高 20 位：页大小 4 KB = 2¹²，地址低 12 位是页内偏移，切掉偏移剩下的高 20 位就是页号。0013E004H = 页号 0013EH + 页内偏移 004H → 页号 0013EH。

⑤ 数组 a 至少占几页：a 的首地址 0013DFF0H 落在页 0013DH，距页末还剩 1000H − FF0H = 10H 即 16 B，恰好放下 a[0]~a[3]；a[4] 从 0013E000H 起已进入页 0013EH（a[5] 就在这一页）。数组从 0013DH 跨到 0013EH，至少存放在 2 页中——"至少"的依据是本次执行只动用了 a[0]~a[5] 这 6 个元素（24 B），更长的数组可能跨更多页。

第（3）问：slli 的机器码与 short 版本（2 分）

拼机器码按位段装填：高 7 位 0000000、shamt=2 → 00010、rs1=r2 → 00010、功能码 010、rd=r4 → 00100、操作码 0010011：

0000000 00010 00010 010 00100 0010011B = 0000 0000 0010 0001 0010 0010 0001 0011B

为什么 4 位一组就能变成十六进制：每 4 位二进制恰好对应 1 个十六进制位，上面 8 组依次是 0、0、2、1、2、2、1、3 → 0021 2213H。

若数组 a 改为 short 类型：short 占 2 字节，偏移公式变成 i×2，而"×2 = 左移 1 位"，移位量从 2 改成 1 → 汇编形式为 slli r4, r2, 1。

易错点

  • 小端拼反：把 DC EC FF FF 顺读成 DCECFFFFH——小端是"低位字节在低地址"，拼数要倒序连。
  • sum 忘按补码/截断：把 FFFFECDCH 当无符号大数、或保留第 33 位进位，都会答错；它是 −4900，和要按 32 位补码落笔。
  • 页号夹带偏移：页号只取高 20 位，0013E004H 的页号是 0013EH，别写成 0013E00H。
  • "至少 2 页"说不出依据：证据链是"首地址距页末只剩 16 B（恰容 a[0]~a[3]），a[4] 起进下一页"。
  • 机器码位段串位：slli 的 shamt 与 rs1 都在 IR[24:20] 附近，装填时按 高7位|shamt|rs1|功能码|rd|操作码 的顺序逐段对位，别错格。
一句话结论：首地址→r3、i→r2、sum→r1；a[i] 地址 0013E004H、机器数 FFFFECDCH、sum = 0000000EH、页号 0013EH、至少 2 页；机器码 00212213H，short 版为 slli r4, r2, 1。

本题讲解：页式虚存——先拆地址，再顺着页表走两次查

第 0 步：机制先行——页式翻译只动高位，偏移直通

页式虚拟存储把虚地址空间和物理地址空间都切成等大的页/页框。本题页大小 4 MB = 2²² B，所以地址的低 22 位是页内偏移，剩余高 10 位是页号（虚）或页框号（物）。

页式翻译的基本动作只有一步：拿虚地址高 10 位的页号去查页表，换成页框号；低 22 位的页内偏移原样直通、一字不改。本题的翻译结果印证了这一点：1234 5678H → BAB4 5678H，低 22 位 345678H 纹丝不动，变的只有高 10 位——这也顺带给出一个重要读法：页框号 = 物理地址的高 10 位。

页表是什么：按页号索引的数组，第 p 项存放第 p 页的页框号，每项 4 字节。于是任何"某个页的页表项地址"都遵循同一个公式：页表项地址 = 页表始址 + 页号 × 4。

第（1）问：缺页处理后更新的那个页表项（3 分）

第三步，页表项的物理地址。 页表被整体装载到物理 6540 0000H 开始的连续空间：页表项在页表内部的相对位置（偏移 120H）不因装载而变，变的只是基址——所以物理地址 = 6540 0000H + 120H = 6540 0120H。

本题讲解：一个缓冲区逼出两类信号量——互斥与同步的判别与最小实现

第 0 步：机制先行——wait/signal 在管什么，怎么判断该用哪种

信号量的本质是一个整型计数加两个原子操作：wait(S) 在 S>0 时把 S 减 1 并放行，否则阻塞等待；signal(S) 把 S 加 1，若有等待者则唤醒一个。计数的语义就是"当前可用资源（或已发生事件）的个数"。

判别该用哪种信号量，只看约束的形状：若约束是"不能同时上"——资源只有一个槽位，多个进程的操作互斥 → 用互斥信号量，初值 = 允许同时进入的进程数 = 1；若约束是"必须先后"——事件 A 不发生，B 就不能做 → 用同步信号量，初值 = 事件已发生的次数（通常为 0），A 结束处 signal，B 开始前 wait。

第（1）问：C1 是否临界区（2 分）

是临界区。 先看 C1 内部干了什么：B 只有一个槽位，C1 包含"确认 B 为空"与"写入分组"两个动作。P1、P2 的 C1 若并发交错，可能出现：两者都在对方写入之前查得"B 为空"，于是先后写入，后写者覆盖先写者的分组（丢数据）；或写入动作交错，破坏 B 中的数据。这段代码访问共享资源 B、并发执行时结果与推进次序有关、必须互斥执行——按定义，并发进程中必须互斥访问共享资源的那段代码就是临界区，所以实现 C1 的代码是临界区。

第（2）问：B 初空，P1 写一次、P2 读一次（3 分）

先分析约束的形状：B 初始为空，只有 P1 写一次、P2 读一次。"B 为空才能执行 C1"这一侧自动满足——P1 是唯一写者，它执行 C1 时 B 必为空（没有别的进程写过）；真正需要机制保证的只有一件事：C2 必须发生在 C1 之后（B 非空才能读）。这是"必须先后"的同步关系，按第 0 步的机制，一个初值为 0 的同步信号量就够：

进程代码
P1C1; signal(S);
P2wait(S); C2;

S 的作用：表示"B 中是否已有 P1 写入的数据"，初值 0 正是"B 初空、写事件发生 0 次"。机制上它如何强制先后：若 P2 先到，wait(S) 发现 S=0，被阻塞；P1 执行完 C1 后 signal(S) 把 S 增为 1 并唤醒 P2，P2 才能执行 C2——先后次序由计数器硬性保证，不是靠运气。为什么不用再加互斥信号量 mutex：读被同步信号量排他地压在写之后，对 B 的访问天然不会并发，再加 mutex 只会增加多余的同步开销，违背"信号量尽可能少"的要求。

第（3）问：B 初非空，P1、P2 各修改一次（3 分）

再看约束的形状：B 初始不为空，P1、P2 各执行一次 C3（修改）。两者没有先后次序要求——谁先谁后结果都对，所以不需要同步信号量；但两个 C3 都是"读 B—改 B—写回 B"的过程，同时进行会交错：一个进程的修改可能被另一个覆盖、或读到中间状态。这是"不能同时上"的互斥关系，用 1 个互斥信号量 mutex（初值 1，即 mutex=1）把各自的 C3 包起来：

进程代码
P1wait(mutex); C3; signal(mutex);
P2wait(mutex); C3; signal(mutex);

mutex 的作用：保护对共享资源 B 的修改操作，保证两个 C3 互斥执行。初值为什么是 1：初值 = 允许同时进入的进程数 = 1，第一个到达者直接进入（B 本来就可用），第二个到达者被挡在 wait(mutex) 上，等前者 signal(mutex) 释放后才能进入。为什么不用同步信号量：题面没有给出任何"必须先后"的约束，硬造一个先后关系反而改变题目语义。

易错点

  • 第（2）问多设 mutex：一写一读且读必在写后，S 本身已完成全部约束，加 mutex 违背"尽可能少"。
  • 第（2）问把 S 初值设为 1：S 的语义是"已有数据可读"（事件计数），不是"槽位空闲"；B 初空，初值必须是 0。
  • 第（3）问误用同步信号量：两个 C3 无先后要求，只有互斥要求，设同步信号量没有依据。
  • 第（1）问只答"是"不答为什么：得分点在"访问共享资源 B + 必须互斥执行"，缺了机制只给结论拿不到分。
记忆锚点：不能同时上 → 互斥信号量初值 1；必须先后 → 同步信号量初值 0，前事件后 signal、后事件前 wait；信号量个数以"约束最少表达"为准。

本题讲解：一条路由的旅程——IGP 选型、TTL、RIP 扩散节奏与 BGP 选路

第 0 步：机制先行——五问各挂在一个机制上

本题五个小问看似分散，其实各挂一个底层机制，先把机制立起来，答案都是自然推论：

  • IGP 选型挂"协议规模上限"：RIP 规定最大距离 15（16 即"不可达"），超大规模网络会误报不可达；OSPF 没有跳数限制。
  • TTL 挂"逐跳减一"：分组每被一个路由器转发，TTL 减 1；减到 0 即被丢弃，永远到不了目的主机。目的主机接收时不再减——所以初始 TTL 必须 ≥ 途经路由器数 + 1。
  • RIP 收敛挂"逐跳扩散 + 每轮发旧表"：路由器只与邻居交换距离向量，信息一轮只能前进一跳；且每轮发出的是本轮开始之前的路由表（旧表），刚在这一轮学到的新信息要等下一轮才往外传。
  • BGP 会话挂"跨不跨 AS"：不同 AS 的边界路由器之间是外部会话 eBGP；同一 AS 内部是内部会话 iBGP；承载路由通告的报文是 UPDATE。
  • BGP 选路挂"决策次序"：无策略约束时，先比 AS 路径条数（短者胜）；等长再比到下一跳的 IGP 距离（短者胜）。

第（1）问：AS4 选哪个 IGP（1 分）

AS4 内任意两主机通信可能超过 20 个路由器，超出 RIP 的 15 跳上限——超限路径会被 RIP 记成"不可达"，明明通的网却学不到。OSPF 无此限制 → AS4 选 OSPF。

第（2）问：AS3 内通信的初始 TTL（1 分）

AS3 内最多经过 15 个路由器。TTL 在这 15 个路由器处各被扣 1，扣掉 15 后必须还剩 ≥ 1 才能活着到达目的主机（若初始 TTL=15，到主机时恰好减成 0，分组在到达前被丢弃，无法被正常接收）→ 初始 TTL 至少 16。

第（3）问：R11~R16 均获正确路由至少多久（2 分）

用"逐跳扩散 + 每轮发旧表"推演两个直连网络的扩散轮数（t=0 为交换初始距离向量的时刻）：

  • 210.2.3.0/24 直连 R14：t=0 交换时 R14 把它写进初始向量，邻居 R11、R15 学得；t=30 第一次周期交换，R11、R15 发出的是"含此网"的旧表 → 邻居 R12（经 R11）、R13、R16（经 R15）学得。至此 6 台全部正确 → 至少 30 s。
  • 210.2.4.0/24 直连 R16：t=0 时邻居 R13、R15 学得；t=30 时 R13、R15 发旧表 → R12（经 R13）、R14（经 R15）学得；但 R11 的邻居恰好是 R12 和 R14，它们在 t=30 这轮发出的仍是各自不含此网的旧表——旧表规则把 R11 挡到下一轮；t=60 第二次周期交换，R12、R14 的新表到达 R11 → 至此全部正确 → 至少 60 s。

第（4）问：BGP 会话类型与报文（3 分）

R44 属 AS4、R13 属 AS1，跨 AS 的可达性通告由 BGP 外部会话（eBGP） 完成，通告使用 UPDATE 报文；R13 把该信息传给 R14、R15 时，三方同属 AS1，走 BGP 内部会话（iBGP）。判别只看一件事：通信双方是否同属一个 AS。

第（5）问：R14、R15 更新后的下一跳（2 分）

三条候选信息的 AS 路径条数：经 R11 为 3 个（AS2 AS8 AS19）、经 R13 为 3 个（AS4 AS10 AS19）、经 R12 为 4 个（AS3 AS7 AS11 AS19）——先淘汰最长的经 R12。剩下两条等长，进入下一比较项：到下一跳的 IGP 距离（AS1 内部跑 RIP，即 RIP 跳数；三条路都经 iBGP 学得，"eBGP 优先于 iBGP"这一档区分不了，所以直接轮到它）：

易错点

  • 第（1）问答 RIP：忽略"可能超过 20 个路由器"撞上 RIP 15 跳上限。
  • 第（2）问答 15：TTL 的减 1 只发生在路由器转发处，主机不减；TTL=0 即丢弃，等于"最多路由器数"还到不了主机，必须 +1。
  • 第（3）问两网都答 30 s：漏了"每轮发旧表"——R11 距 R16 三跳，且 t=30 时它的两个邻居发出的都是旧表，必须等第二轮（60 s）。
  • 第（4）问会话弄反：判别标准只有"跨不跨 AS"：跨 AS 用 eBGP，AS 内用 iBGP。
  • 第（5）问等长后乱选：按路由器名或 IP 排序都不对，要按"AS 路径条数 → 到下一跳的 IGP 距离"的次序比。
