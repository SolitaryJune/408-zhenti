本题讲解：单链表倒数第 k 个结点 —— 双指针一次遍历

第 0 步：机制先行——「倒数第 k」为什么难，双指针为什么行

单链表只能沿 link 单向走、不能随机访问，「倒数第 k 个」没有现成地址可算。直觉做法是两趟：先数出表长 n，再从头走 n−k+1 步。但链表一遍走完之前无法先知 n，而题目要求「尽可能高效」——所以要把「倒数」换成另一种度量方式。

双指针的机制一句话：用「距链尾的距离」定义「倒数」。让 p 先走 k 步，在链上制造出一段固定间隔，然后 p、q 同步前进、间隔保持；当 p 越过链尾（p == NULL）时，q 距链尾恰好 k 个结点——这正是倒数第 k 个。

这套机制靠三条推理支撑，也是最容易被追问的三个「为什么」：

  • 为什么间隔是 k？ p 先行阶段每步只动 p 不动 q，p 比 q 多走 1 步/次，走 k 次后两者恰好相差 k 步。
  • 为什么间隔一直不变？（循环不变量）同步阶段 p、q 每轮各前移 1 步，走过的步数始终相同，差值自然保持 k。
  • 为什么 p == NULL 时 q 就是倒数第 k 个？ 设表长 n，p == NULL 说明 p 已越过最后一个结点；q 比 p 落后 k 步，故 q 停在第 n−k+1 个结点，从后往前数正是第 k 个。举例验证：表长 5、k = 2——p 先行 2 步后指向第 3 个结点；同步走 3 步后 p 变 NULL，q 从第 1 个走到第 4 个，倒数第 2 个恰是第 4 个。✔

为什么用 count 判失败？ count 只在 p 先行阶段累加。若表长不足 k，p 没走满 k 步就越过了链尾，循环结束时 count < k——「间隔没能建成」就是 k 非法的信号，返回 0。

问 1：算法的基本设计思想

设 p、q 初始均指向第一个结点。p 先沿链走 k 步（若中途 p 为空，说明 k 超过表长，查找失败）；随后 p、q 同步后移、保持间隔 k；当 p 到达链尾（NULL）时，q 所指即倒数第 k 个结点。全程一遍遍历，时间 O(n)，辅助变量仅常数个——这比两趟法（先求表长再定位）少一整趟扫描，是「尽可能高效」的落点。

问 2：详细实现步骤

  1. 初始化：p = list 的后继，q = list 的后继（带头结点，第一个数据结点是头结点的后继），计数器 count = 0。
  2. 当 p 不为空时循环：若 count < k，只让 p 后移一步、count 加 1（p 先行建间隔）；否则 p、q 同时后移一步（间隔已建成，同步走）。
  3. 循环结束后：若 count = k，q 即倒数第 k 个结点，输出 q 的 data 域并返回 1；若 count < k，说明 k 超出表长，返回 0。

问 3：C 语言实现（关键处有注释）

行代码
1typedef struct LNode { int data; struct LNode *link; } *LinkList;
2int Search_k(LinkList list, int k) {
3 LinkList p = list->link, q = list->link; // 均指向第一个结点
4 int count = 0;
5 while (p != NULL) {
6 if (count < k) { p = p->link; count++; } // p 先行，建间隔 k
7 else { p = p->link; q = q->link; } // 间隔建成，同步前进
8 }
9 if (count == k) { printf("%d", q->data); return 1; } // 表长≥k，查找成功
10 return 0; // k 超出表长
11}

易错点

  • 两趟遍历：先求表长再定位，结果正确但违背「尽可能高效」，按次优解扣分。
  • 丢失败分支：count < k 时必须返回 0，漏判会继续解引用空指针。
  • 起点弄错：带头结点的链表第一个数据结点是 list 的后继，从 list 本身出发整条间隔错一位。
  • 间隔语义记反：p 先行 k 步、p 触底时 q 距链尾 k 个结点，对应「倒数第 k」；不要在先行步数上多加或少加 1。
一句话结论：p 先走 k 步建间隔，p、q 同步走到 p 越过链尾，q 即倒数第 k 个结点；一次遍历 O(n)、空间 O(1)，count 判 k 是否合法。
