本题讲解：GBN 序号比特数与信道利用率

结论：答案 B（4 比特）

要让信道利用率最高，发送方必须连续不断发帧。用最短帧 128 B 的最坏情况算：填满「一去一回」管道需要的帧数最多，再由 GBN 窗口约束 W ≤ 2^n − 1 定出 n。

为什么必须按最短帧算？ 利用率"最高"意味着确认回来之前发送方一刻不停；帧越短、发送时延 Tf 越小，同样 668 ms 的往返管道里要塞的帧数就越多——长帧（512 B，Tf = 256 ms）只要 5 帧多，短帧（128 B，Tf = 64 ms）要 10 帧多。序号比特数是按最坏需求设计的，所以取帧长下限 128 B。

第一步：算时间

量计算结果
帧发送时延 Tf128×8 bit ÷ 16 kbps64 ms
单向传播时延 Tp题目给定270 ms
ACK 发送时延 Ta确认帧与数据帧等长64 ms

第 1 帧从开始发送到它的确认完全回到发送方：Tf + Tp + Ta + Tp = 64 + 270 + 64 + 270 = 668 ms。

第二步：算窗口与比特数

这 668 ms 内发送方一刻不能停，需要连发的帧数 W ≥ 668 ÷ 64 ≈ 10.44，取 W ≥ 11。GBN 发送窗口受序号空间限制：2^n − 1 ≥ 11，即 2^n ≥ 12：

为什么窗口上限是 2^n − 1 而不是 2^n？ 序号共 2^n 个、GBN 接收窗口为 1。若发送窗口开满 2^n，发送方可以在一个确认都没收到的情况下把 0 ~ 2^n−1 号帧全部发完；此时一旦最老的累计确认丢失，重传的 0 号帧和"下一轮新发"的 0 号帧撞用同一序号，接收方无法分辨新旧帧，出了错就无法挽回。留出 1 个序号作隔离带，新帧序号就绝不会与未确认旧帧重合——这就是 W ≤ 2^n − 1 的由来。

  • n = 3：2^3 − 1 = 7，小于 11，不够；
  • n = 4：2^4 − 1 = 15 ≥ 11，可行。

故帧序号至少 4 比特。

易错点

  • 按 512 B 长帧算：Tf = 256 ms，此时 W ≥ 5、n = 3 就够——但帧长可以短到 128 B，要保证任何帧长下利用率都能最高，必须按最坏情况（最短帧）设计。
  • 漏掉 ACK 的发送时延：题目明说「接收方总是以与数据帧等长的帧进行确认」，Ta = Tf = 64 ms，不能当成瞬间到达。
  • 窗口上限记成 2^n：GBN 发送窗口最大是 2^n − 1，不是 2^n。
一句话：最短帧定出最大需求 11 帧，2^n − 1 ≥ 11 → n 至少为 4。
