本题讲解：指令 Cache 与数据 Cache 分离的目的

答案：D（减少指令流水线资源冲突）。

第一步：冲突从哪来

流水线中 IF（取指）与 MEM（取操作数）可能出现在同一个时钟周期：一条指令正在访存取数，同时流水线又在取下一条指令。若指令和数据共用一个 Cache，两个访问就要争用同一个 Cache 的同一个端口，流水线只能停一拍等待——这就是结构相关（资源冲突）。

第二步：分离的作用

把 Cache 拆成指令 Cache 与数据 Cache 两套后，IF 走指令 Cache、MEM 走数据 Cache，两条通路并行工作，取指与取数互不干扰 → 主要目的就是减少指令流水线的资源冲突。

易错点

  • 选 C（降低 CPU 平均访存时间）：这是分离带来的间接好处，但"主要目的"的口径是支持流水线并行取指取数，C 不是目的本身的表述。
  • 选 B（提高命中率）：命中率取决于容量、映射方式、块大小与替换算法，与指令、数据是否分开存放无直接关系。
  • 选 A（降低缺失损失）：缺失损失由缺失处理（写回、调块）的开销决定，分离 Cache 不改变它。
记忆锚点：分离 Cache 的关键词是"流水线"——IF 与 MEM 同周期并行访问，解决的是结构相关。
