本题讲解：读盘完成后操作系统必做之事

答案：A（修改进程状态为就绪态）。

第一步：回顾状态转换链

进程执行读盘的系统调用后因等待 I/O 进入阻塞态；磁盘把数据读入缓冲区后向 CPU 发中断，中断处理程序检查发现"P 等待的事件已发生" → 必做：把该进程的状态改为就绪态，挂入就绪队列。这一步不做，进程就永远没人唤醒。

第二步：为什么其他项不是"必做"

  • B 降低优先级：是否动态调整优先级取决于具体调度策略（如有些系统对 I/O 型进程提级），不是 I/O 完成的必然动作。
  • C 分配用户内存空间：内存分配发生在进程创建或动态增长时，与一次读盘完成无关。
  • D 增加时间片大小：时间片是调度策略的参数，I/O 完成并不必然修改它。
  • 另注意：被唤醒 ≠ 立即运行，从就绪到运行要等调度程序选中。

易错点

  • 答成"转为运行态"：I/O 完成只是唤醒进程放入就绪队列，能否上处理机由进程调度程序决定。
  • 以为要重新分配内存：读盘完成只意味着数据到达，不涉及内存管理动作。
一句话结论：I/O 完成后，等待该 I/O 的进程由阻塞态改成就绪态——这是操作系统必做的"唤醒"动作。
