本题讲解：Cache 命中率、异常判定与访盘/TLB 次数（按问展开）

先立机制：三种"资源账本"怎么记

本题在三套机制上记账，它们串成一条链：访存 → 查 TLB → 查页表 →（缺页才）读盘。

  • Cache 侧：取指/取数先看 Cache，命中与否取决于地址是否落在已调入的块里；
  • 虚存侧：取指和数据访存都要做"虚地址 → 物理地址"变换，页不在内存就触发缺页异常，由操作系统把页从磁盘调入；
  • TLB 侧：TLB 是页表项的缓存，每次地址变换都要用到它，查它决定变换走快路还是慢路。

条件：循环执行 N = 1000 次（(R6) = 1000），(R1) = (R2) = 0；机器代码已调入主存但不在 Cache 中；数组 A 未调入主存，所有元素在同一页、存放在磁盘同一扇区。

第 1 问：R2 的内容

R2 存循环变量 i，每轮加 1；bne 在 R2 ≠ R6 时跳回循环头，所以循环体恰好执行 1000 次——i 从 0 数到 1000 时与 R6 相等、退出循环。P 执行结束时 R2 = 1000（十六进制 3E8H）。

第 2 问：指令 Cache 数据区容量与命中率

  • 容量：数据区 = 行数 × 块大小 = 16 × 32 B = 512 B（标记位、有效位等不算在数据区内）。
  • 命中率分三步推导。第一步，24 B 代码落在哪个块：块大小 32 B → 地址低 5 位是块内偏移。起始地址 08048100H 的低 5 位为 0，恰好是某 32 B 块的块首；6 条指令占 08048100H ~ 08048117H 共 24 B ≤ 32 B，全部落在同一个块内。第二步，总共取指多少次：1000 轮 × 每轮 6 条 = 6000 次。第三步，缺多少次：题干明说"机器代码不在 Cache 中"，第 1 次取指必然缺失（并把整块调入）；此后整块都在 Cache 里，其余 5999 次全部命中。

命中率 = 5999 ÷ 6000 ≈ 99.98%。

第 3 问：异常与访盘、TLB 次数

  • 溢出异常 → 指令 4（add R1, R1, R5）。它是把 A[i] 累加进 sum 的加法：累加值随循环不断增大，可能超出机器数表示范围。为什么不是指令 2（add R4, R4, R3）：它算的是元素地址 = 首地址 + i × 4，最大不过"首地址 + 3999"，离 32 位补码的表示上限很远，不会溢出——会溢出的是数值累加，不是地址计算。
  • 缺页异常 → 指令 3（load R5, 0(R4)）。它是唯一访问数组 A 的访存指令，而 A 未调入主存，首次访问必然缺页。为什么取指不会缺页：题干说机器代码"已调入主存"，指令所在页常驻内存。
  • 读磁盘次数 = 1。缺页时调入的是整页；题干说 A 的所有元素在同一页且在磁盘同一扇区，一次 I/O 就把该页（该扇区）读了进来，之后 999 次访问都在内存完成。
  • TLB 次数 = 1001。TLB 初始为空：第 1 次取指查 TLB 1 次（缺失后把代码页的页表项装入，此后 6 条指令同页、取指直接命中）；每轮循环执行指令 3 取 A[i] 都要做一次虚实地址变换、查 TLB 一次，共 1000 次。合计 1 + 1000 = 1001 次。（官方口径：取指侧只计首次查表，数据访存侧每次都查。）

易错点

  • 命中率算成 100%：题干明说"机器代码不在 Cache 中"，第一次取指必然缺失，要计入 1 次。
  • 溢出写成指令 2：地址加法的上界很小不会溢出；可能溢出的是数值累加的指令 4。
  • 把读盘算成 1000 次：缺页调入的是整页，所有元素同页同扇区，一次 I/O 即可。
  • TLB 漏掉取指那 1 次：只算 1000 次 load 的地址变换，漏了 TLB 初始为空时第 1 次取指的查表。
记忆锚点：同块 24B 一次调块 → 5999/6000；溢出看数值累加、缺页看访存（取指不缺页因代码已调入）；同页同扇区读盘 1 次；TLB = 1 次首取指 + 1000 次取数变换。
