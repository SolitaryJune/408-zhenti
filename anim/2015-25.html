本题讲解：运行态 → 就绪态的触发事件

答案：D（被高优先级进程抢占）。

第一步：区分两条"下台"路径

运行态的进程离开 CPU 有两种去向，判据是进程自身还能不能马上运行：

  • 运行 → 阻塞：进程自己请求资源或等待事件（主动让出），没拿到就得等；
  • 运行 → 就绪：进程本身随时可运行，只是 CPU 被别人拿走（被动失去）。

第二步：逐项归类

选项事件去向理由
A执行 P(wait) 操作阻塞信号量值不足时申请失败，等待其他进程 V 它
B申请内存失败阻塞等待"内存可用"这一事件
C启动 I/O 设备阻塞等待 I/O 完成
D被高优先级进程抢占就绪可剥夺调度下 CPU 被夺走，但进程随时可再次被调度

第三步：同类场景补充

运行 → 就绪还有另一个典型事件：时间片用完。这类事件的共同点是"进程没毛病，就差一个 CPU"。

易错点

  • 误选 A/B/C：三者都是"等资源/等事件"，属于阻塞而非就绪；阻塞进程即使 CPU 空闲也不能被调度，必须先等事件发生被唤醒。
  • 混淆"抢占"与"自愿让出"：抢占（剥夺）是调度程序强制收回 CPU，进程本身可运行，所以回到就绪队列。
一句话结论：等资源 → 阻塞；被抢 CPU → 就绪。
