本题讲解：基址寻址里的补码符号扩展与大端存放

答案：D（EFFF FF15H）。

第 0 步：先把 FF12H 这个数"读对"——为什么是负数、为什么减 10000H

形式地址 FF12H 是 16 位补码。补码不是另一种数制，它是模运算下的记数方式：16 位一共 65536 个状态（0000H~FFFFH），把这个环从中间掰开——最高位为 0（0000H~7FFFH）表示 0 ~ +32767；最高位为 1（8000H~FFFFH）表示 −32768 ~ −1。

所以判断就一句话：最高位为 1 → 负数；真值 = 无符号解释值 − 65536。

FF12H 按无符号读是 65298，是负数，真值 = 65298 − 65536 = −238 = −EEH。

为什么"减 10000H"是合法的？ 这正是补码的定义：位串 FF12H 代表 −238，是因为 −238 ≡ 65298 (mod 65536)。从位串求真值，减一次模即可。

"取反加一"同样对，还能互相印证：FF12H 取反得 00EDH，加 1 得 00EEH = 238 → 真值 −238。两条路结果必然一致——"取反加一"与"减模"在数学上是同一件事，选顺手的用。

第 1 步：为什么要符号扩展——32 位加法器不吃 16 位输入

EA = (BR) + A，BR = F000 0000H 是 32 位的，加法在 32 位加法器里做，−238 必须先写成 32 位补码：FFFF FF12H（高 16 位全补 1，低 16 位照抄）。

规则：补码扩展 = 左边补符号位——负数补 1，正数补 0。

为什么补符号位数值不变？ 直觉：给一个负补码数往左多写一串 1，它"欠的账"没变。数学上：FF12H ≡ −238 (mod 2¹⁶)，FFFF FF12H ≡ −238 (mod 2³²)——同一个负数在更大模下的化身。

反例正是干扰项 A：若补 0（零扩展），FF12H 变成 0000 FF12H = +65298，数值从 −238 变成 +65298，EA 就算成 F000 FF12H 了。

（正数为什么补 0 没问题？正数没有"欠账"，左边加 0 不改变值——所以规则统一写成"补符号位"。）

第 2 步：算 EA——进位为什么可以扔

  F000 0000H
+ FFFF FF12H
= 1 EFFF FF12H   ← 第 33 位的进位

32 位机器只有 32 位地址线，第 33 位的 1 自然丢弃——模 2³² 运算本来就允许丢进位，丢掉 2³² 不影响 32 位内的余数。EA = EFFF FF12H。

第 3 步：大端方式决定 LSB 在哪

操作数 1234 FF00H 共 4 字节：12（MSB，最高有效字节）、34、FF、00（LSB，最低有效字节）。

大端 = 最高有效字节放最低地址，从 EA 开始依次摆放：

地址EFFF FF12HEFFF FF13HEFFF FF14HEFFF FF15H
内容12（MSB）34FF00（LSB）

LSB = 00H 落在 EA + 3 = EFFF FF15H，选 D。

（若是小端，LSB 在 EA 本身——正是干扰项 B 的位置。）

易错点

  • 零扩展代替符号扩展 → F000 FF12H（干扰项 A）。FF12H 是负数，高位必须补 1。
  • 大小端弄反 → EFFF FF12H（干扰项 C）。大端 = MSB 在低地址，所以 LSB 在最高地址 EA+3。
  • 不明白为什么减 10000H → 补码真值 = 无符号值 − 模（最高位为 1 时）；模就是"状态总数"65536。
记忆锚点：负补码真值 = 无符号值 − 2ⁿ；符号扩展 = 高位补符号位、数值不变；大端 = MSB 在低地址 → LSB 在 EA + 字节数 − 1。
