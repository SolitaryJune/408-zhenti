本题讲解：流水线数据冒险的判定

答案：C（I2 和 I4）。

第 0 步：先立机制——数据冒险的本质是"值还没落地就被读走"

五段流水线（取指、译码/取数、执行、访存、写回）里多条指令同时在不同段推进。若后一条指令在取数段就要用某个寄存器的值，而写这个寄存器的前一条指令还没走到写回段，读到的就是旧值——这才是数据冒险。所以判据围绕"写"建立：

  • 前写后读（RAW）：有冒险——读的人要的值还在路上；
  • 读与读相遇：永远不冲突——读操作不改变寄存器内容，谁先谁后读到的都是同一个当前值，互相不干扰；
  • 写与写（WAW）：在本题这种按序五段流水线中，写回仍按程序顺序进行，次序不会乱，相邻指令间实际不会形成 WAW 冒险。

于是只需列出每条指令的"读集、写集"，逐对检查"写"有没有撞上别人的"读"。

第 1 步：列出每条指令读、写的寄存器

指令读取寄存器写入寄存器
I1 add s2, s1, s0s1, s0s2
I2 load s3, 0(t2)t2s3
I3 add s2, s2, s3s2, s3s2
I4 store s2, 0(t2)s2, t2（写主存，不写寄存器）

注意 I4 是 store：它要把 s2 的值读出来写进主存，自己不写任何寄存器。

第 2 步：逐对检查

  • I1 与 I3：I1 写 s2，I3 要读 s2 → RAW，有冒险。
  • I2 与 I3：I2 写 s3，I3 读 s3 → RAW，有冒险。
  • I2 与 I4：I2 写 s3、读 t2；I4 读 s2、t2、写主存。两人唯一同用的是 t2，且都是读——读读相容，不构成冒险；s3 只有 I2 在写、无人读。无数据冒险。
  • I3 与 I4：I3 写 s2，I4 要读 s2 → RAW，有冒险。

易错点

  • 把 t2 当成 I2 与 I4 的冲突点：两条指令都只"读" t2，多个读者相容——这正是 C 项成立的根据。
  • 漏判 I3 与 I4：store 并非"只写不用寄存器"，它要从 s2 取数送进主存，前写后读照样冒险。
  • 以为 store 会写寄存器：store 的目的地是主存，寄存器只出不进。
记忆锚点：冒险只跟"写"过不去——前写后读才算数，读读永远相容；store 只读寄存器、只写主存。
