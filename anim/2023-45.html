本题讲解：用 swap 指令实现临界区互斥

先立机制：lock 是线程间共享的锁变量，按题面约定 lock = TRUE 表示临界区被占用，lock = FALSE 表示空闲；key 是每个线程私有的申请变量。swap 是一条硬件原子指令：一个指令周期内一步完成 key 与 lock 的内容互换，中途不可被打断。

第 1 问：找出错误语句并改正（不增加语句条数）

共两处错误：进入区的 if (key == TRUE) swap key, lock; 应把 if 改成 while；退出区的 lock = TRUE; 应改成 lock = FALSE;。两处都只换关键字或一个字，语句条数不变。

进入区为什么必须是 while——先看 swap 协议怎么运转：线程想进临界区时把自己的 key 置 TRUE（"我想进"），然后执行 swap：key 换入 lock 的旧值。若 lock = FALSE（空闲），key 变为 FALSE，循环条件不成立，线程进临界区——同时 lock 已被换成 TRUE，锁被它带走；若 lock = TRUE（被占用），key 换出来还是 TRUE，if 只试一次就放行，第二个线程会在锁已被占时照样闯进去，与持锁者同时在临界区里，互斥失败。while 的语义是"没换到空闲就反复交换、原地重试"，直到某个时刻把 FALSE 换进 key 才放行。

为什么用 swap 就不会出现两个线程同时进去？ 因为 swap 把检查 lock 与占住 lock 合并成一步：两个线程各自 swap，同一份 lock 内容只能被换走一次——先执行者拿走 FALSE，后执行者拿到的必然是 TRUE。若换成"先读 lock、再写 TRUE"两步分开做，两线程可能都读到 FALSE，各自再写 TRUE，双双进入——单条不可分割的指令正是为了消灭这个"都看见空闲"的窗口。

退出区为什么是 lock = FALSE：释放临界区就是把"占用"清回"空闲"，置 lock = FALSE 后，别的线程才能在 while 里换到 FALSE 进入。写成 TRUE 等于永远宣告"我被占用"，其他线程将在 while 中无限等待，谁也进不去。

两处错误对照：

位置学生写的（错误）应改为错因
进入区if (key == TRUE) swap key, lock;while (key == TRUE) swap key, lock;只试一次就闯入，锁被占也进
退出区lock = TRUE;lock = FALSE;释放写反，别人永远等不到 FALSE

第 2 问：能否用 newSwap(&key, &lock) 代替 swap 指令

不能用 newSwap(&key, &lock) 代替 swap key, lock。原子性来自"单条硬件指令不可分割"，不来自函数封装：swap 的读、换、写发生在一个指令周期内，中断无法插进来；而 newSwap 是普通函数，函数体里"读 lock、写 key、写 lock"是多条机器指令，任何一条之间都可能被时钟中断打断、被其他线程插足。典型交错：T2 执行到"key = lock（旧值 FALSE）"后被 T1 抢占；T1 完整跑完自己的 newSwap，把 lock 写成 TRUE 并进入临界区；T2 恢复后把临时值（FALSE）写回 lock。结果是两个线程的 key 都是 FALSE，都"以为"自己拿到了锁，同时进入临界区——这正是上一问说要消灭的"检查与上锁分两步"的窗口，互斥被破坏。

易错点

  • 把 if 与 while 混为一谈：进入区必须"循环尝试"直到抢到 FALSE，一次判断只适合"要么拿到要么放弃"的场合。
  • 记反 lock 的语义：本题 TRUE = 占用、FALSE = 空闲，释放置 FALSE——要按题面约定，不能套自己背的模板。
  • 以为函数调用也能原子：原子性来自硬件单指令，函数封装再"一体化"也只是多条指令的拼接；这正是 TSL/swap 类指令存在的意义。
  • 只改 while 忘改退出区（或反之）：两处错误独立扣分，进入区管"怎么进"，退出区管"怎么放"，缺一不可。
进入区用 while 循环交换（swap 把检查与占锁合成一步，FALSE 只会被换走一次）、退出区置 lock = FALSE；newSwap 是多条指令的普通函数，检查与上锁可被中断拆开，不能替代硬件 swap。
