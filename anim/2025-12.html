本题讲解：short 转 unsigned int 的符号扩展与无符号解释

第 0 步：先立模型——补码与无符号数是同一位串的两种解释

32 位一共只有 2^32 个位串。补码和无符号数是同一批位串的两种读法：位串按补码读出真值 t（−2^31 ~ 2^31−1），按无符号读出 u（0 ~ 2^32−1），两者恒满足 u ≡ t (mod 2^32)——真值为负时就是 u = t + 2^32。这正是本题的全部机关：si 按补码是 −32767，赋给 unsigned 后同一串位按无符号读，值就是 −32767 + 2^32。

为什么符号扩展补 1 而数值不变？ 8001H 之所以代表 −32767，依据是 −32767 ≡ 32769 (mod 2^16)；高位再补一串 1 得 FFFF 8001H，依据变成 −32767 ≡ 4294934529 (mod 2^32)——同一个负数在更大模下的化身，同余关系被高位全 1 维持着。若补 0，同余关系破坏，就换成另一个数了。

第一步：先写出 si 的 16 位补码

si = -32767。先写 32767 的 16 位表示：0111 1111 1111 1111B = 7FFFH；取负数按「按位取反、末位加 1」得 1000 0000 0000 0001B，即 [si]补 = 8001H。

第二步：赋给 32 位 unsigned int 时发生了什么

C 语言转换规则：short（16 位有符号）赋给 unsigned int（32 位）时，先把 16 位补码符号扩展到 32 位——符号位是 1，高 16 位全部补 1，得机器数 FFFF 8001H；然后这个 32 位机器数按无符号数解释。

阶段机器数解释
si 的 16 位补码8001H真值 -32767
符号扩展成 32 位FFFF 8001H按补码解释仍是 -32767
按 unsigned 解释FFFF 8001H2^32 - 32767

第三步：按无符号数算真值

FFFF 8001H 的最高位是 1，但 ui 是无符号类型，按第 0 步的模型直接加模：u = −32767 + 2^32 = 2^32 − 32767。而 32767 = 2^15 − 1，所以 ui = 2^32 − 2^15 + 1，选 D。

易错点

  • 做成零扩展：把 8001H 前面直接补 0 得 0000 8001H，无符号解释正好是 2^15 + 1——这就是干扰项 A。有符号数加宽位数必须符号扩展。
  • 误选 B（2^15）：把 8001H 的无符号值记成 2^15——记错邻居：无符号值 2^15 = 8000H 才是 −32768 的位串；8001H 的无符号值是 2^15 + 1 = 32769。
  • 按补码读回：得到 -32767，忽略了 ui 是无符号类型，最高位 1 不再当符号。
  • 加减差 1：8001H 对应的绝对值是 32767 = 2^15 − 1，所以减 32767 等价于 −2^15 + 1；误算成 2^32 − 2^15 − 1 就是干扰项 C。
一句话结论：先符号扩展得 FFFF 8001H，再按无符号解释为 2^32 − 2^15 + 1，选 D。
