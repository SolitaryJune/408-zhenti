## 本题讲解：直接映射 Cache 的容量、行号与命中率

> 答题框架：地址拆位算容量 → 数组元素地址换算出块号与行号 → 两种遍历顺序分别推命中率。

### 第(1)问：数据 Cache 的总容量

- 主存 256MB 按字节编址 → 地址 28 位；块大小 64B = 2^6 → 块内偏移 6 位；8 行 → 行号 3 位；标记位 = 28 − 6 − 3 = **19 位**。
- 每行：数据 64 × 8 = 512 bit + 标记 19 bit + 有效位 1 bit = **532 bit**。
- 总容量 = 8 行 × 532 bit = 4256 bit = **532 B**。

### 第(2)问：a[0][31] 与 a[1][1] 的 Cache 行号

数组按行优先存放、首地址 320（十进制）、int 占 4B、每行 256 个元素：

| 元素 | 主存地址 | 主存块号 | Cache 行号（块号 mod 8） |
|---|---|---|---|
| a[0][31] | 320 + 31×4 = 444 | 444 ÷ 64 取整 = 6 | 6 mod 8 = **6** |
| a[1][1] | 320 + (256+1)×4 = 1348 | 1348 ÷ 64 取整 = 21 | 21 mod 8 = **5** |

### 第(3)问：两个程序的命中率与执行时间

- **程序 A（按行访问）**：一块 64B 恰好装 16 个 int，调入一块后连续 16 次访问只有第一次 miss；全数组 65536 次访问、共 65536 ÷ 16 = 4096 块 → 命中率 = (65536 − 4096) ÷ 65536 = **93.75%**。
- **程序 B（按列访问）**：同列相邻元素相距 256 × 4 = 1024B，每次访问都换块；且相距 8 个块的地址又映射到同一 Cache 行（直接映射），到再次轮到该行时数据早已被换出 → 每次访问都 miss → 命中率 **0%**。
- **程序 A 执行时间更短**：A 顺序访问利用了空间局部性，Cache 几乎每次都命中；B 几乎每次访存都要真正访问主存。

### 易错点

- **容量漏算有效位**：每行还要加 1 位有效位（本题不考虑替换算法控制位与一致性维护位），532B 才是答案。
- **首地址 320 没加**：地址 = 320 + 元素偏移，漏加会算错块号。
- **行号忘取模**：直接映射行号 = 主存块号 mod 8，21 不是行号，5 才是。

> 一句话结论：数据 Cache 总容量 532B；a[0][31]、a[1][1] 对应行号 6、5；A 命中率 93.75%、B 为 0%，程序 A 执行更快。
