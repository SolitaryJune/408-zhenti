## 本题讲解：银行家算法安全性检测——找安全序列

**答案：D（安全序列不存在）**。检测方法：反复寻找"尚需资源 ≤ 可用资源"的进程，让它运行完毕并回收其全部已分配资源；若推到某一步后没有任何进程能继续，则系统不安全。本题逐一检验后，P2、P3 始终无法满足。

题中数据（可用资源 R1 R2 R3 = 0 2 1）：

| 进程 | 已分配 R1 R2 R3 | 尚需 R1 R2 R3 |
|---|---|---|
| P1 | 2 0 0 | 0 0 1 |
| P2 | 1 2 0 | 1 3 2 |
| P3 | 0 1 1 | 1 3 1 |
| P4 | 0 0 1 | 2 0 0 |

### 第一步：谁能先运行

与可用 (0,2,1) 逐一比较：

- P1 尚需 (0,0,1) ≤ (0,2,1)，满足；
- P2 尚需 (1,3,2)：R1 缺 1、R2 缺 1，不满足；
- P3 尚需 (1,3,1)：R2 缺 1，不满足；
- P4 尚需 (2,0,0)：R1 缺 2，不满足。

开局只有 P1 能运行，所以任何安全序列都必须以 P1 开头——选项 A、B、C 也都如此。

### 第二步：P1 运行后的僵局

P1 完成后回收其已分配的 (2,0,0)，可用资源变为 (2,2,1)。再比：

- P2 需 (1,3,2)：R2 仍缺 1，不行；
- P3 需 (1,3,1)：R2 仍缺 1，不行；
- P4 需 (2,0,0) ≤ (2,2,1)，可以让 P4 先运行。

### 第三步：连 P4 也救不回来

按选项 C 的顺序 P1、P4 先行：P4 完成后回收 (0,0,1)，可用变为 (2,2,2)。但 P2 尚需 R2=3、P3 尚需 R2=3，都仍大于 2——剩下的两个进程谁也满足不了，执行到一半必然卡死。

### 结论

- 选项 A（P1, P2, …）：第二步选 P2 即失败；
- 选项 B（P1, P3, …）：第二步选 P3 即失败；
- 选项 C（P1, P4, P3, …）：第三步选 P3 失败。

所有顺序都无法推进到底，不存在安全序列，系统处于不安全状态，选 **D**。

### 易错点

- **找到一个能运行的进程就认为安全**：P1、P4 能运行不代表存在安全序列，必须让所有进程都能依次完成。
- **忘记回收资源**：进程完成后必须把它的"已分配"全部加回可用资源，再继续检测。

> 记忆点：安全性检测 = 反复找"尚需 ≤ 可用"的进程运行并回收资源；找不到可推进者即不安全。
