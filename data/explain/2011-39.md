## 本题讲解：TCP 第二次握手的报文段

**答案：C（SYN=1，ACK=1，seq=11221，ack=11221）**

### 第一步：认清这是第几次握手

甲发来 (SYN=1，seq=11220) 是**第一次握手**；乙接受连接，回送的是**第二次握手**：既要带上乙自己的同步位（SYN=1），又要确认甲的 SYN（ACK=1）。SYN=0、ACK=0 的 A、D 直接排除。

### 第二步：定确认号 ack

规则：**SYN 报文段虽然不携带数据，但要消耗一个序号**。甲的序号用到了 11220，乙期望甲的下一个字节从 11221 开始，所以 ack = 11220 + 1 = **11221**。B 的 ack = 11220，错在"忘了 SYN 占一个序号"，排除。

### 第三步：定序号 seq

seq 是**乙自己选择**的初始序号，与甲的 11220 无关；四个选项中同时满足 SYN=1、ACK=1、ack=11221 的只有 C（seq=11221）。

| 选项 | SYN / ACK | ack | 判定 |
|---|---|---|---|
| A | 0 / 0 | 11221 | 没有同步与确认位 ✗ |
| B | 1 / 1 | 11220 | 漏加 SYN 占的 1 ✗ |
| C | 1 / 1 | 11221 | 全对 ✓ |
| D | 0 / 0 | 11220 | 同 A ✗ |

### 易错点

- **ack 忘了加 1**：SYN 占一个序号是三次握手的经典考点，确认号 = 对方 seq + 1。
- **以为第二次握手只回 ACK**：乙的同步也要借这次握手完成，所以 SYN 仍为 1。

> 一句话结论：第二次握手 = (SYN=1，ACK=1，seq=乙自选，ack=甲 seq+1=11221)，选 C。
