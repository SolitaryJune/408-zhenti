## 本题讲解：单链表共同后缀的起始位置——先数长度、再对齐、再同步

### 第 0 步：先看清"共享后缀"在链表里意味着什么

题图的存储方式是：两个单词各有一条链，从共同后缀首结点（字符 i）开始**两条链汇成同一条链**——i、n、g 这些结点只有一份，两个表经 next 指向同一批结点。由此得到两条关键性质：

1. **共享是"结点同一"，不是"内容相同"**：汇合点 X 之后每个结点地址都一样；X 之前两链的结点互不相干（否则汇合点会更靠前）。
2. **单链表只有 next，不能从表尾倒着走**：想"从后往前找第一个不同的结点"走不通，只能把方向问题转为正向——让两个指针站到"同一条链"上并排前进。

思路由此自然浮现：X 及其后是同一条链，X 之前是两段长度不同的私有前缀。若让两指针**到表尾等距**后同步后移：未到 X 时，两指针必各自走在私有前缀上（p ≠ q）；一旦同到 X 或其后，走的已是同一条链（p == q）。所以**第一次 p == q 的结点恰好就是 X**；走到 NULL 仍未相遇则无共同后缀。

而"等距"怎么保证？表尾看不见，但表长数得出来：先各遍历一遍求 len1、len2，让较长链的指针先走 |len1−len2| 步即可。两个最可能追问的"为什么"先答掉：

- **为什么比较指针而不比较字符**？字符相同不代表同一结点（两个表都可能含 'i'）；只有 p == q（同一地址）才能保证其后整段共享。
- **为什么先数长度**？单链表不能倒走，"两段前缀差多少"只有数一遍才知道。

### 第 1 问：算法的基本设计思想

1. 分别遍历两链（带头结点，从 `head->next` 起数）求出 len1、len2；
2. 对齐：p、q 从两表**头结点**出发，较长表的指针先走 |len1−len2| 步——此后两指针到表尾（NULL）的步数相等；
3. 同步后移，第一个 p == q 的结点即共同后缀首结点（图中字符 i 所在结点）；直至 NULL 未相遇则返回"无共同后缀"。

用题中例子走一遍："loading"（l→o→a→d→i→n→g，len1=7）、"being"（b→e→i→n→g，len2=5）。p 先走 2 步到 'o' 结点（此后 p、q 到 NULL 均为 6 步）；同步第 1 步 p=a、q=b，第 2 步 p=d、q=e，第 3 步两指针同时到达字符 i 的结点——即共同后缀的起始位置 p。

### 第 2 问：C 语言描述（要点）

1. `int Length(LinkNode *head)`：从 `head->next` 起计数，返回数据结点个数（跳过头结点）；
2. 对齐：`p = str1; q = str2;` 若 `len1 > len2` 则 p 先走 `len1 - len2` 步，否则 q 先走 `len2 - len1` 步；
3. 同步：`while (p != NULL && q != NULL && p != q) { p = p->next; q = q->next; }`；
4. 返回 `p`——要么指向共同后缀首结点，要么为 NULL（无共同后缀）。

（对齐的等距性可以验证：p 从头结点走 `len1−len2` 步后，p 之后（不含 p）恰剩 `len2` 个结点，与 q 从头结点出发后的 `len2` 个结点相等——计数跳过头结点、对齐从头结点走，两者正是配套的。）

### 第 3 问：时间复杂度

数长度：两链各扫一遍，O(len1+len2)；对齐：走 |len1−len2| 步；同步：至多走到 NULL，步数不超过较短链长。每个结点至多被扫 2 次，总计 **O(len1+len2)**。若用"双重循环逐结点比对"（对 str1 的每个结点去 str2 中找相同字符/位置），是 O(len1×len2)，不满足"时间上尽可能高效"的要求。

### 易错点

- **同步时比较字符而不比较指针**：必须 `p == q`——字符相同 ≠ 同一结点，这是本题最核心的陷阱。
- **计数与对齐的起点不配套**：计数从 `head->next`（跳过头结点），对齐时指针从头结点出发走差值步；起点一旦搞混，"等距"就不成立。
- **漏掉无共同后缀的情形**：循环条件必须含 `p != NULL && q != NULL`，无共享时函数返回 NULL，而不是空指针崩溃。

> 记忆锚点：共享后缀 = 尾部同一条链 → **数长度 → 对齐 → 同步 → 比指针**，O(len1+len2)。
