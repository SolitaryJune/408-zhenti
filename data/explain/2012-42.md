## 本题讲解：求两单链表共同后缀的起始位置

### 答题框架（先记这个）

1. 关键观察：**后缀共享 ⇒ 两链表尾部是同一条链**（图中两个表都汇入字符 i 结点）；
2. 单链表无法从后往前找 ⇒ 让两指针**先"尾部对齐"，再同步后移**；
3. 复杂度要做到 O(len1+len2)：先数长度、再对齐、再同步，每条链只扫常数遍。

### 第 1 问：算法的基本设计思想

- 分别遍历两个链表（从 `head->next` 开始，跳过头结点），求出数据结点个数 len1、len2；
- 让**较长链表的指针先走 |len1−len2| 步**，使 p、q 到表尾的距离相等；
- 然后 p、q **同步后移**，第一个 p == q 的结点即共同后缀的起始位置（图中字符 i 所在结点）；若走到 NULL 仍未相遇，则无共同后缀。
- 以题中例子验证："loading" len1=7、"being" len2=5，p 先走 2 步，同步后第 3 步两指针同时到达字符 i 结点。

### 第 2 问：C 语言描述（要点版）

1. `int Length(LinkNode *head)`：从 `head->next` 起计数，返回数据结点个数；
2. 对齐：`p = str1; q = str2;` 若 `len1 > len2` 则 p 先走 `len1-len2` 步，否则 q 先走 `len2-len1` 步（注意 p、q 都从**头结点**出发）；
3. 同步：`while (p != NULL && p != q) { p = p->next; q = q->next; }`；
4. 返回 `p`——它要么指向共同后缀首结点，要么为 NULL（无共同后缀）。

### 第 3 问：时间复杂度

求长度各遍历一遍：O(len1+len2)；对齐与同步至多再走较短链表长度的结点：O(max(len1,len2))。总计 **O(len1+len2)**。若用"双重循环逐结点比对"则为 O(len1×len2)，不满足"时间尽可能高效"的要求。

### 易错点

- **长度计数与对齐的起点搞混**：本题带头结点，计数要跳过头结点；对齐时 p 从头结点出发走 len1−len2 步，恰好落在与 q"到表尾等距"的位置。
- **同步时比较 data 值而不是结点指针**：必须比较 **p == q（同一结点）**——两链表中出现相同字符不代表是同一结点，只有指针相同才真正进入共享后缀。

> 记忆锚点：先数长度、再对齐、再同步，比较的是**指针**——O(len1+len2)。
