## 本题讲解：找主元素——摩尔投票算法（13 分）

### 答题框架

大题按问作答：先写设计思想（两遍扫描：先投票、后验证），再写代码（关键处注释），最后写复杂度。核心一句话：一遍扫描用"抵消"找出候选主元素，第二遍扫描验证候选是否真的超过一半。

### 第（1）问：算法的基本设计思想

采用摩尔投票思想，分两个阶段：

1. **找候选**：遍历数组，维护候选值 c 与计数 count。遇到与 c 相同的元素，count 加 1；遇到不同的元素，count 减 1；当 count 减到 0 时，把当前元素换作新候选、count 置 1。若主元素 x 真的存在（出现次数大于 n/2），它"一换一抵消"后必有剩余，最终候选一定是 x。
2. **再次遍历验证**：候选未必真是主元素——例如 A=(0,5,5,3,5,1,5,7) 抵消后候选是 5，但 5 只出现 4 次，不大于 8/2。所以第二遍统计候选出现次数，若大于 n/2 输出该元素，否则输出 −1。

### 第（2）问：C 语言实现（与参考答案一致，关键处注释）

1. `int i, c, count = 1;` // c 保存候选主元素，count 计数
2. `c = A[0];` // 先设 A[0] 为候选
3. `for (i = 1; i < n; i++)` // 第一遍：找候选
4. `if (A[i] == c) count++;` // 与候选相同则计数加一
5. `else if (count > 0) count--;` // 不同则抵消一次
6. `else { c = A[i]; count = 1; }` // 计数为零时更换候选
7. `if (count > 0)` // 候选有剩余才值得验证
8. `for (i = count = 0; i < n; i++)` // 第二遍：重新计数
9. `if (A[i] == c) count++;` // 统计候选实际出现次数
10. `if (count > n/2) return c; else return -1;` // 严格大于 n/2 才确认

### 第（3）问：时间复杂度与空间复杂度

- 时间复杂度：两次线性遍历数组，为 **O(n)**。
- 空间复杂度：只用 c、count、i 等常数个辅助变量，为 **O(1)**。

### 易错点

- **只做一遍扫描就输出候选**：候选不一定是主元素，缺少第二遍验证会丢分（题干第二个例子就是反例）。
- **改用排序或哈希表统计**：虽然正确，但时间是 O(n log n) 或空间 O(n)，达不到题目"尽可能高效"的 O(n) 时间、O(1) 空间。
- **判断条件写成 count ≥ n/2**：必须是严格大于 n/2；反例中 5 出现 4 次恰好等于 8/2，应输出 −1。

> 两遍扫描：先投票选候选，再数票做验证；时间 O(n)、空间 O(1)。
