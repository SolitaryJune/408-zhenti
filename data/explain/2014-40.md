## 本题讲解：访问 Web 主页可能用到的协议，谁"不可能"

### 结论：答案 D（SMTP）

浏览器访问某大学 Web 主页，整条链路是：**域名解析（DNS）→ 建立 TCP 连接 → 发送 HTTP 请求 → 返回网页**，中间可能穿插 ARP 解析地址、PPP 拨号接入。四个选项逐一对号，只有 SMTP 与"浏览网页"无关。

### 第一步：先列可能用到的协议清单

| 环节 | 协议 |
|---|---|
| 域名解析 www.xxx.edu.cn | DNS（默认用 **UDP** 53 端口，偶尔 TCP） |
| 同网段找网关/服务器的 MAC 地址 | **ARP** |
| 家庭拨号/ADSL 接入链路 | **PPP**（数据链路层） |
| 与 Web 服务器传网页 | TCP + HTTP（+ IP） |

### 第二步：逐项判断"可能还是不可能"

- **A PPP**：若主机通过电话线/ADSL 等接入，接入链路上用的就是 PPP——**可能用到**。
- **B ARP**：主机要先把 IP 分组交给网关（或直接给服务器），必须知道对方 MAC，ARP 广播解析几乎是每次上网的前奏——**可能用到**。
- **C UDP**：域名解析 DNS 查询通常就封装在 UDP 报文里（53 端口）——**可能用到**。
- **D SMTP**：SMTP 是**发送电子邮件**用的协议（"推"邮件），浏览网页既不发邮件也不收邮件，整条链路里没有它的位置——**不可能用到**，选 **D**。

### 易错点

- **以为 UDP 不沾边**：看到"浏览网页用 HTTP/TCP"就以为 UDP 用不上，漏了 DNS 查询默认走 UDP——错选 C 是本题最大陷阱。
- **忽略接入网**：PPP 不在"应用层清单"里，容易被忽略；题目问的是"可能"，只要存在一种接入场景就成立。

> 记忆锚点：上网浏览一条链——PPP 接入、ARP 找门、DNS(UDP) 查名、TCP/HTTP 取页；SMTP 是寄信的，与浏览无关。
