## 本题讲解：递归调用时栈内保存信息的排列次序

**答案：A**（自栈底到栈顶：main() → S(1) → S(0)）。

### 第零步：先立模型——调用即压栈，返回即弹栈

程序运行时，每次函数调用都要保存"回来的路"和"现场的账"：返回地址、参数、局部变量等被打包成一个**活动记录**，在调用发生的那一刻**压入调用栈**；函数执行完毕返回时，它的活动记录**弹出**，控制流回到调用者。于是栈里自底向上恰好就是调用发生的先后次序。

**为什么调用信息必须用栈存？** 因为返回次序与调用次序严格相反：最后被调用的函数一定最先返回（S(0) 先于 S(1) 返回，S(1) 先于 main 结束）。这种"后进先出"的依赖关系天然对应栈结构——若用队列（先进先出）保存，返回时就找不到正确的去处了。

### 第一步：理清调用链

程序从 `main()` 开始执行：`main()` 调用 `S(1)`；`S(1)` 中 n=1>0，要计算 `S(0)+1`，又调用 `S(0)`；`S(0)` 满足 n≤0 直接返回 0。调用链为 `main() → S(1) → S(0)`。

### 第二步：按"压栈次序"还原栈内容

| 时刻 | 动作 | 栈内（自底向上） |
|---|---|---|
| 1 | main() 开始执行 | main() |
| 2 | main 调用 S(1)，压入 S(1) 的活动记录 | main() → S(1) |
| 3 | S(1) 调用 S(0)（递归最深时刻） | main() → S(1) → S(0) |
| 4 | S(0) 返回 0 弹栈，S(1) 算出 1 弹栈 | main() |
| 5 | main 输出 1，结束弹栈 | （空） |

递归到达最深、S(0) 尚未返回的那一刻，栈自底向顶依次是 **main() → S(1) → S(0)**：main 最先调用所以压在栈底，S(0) 最后调用所以停在栈顶。

### 易错点

- **把栈顶当成栈底**（对应 B/D）：后调用的压在**栈顶**而不是栈底，栈顶永远是"当前正在执行"的函数。
- **漏掉或颠倒调用层**（对应 C 的 main→S(0)→S(1)）：S(1) 先于 S(0) 被调用，压栈次序不可颠倒。
- **误以为返回后栈里还留着记录**：返回即弹栈，第 4 步之后栈里只剩 main()。

> 记忆锚点：调用 = 压入活动记录，返回 = 弹出；栈自底向顶 = 调用先后次序；返回次序 = 调用次序的逆序，所以必须用栈。
