## 本题讲解：用快速排序划分思想实现集合划分

### 第（1）问：算法基本设计思想

**答题框架：先定个数，再定成员，最后选手段。**

- **|n1−n2| 最小** → 两部分个数尽量对半：取 n1 = ⌊n/2⌋（记 k = n/2 向下取整），其余归 A2。
- **|S1−S2| 最大** → 个数已定，只能靠"挑人"拉开差距。用交换论证看：若 A1 中有元素 a 大于 A2 中的元素 b（"倒挂"），把 a、b 对调，S1 增大 (a−b)、S2 减小 (a−b)，S2 − S1 恰好增大 2(a−b)。所以和的差最大 ⇔ 不存在倒挂 ⇔ **A1 装走最小的 k 个元素、A2 装其余**，此时 S2 − S1 达到最大。
- **手段**：完整排序给的是"全序"信息，而本题只需要"前 k 小与其余分开"这半份信息，花 O(nlogn) 不值得。借用**快速排序的一次划分**：枢轴归位后其左侧全部 ≤ 枢轴、右侧全部 ≥ 枢轴。若枢轴恰好落在下标 k−1，则 a[0..k−1] 就是全数组最小的 k 个数；落在 k−1 左侧就到右段继续划分，落在右侧就到左段继续划分（非递归，只收缩区间），直到枢轴命中 k−1。最后分别累加两部分，返回 s2 − s1。

### 第（2）问：算法描述（C 语言，与参考答案一致）

1. 初始化：`low = 0, high = n-1, low0 = 0, high0 = n-1, k = n/2, flag = 1, s1 = 0, s2 = 0`。
2. 每轮取枢轴 `pivokey = a[low]`，双端交替扫描（挖坑填坑）：high 端向左找小于枢轴的元素填入 low 侧的坑，low 端向右找大于枢轴的元素填入 high 侧的坑，直到 `low == high`，执行 `a[low] = pivokey` 归位。归位后枢轴左边都不大于它、右边都不小于它——这正是"前 k 小已被切出"的依据。
3. 判断枢轴位置：若 `low == k-1`，置 `flag = 0` 结束；若 `low < k-1`，执行 `low0 = ++low; high = high0;` 转去右段；否则执行 `high0 = --high; low = low0;` 转去左段，重复第 2 步。（low0/high0 记住整个待划分区间的两端，区间收缩后靠它们复位。）
4. 结束后累加：`for(i=0; i<k; i++) s1 += a[i];`、`for(i=k; i<n; i++) s2 += a[i];`，返回 `s2 - s1`（A1 是小的一半，差值非负）。

举例：a = [4,1,9,3,7,8,2,6]，n=8、k=4。第一轮以枢轴 4 划分后数组变为 [2,1,3,4,7,8,9,6]，枢轴恰落在下标 3 = k−1，直接收工：s1 = 2+1+3+4 = 10，s2 = 7+8+9+6 = 30，返回 20。

### 第（3）问：时间复杂度与空间复杂度

- **平均时间复杂度 O(n)**：每轮划分只扫当前区间、代价 O(区间长度)；期望情形下枢轴把区间按比例切小，总扫描量约为 n + n/2 + n/4 + … ≤ 2n，故期望线性。与快排不同的是这里**不递归展开**——只沿着"目标下标所在的那一半"走下去，这正是 O(n) 而非 O(nlogn) 的原因。
- **空间复杂度 O(1)**：非递归实现，只用 low、high、low0、high0 等常数个辅助变量，不压栈。

### 易错点

- **先完整排序再划**：O(nlogn) 达不到"尽可能高效"的要求，本题只需"划分到位"，不必全序。
- **以为一次划分必然成功**：枢轴未必一次落到 k−1，必须按 low 与 k−1 的大小关系收缩区间、反复划分。
- **只答"放最小 k 个"不答为什么**：第（1）问要给依据——倒挂必可对调增大差值（交换论证），否则丢分。
- **返回值写反**：A1 是小的一半，应返回 `s2 - s1`（非负）；写成 s1 − s2 会得负数。

> 一句话总结：这是快排划分的"半程版"——枢轴归位到 n/2 − 1 就收工，前 k 个元素正是最小的一半。
