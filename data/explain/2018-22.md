## 本题讲解：外部 I/O 中断的四个说法

**答案：C**。

### 第一步：回忆中断响应的全流程

外设发请求 → 中断控制器按**优先级**排队 → CPU 在**一条指令执行结束时**查询请求 → 若 CPU 处于**开中断**（中断允许）状态且请求未被屏蔽 → 执行**中断隐指令**（关中断、保存断点 PC 和 PSW、取中断向量）→ 转入中断服务程序，由服务程序保护通用寄存器等现场。

### 第二步：逐项核对

- **A 错**：排队依据是预先规定的中断**优先级**（硬件排队器实现），不是请求到达的先后次序。
- **B 错**：中断隐指令是硬件固定动作，只负责关中断、保存断点（PC）和程序状态字；**通用寄存器**的保存由中断服务程序（软件）完成。
- **C 对**：CPU 只有处于中断允许状态（开中断）才能响应外部设备（可屏蔽中断）的请求；关中断期间请求只能挂起。
- **D 错**：CPU 不能"立即"暂停当前指令，必须等**一条指令执行完毕**（执行周期结束）才检查并响应中断。

### 易错点

- **以为隐指令包办全部现场保护**：隐指令只保存断点；通用寄存器属于"现场"，由服务程序按需压栈保存。
- **把优先级排队想成"先来先服务"**：排队只看优先级，与到达时间无关。
- **认为响应可以在指令中途**：指令执行到一半就转走会破坏执行的完整性，响应点固定在指令边界。

> 主线口诀：一条指令执行完 → 开中断 → 按优先级 → 隐指令保断点 → 服务程序保现场。
