## 本题讲解：页式虚存 → TLB → Cache 的地址翻译全程

先从题 44 图读出三个关键结构：虚拟地址 = 虚页号 20 位 + 页内地址 12 位；Cache 地址 = Tag 20 位 + 组号 3 位 + 块内地址 5 位；TLB 的每个表项都配一个比较器，拿虚页号与所有表项并行比较。

### 第（1）问：主存物理地址的位数

物理地址就是 Cache 地址：Tag 20 位 + 组号 3 位 + 块内 5 位 = **28 位**。（等价说法：实页号 16 位 + 页内地址 12 位 = 28 位。）

### 第（2）问：TLB 的映射方式与器件

- 图中每个 TLB 表项各带一个比较器，虚页号与全部表项同时比较，没有"按索引定位"的字段 → **全相联映射**。
- TLB 必须尽快给出实页号、速度要求最高 → 用 **SRAM** 实现。

### 第（3）问：Cache 的映射方式、附加位与容量

- 组号 3 位，图中每组画出左右两个表项 → **2 路组相联映射**。
- 采用 LRU 替换：每组 2 行需要 1 位 **LRU 位**记录该淘汰哪一行；采用回写策略：需要 1 位**修改位（脏位）**标记该行是否被改过、换出时要不要写回主存。
- 容量：8 组 × 2 路 = 16 行；每行 = 数据 32B（256 位）+ Tag 20 位 + 有效位 1 位 + LRU 位 1 位 + 脏位 1 位 = 279 位。总容量 = 16 × 279 = **4464 位 = 558 字节**。
- **有效位**的作用：指示该 Cache 行中的数据是否有效（上电初始或行被作废时为 0，此时即使 Tag 匹配也不能使用）。

### 第（4）问：两个具体地址

**虚拟地址 `0008C040H`：**

| 步骤 | 结果 |
|---|---|
| 拆分 | 虚页号 = `0008CH`，页内地址 = `040H` |
| 查 TLB | 表项 `0008CH` 有效位 = 1，命中，实页号 = `0040H` |
| 拼物理地址 | `0040H` 拼 `040H` = `0040040H` |
| 查 Cache | Tag = `00400H`，组号 = 2，块内偏移 = 0 |
| 判断 | 组 2 左路 Tag 恰为 `00400H`，但**有效位 = 0** → 不命中 |

**虚拟地址 `0007C260H` 所在主存块的 Cache 组号：**

组号由物理地址第 7～5 位决定，这 3 位完全落在**页内地址**（低 12 位）里——虚存变换只改变高位（虚页号换成实页号），页内地址原样照搬。页内地址 = `C260H` = 0010 0110 0000B，其第 7～5 位 = 011 = **3**，所以映射到 Cache 组号 3（无需知道实页号即可作答）。

### 易错点

- **把物理地址当成 32 位**：物理地址 = 实页号 16 位 + 页内 12 位 = 28 位，与虚拟地址 32 位无关。
- **以为算组号必须先查到实页号**：组号 3 位全在页内地址里，虚/实相同，直接算。
- **Tag 匹配就判命中**：必须有效位为 1 才算命中，本题组 2 正是"Tag 对但有效位 0"的陷阱。
- **容量漏算附加位**：LRU 位、脏位每行各 1 位，16 行共 32 位，漏掉会算成 4432 位。

> 主线：虚页号查 TLB 得实页号 → 拼 28 位物理地址 → 按"Tag 20 | 组 3 | 块内 5"查 Cache，Tag 匹配且有效位为 1 才算命中。
