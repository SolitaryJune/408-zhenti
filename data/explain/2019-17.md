## 本题讲解：一条指令的取数与执行需要哪些部件

答案：**B（I、II、III）**。

### 第 0 步：先建立模型——一条指令的一生分五个阶段

部件题不能上来就背，先把大背景立起来：一条指令从主存里被取出，到结果落定，按顺序经过**五个阶段**。每个阶段，"当班"的部件不同：

| 阶段 | 在干什么 | 谁在上班 |
|---|---|---|
| IF 取指 | 去主存把这条指令的二进制代码取出来 | 存储器（取的是**指令**） |
| ID 译码 | **指令译码器**把代码翻译成控制信号（"这是个加法，操作数在 r1、以及 r0 所指的内存里"），信号一发出，它对这条指令的任务就结束了 | 指令译码器 |
| OF 取数 | 按翻译结果把两个源操作数取出来 | 通用寄存器组、存储器（取的是**数据**） |
| EX 执行 | 对取出来的数据做运算 | ALU |
| WB 写回 | 结果写回目的寄存器 | 通用寄存器组 |

题目问的是"**取数及执行**"过程 = **OF + EX 两个阶段**。这个范围一划出来，答案自然浮出。

### 第 1 步：把这条指令翻译成"数据怎么流"

R[r2] ← R[r1] + M[R[r0]]：

- 第一个源操作数在 r1 里 → **寄存器寻址**：OF 阶段从通用寄存器组直接读出；
- 第二个源操作数在主存里、其地址放在 r0 中 → **寄存器间接寻址**：OF 阶段先从寄存器组读出地址，再去**存储器**把数据取出来（口诀：寄存器出地址、存储器出数据）；
- 加法在 EX 阶段由 **ALU** 完成；结果在 WB 写回 r2。

### 第 2 步：I~IV 对号入座

| 部件 | 是否需要 | 上班阶段与理由 |
|---|---|---|
| I 通用寄存器组（GPRs） | ✅ | OF 从中读 r0、r1；WB 把结果写入 r2 |
| II 算术逻辑单元（ALU） | ✅ | EX 完成加法 |
| III 存储器 | ✅ | OF 按 M[R[r0]] 访存取**数据** |
| IV 指令译码器 | ❌ | 只在 **ID 阶段**上班；"取数及执行"时它早退场了 |

→ 需要 I、II、III，选 **B**。

### 为什么译码器不算（唯一排除点，值得多说一句）

译码器的任务发生在 **ID 阶段**：把取指阶段拿到的二进制代码翻译成具体的控制信号（解析出"这是加法、操作数在哪"）。一旦翻译完成并发出信号，译码器针对**这条指令**的工作就彻底结束了。

OF/EX 阶段真正干活的是寄存器组、存储器和 ALU。（流水线 CPU 里译码器此刻可能忙着给**下一条**指令译码——但那是下一条指令的事，与本题问的这条指令的"取数及执行"无关。）

### 易错点

- **把 ID 算进来** → 误选 D：题限"取数及执行"，译码器不在其列——这是本题唯一排除点。
- **漏掉存储器** → 误选 A：寄存器间接寻址的操作数在主存，"寄存器给地址、存储器出数据"，不访存拿不到。
- **把取指阶段的访存算作 III 的理由** → 不对：IF 取的是指令，"取数"取的是操作数；本题 III 成立的理由是 OF 阶段取**数据**要访存。

> 记忆锚点：指令一生 = **IF → ID → OF → EX → WB**；部件题先划阶段，再让部件"对号入座"；寄存器间接 = 寄存器出地址 + 存储器出数据；译码器只在 ID 上班。
