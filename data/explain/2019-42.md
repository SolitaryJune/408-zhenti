## 本题讲解：设计"空间只增不减"的 O(1) 队列

### 答题框架

先审四个需求：初始为空、入队可扩容、出队结点可复用（空间只增不减）、入队出队均 O(1)。顺序存储的循环队列在"满"时扩容要整队搬移，普通顺序队列出队后前部空间无法复用，都不是 O(1)；**链式存储（单向循环链表）**天然满足：扩容 = 挂一个新结点，复用 = 结点永远留在环里。

### 第 1）问：选什么存储结构

选择**链式存储结构**：用单向循环链表保存队列，设置队头指针 `front` 和队尾指针 `rear`。元素从 front 沿环延伸到 rear 的前驱。

### 第 2）问：初始状态与队空、队满条件

初始时只建立**一个空闲结点**，`front` 和 `rear` 都指向它。判定条件：

- 队空：`front == rear`
- 队满：`front == rear->next`（rear 的下一个绕回 front，说明环上已无多余空闲结点）

### 第 3）问：第一个元素入队后的状态

按入队流程：先判满——初始结点的 `rear->next` 是自身，`front == rear->next` 成立 → 在 rear 后**插入一个新空闲结点**；再把元素写入 rear 所指结点；最后 `rear = rear->next`。结果：原结点保存第一个元素，front 指向它，rear 指向新挂上的空闲结点。

### 第 4）问：入队 / 出队的基本过程

- 入队 EnQueue(e)：若 `front == rear->next`（队满）则在 rear 后插入一个新的空闲结点；然后 `rear->data = e; rear = rear->next;`。
- 出队 DeQueue(e)：若 `front == rear`（队空）返回 ERROR；否则 `e = front->data; front = front->next;`。出队结点不释放，仍留在环中供以后复用——队占用空间只增不减。
- 两操作都只做常数次指针修改与判断，时间复杂度始终 **O(1)**。

### 易错点

- **选顺序存储**：循环队列扩容要整队搬移、普通队列出队后空间复用不了，都与需求冲突。
- **队满条件写成 front == rear**：那是队空；"环上没有空闲结点"的标志是 `rear->next` 绕回 `front`。
- **入队不先判满就写数据**：会把新元素写进已存元素的结点，破坏队列；必须先判满扩容、再写入、再后移。
- **出队把结点 free 掉**：一旦释放就违背"空间只增不减、可复用"的要求。

> 一句话：环形链上排队——front 向前挤，rear 挂新环，进出皆 O(1)。
