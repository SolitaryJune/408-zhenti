## 本题讲解：递归函数 f1 的机器级代码（五问全解）

答题框架：先从源程序结构推调用次数（问 1），再按"是否看标志位"给转移指令分类（问 2），然后用"下一条指令地址 + 偏移量 = 目标地址"算相对偏移并借机器码判大小端（问 3），最后处理 int 溢出（问 4）与 OF 标志（问 5）。

### 第（1）问：调用次数与递归调用指令

f1(n) 只有 n>1 时才执行 `return n*f1(n-1)`。计算 f(10) 的调用链为 f1(10)→f1(9)→…→f1(1)，n 取 10, 9, …, 1，共调用 **10 次**（n=1 走 else return 1，不再递归）。每次递归调用自身都由**第 16 行 call 指令**完成。

### 第（2）问：条件转移与必跳转指令

- 条件转移指令：**第 12 行 jle**——要根据比较 n 与 1 的标志位决定是否跳转。
- 一定跳转的指令：**第 16 行 call**（函数调用必转移）、**第 20 行 jmp**（无条件转移）、**第 30 行 ret**（函数返回必转移）。

### 第（3）问：返回地址、偏移量与大小端

1. 第 16 行 call 位于虚拟地址 00401025H，机器码 `E8 D6 FF FF FF` 长 5 字节（操作码 E8 + 4 字节偏移量），故下一条指令（第 17 行）虚拟地址 = 00401025H + 5 = **0040102AH**。
2. 相对寻址：转移目标地址 = 下一条指令地址 + 偏移量，所以偏移量 = 00401000H − 0040102AH = **FFFF FFD6H**（即 −2AH 的 32 位补码：2^32 − 2AH）。
3. 机器码中偏移量按 `D6 FF FF FF` 顺序存放——最低有效字节在最低地址，故 M 采用**小端方式**。

### 第（4）问：为什么返回 1932053504

int 为 32 位补码，表示范围 [−2^31, 2^31−1]，上限 2147483647；而 f(13) = 6227020800 > 2^31−1，**发生溢出**。机器保留 64 位乘积的低 32 位（等价于模 2^32）：6227020800 − 4294967296 = 1932053504，恰为题给返回值。修改：把 f1 的**形参、局部变量和返回值都改为 double**（或足够宽的整数类型，如 64 位整数）。

### 第（5）问：OF=1 的条件与自陷指令

imul 内部产生 64 位乘积 = 高 32 位 : 低 32 位。当**高 32 位不是低 32 位的符号扩展**（乘积超出 32 位补码可表示范围）时 OF=1。要使 CPU 在溢出时转异常处理，编译器应在 imul 后加一条**溢出自陷指令**，它检测到 OF=1 即触发自陷，转入溢出异常处理程序。

> 大题套路：相对寻址偏移 = 目标地址 − 下一条指令地址；溢出值 = 真值 mod 2^32 再按补码解释；小端 = 最低有效字节在最低地址。
