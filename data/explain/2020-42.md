## 本题讲解：前缀编码住二叉树——保存、译码、判定是同一棵树

### 第一步（问 1）：机制——编码是"一条"从根到叶的路径

**用二叉树保存。** 二进制编码和二叉树是天生一对：从根出发，**0 走左分支、1 走右分支**，编码的每一位决定一步走向，一个编码就对应**从根到某个结点的一条路径**；把字符存在这条路径的终点——**叶结点**上，叶内可再存该字符的编码等信息。

**为什么字符只能放叶子上？** 在树上，"编码 C 是编码 D 的前缀"翻译成结构语言就是：C 的路径终点站在 D 的路径**中间**。反过来说，只要字符全部住在叶子上——叶子下面没有分支，谁也不可能"路过"它继续往下走——任何编码都不可能是别的编码的开头，**前缀特性由这个结构自动保证**。若把字符放进中间结点，它的编码立刻成为其子树内所有编码的前缀，特性被直接破坏。所以"前缀特性"不是额外检查出来的，而是"字符在叶"这一存放规则的必然结果。

### 第二步（问 2）：译码 = 拿着 0/1 串在树上走

1. 从**根结点**出发，读 0/1 串的当前位：该位为 0 走左孩子、为 1 走右孩子；
2. 到达**叶结点** → 输出叶上的字符，然后**回到根**；
3. 从下一位继续，如此反复，直到 0/1 串读完，译码结束。

**为什么译码结果唯一？** 前缀特性保证"第一次踩到叶子"的时刻是唯一确定的：叶子没有孩子，不可能走过头；又因为没有编码是其他编码的前缀，不存在"更早一步就该停"的歧义。于是整个 0/1 串被唯一地切成若干段、每段对应唯一字符。**为什么每译出一个字符必须回根？** 下一个字符的路径永远从根开始数起；不回根，后面所有比特与字符的对应关系就整体错位了。

### 第三步（问 3）：判定前缀特性 = 边建树边查违规

判定过程就是**把每个编码依次插入一棵初始只有根结点（左右指针为空）的树**：按位沿分支下行，遇到空指针就新建结点。违规只有两种形态，机理各不相同：

1. **尚未扫完 C 就到达已有叶结点** → 从根到这个叶的路径是某个已有编码的全部，而它只是 C 的一段 → **已有编码是 C 的前缀**，不具有前缀特性。
2. **扫完 C 却一个新结点都没创建** → C 的整条路径早已存在，终点无非两种：是某个已有**叶**——C 与已有编码完全相同，相同即互为前缀；是某个**中间结点**——已有更长的编码从它下面延伸出去，**C 是那个编码的前缀**。两种都不具有前缀特性。
3. **恰在 C 的最后一位新建出叶结点** → C 的路径是新开的：既不压在任何已有路径上，也不被已有路径包含 → 与所有已有编码互不为前缀，通过，继续检查下一个编码。

| 检查点 | 现象背后的机理 | 结论 |
|---|---|---|
| 中途撞上已有叶 | 已有编码是 C 的前缀 | 不具有前缀特性 |
| 扫完 C 无新结点 | C 是已有编码的前缀（或与其相同） | 不具有前缀特性 |
| 最后一位新建叶 | C 与所有已有编码互不为前缀 | 通过 |

所有编码都通过上述检查，该字符集的编码即具有前缀特性。

### 易错点

- **把字符放进中间结点**：中间结点的编码必是其子树内所有编码的前缀，直接破坏特性——字符只能放叶上。
- **译码忘记回根**：每译出一个字符必须回到根，否则后续比特整体错位。
- **判定漏掉第二种违规**："C 是别人的前缀"（扫完一个新结点都没建）与"别人是 C 的前缀"（中途撞叶）同样是违规。
- **建完树再回头查**：两种违规都能在**逐个插入的过程中**当场发现，边建边查才是标准流程。

> 记忆锚点：编码在叶、译码从根走、判定边建树边查"撞叶"与"空转"。
