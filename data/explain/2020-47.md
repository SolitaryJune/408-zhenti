## 本题讲解：私网 Web 服务器的静态 NAT 配置与逐跳地址变换

### 第 1 问：让 H2、H3 能访问 Web 服务器——先想清楚"卡"在哪

**答题框架**：两个局域网都用私网段 `192.168.1.0/24`（Web 服务器和 H2 的地址甚至同为 192.168.1.2），而公网互连链路用的是 `203.10.2.x`。私网地址不能在公网侧被路由，所以外网方向找不到"192.168.1.2 的 Web 服务器"——必须由 R2 把自己的公网地址 + 端口静态映射给服务器。Web 服务器走 HTTP，**默认端口号为 80**。

**答案：在 R2 上配置静态 NAT 端口映射**：

| 外网 IP 地址 | 外网端口号 | 内网 IP 地址 | 内网端口号 |
|---|---|---|---|
| `203.10.2.2` | 80 | `192.168.1.2` | 80 |

即：外网发往 `203.10.2.2:80` 的数据报，由 R2 转换成发往 `192.168.1.2:80`。同时 H2/H3 的出网流量由 R3 做 NAPT（源地址换成 R3 的公网地址 203.10.2.6），这是第 2 问"经过 R3 转发后源 IP 变为 203.10.2.6"的依据。

### 第 2 问：数据报 P 在三处的源/目的地址

**答题框架**：源地址看"谁改写了源"（出口 NAT 路由器 R3），目的地址看"谁改写了目的"（服务器侧 NAT 路由器 R2），两处互不干扰。

| 位置 | 源 IP 地址 | 目的 IP 地址 |
|---|---|---|
| H2 发送时 | `192.168.1.2` | `203.10.2.2` |
| 经过 R3 转发后 | `203.10.2.6` | `203.10.2.2` |
| 经过 R2 转发后 | `203.10.2.6` | `192.168.1.2` |

- **H2 发送时**：源填 H2 自己的私网地址 `192.168.1.2`；目的**不能**填 192.168.1.2（Web 服务器的私网地址，公网不认）——目的填 Web 服务器对外呈现的公网地址 `203.10.2.2`。
- **经过 R3 转发后**：R3 是 H2 所在私网的出口，做**源地址转换**：源 192.168.1.2 → `203.10.2.6`（R3 的公网接口地址），目的不变。
- **经过 R2 转发后**：R2 收到目的为 203.10.2.2 的数据报，查静态 NAT 表做**目的地址转换**：目的 203.10.2.2 → `192.168.1.2`，源保持 203.10.2.6 不变。数据报进入左侧局域网，送达 Web 服务器。

### 易错点

- **H2 发送时目的写成 192.168.1.2**：H2 自己就占着 192.168.1.2 这个号，且私网地址不经 NAT 无法跨公网寻址；必须写映射后的公网地址 203.10.2.2。
- **R3 转发后源仍是 192.168.1.2**：私网源地址必须在出口被替换成公网地址，否则回程数据报无法路由回来。
- **R2 转发后又去改写源地址**：R2 只做目的 NAT（按静态表把 203.10.2.2 换成 192.168.1.2），源 203.10.2.6 全程不变。

> 一句话结论：一进一出各归各的 NAT——**R3 出口改源**（192.168.1.2 → 203.10.2.6），**R2 入口改目的**（203.10.2.2 → 192.168.1.2）；让外网能"进"的前提是 R2 上的静态映射 `203.10.2.2:80 ⇄ 192.168.1.2:80`。
