## 本题讲解：判断无向图是否存在 EL 路径（欧拉路径）

### 答题框架

三问分别是：设计思想、C 语言实现、复杂度分析。核心考点是**欧拉路径的度数判定**：无向连通图中，度为奇数的顶点个数为 0 或 2 时，存在包含所有边且长度为 |E| 的路径（EL 路径）。

### 第 1）问：基本设计思想

逐个顶点统计度数：无向图邻接矩阵中，顶点 i 的度 = 邻接矩阵第 i 行元素之和（图无自环）。用计数器 count 统计**度为奇数的顶点个数**：count 为 0 或 2 → 存在 EL 路径，返回 1；否则返回 0。

### 第 2）问：算法实现（与参考答案同口径）

`int IsExistEL(MGraph G)` 的骨架：

- 外层 `for (i = 0; i < G.numVertices; i++)`：内层先把 `degree` 清零，再 `for (j = 0; j < G.numVertices; j++) degree += G.Edge[i][j];`
- `if (degree % 2 != 0) count++;` —— 奇度顶点计数。
- 循环结束后 `if (count == 0 || count == 2) return 1; else return 0;`

关键注释点：degree 初始化清零、奇度判断、`count==0 || count==2` 的最终判定。

### 第 3）问：复杂度

双重循环遍历整个邻接矩阵：时间复杂度 **O(n²)**，n 为顶点数 numVertices；只用了 degree、count 等常数个辅助变量，空间复杂度 **O(1)**。

### 易错点

- **漏掉"0 也算存在"**：奇度顶点为 0 时存在欧拉回路，同样是 EL 路径，条件必须写成 `count==0 || count==2`。
- **度数统计不完整**：无向图邻接矩阵对称，整行求和即可；只加一半会数错。
- **复杂度写成 O(n+e)**：那是邻接表的口径；邻接矩阵必须扫全表，是 O(n²)。
- **忘记初始化**：degree 每行开始前必须清零，否则累加到上一个顶点的度上。

> 一句话：数奇度顶点，0 或 2 个就有 EL 路径；矩阵逐行求度，O(n²) 时间、O(1) 空间。
