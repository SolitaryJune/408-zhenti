## 本题讲解：银行家算法安全序列的个数

### 第一步：先给结论

答案：**B**，安全序列有 **2 个**：P0→P1→P2 与 P0→P2→P1。

### 第二步：用 Available 逐一检查 Need

可用资源 Available = (1, 3, 2)。

**为什么判据是 Need ≤ Available？** 安全序列的定义是"按这个顺序执行，每个进程都能拿到它**尚需的全部资源**并顺利跑完"。银行家算法取最保守的假设——进程可能把它声明过的尚需量一次性全部要走；所以只有当 Available 现在就能满足某进程的全部尚需量（Need 三个分量都 ≤ Available）时，才敢保证它能完成并归还资源，序列才"安全"。

| 进程 | Need(A,B,C) | 对 (1,3,2) 判定 | 结论 |
|---|---|---|---|
| P0 | (0,2,1) | 0≤1，2≤3，1≤2 | 满足 |
| P1 | (1,2,3) | C 分量 3 大于 2 | 不满足 |
| P2 | (0,1,3) | C 分量 3 大于 2 | 不满足 |

此时能立即运行的**只有 P0**，安全序列的第 1 位只能是 P0。

### 第三步：P0 完成后释放资源，再查一遍

**为什么归还 (2,0,1)？** P0 跑完意味着它不再持有任何资源，已分配的全部释放回系统。P0 运行结束归还全部已分配资源 (2,0,1)：Available = (1,3,2) + (2,0,1) = **(3,3,3)**。再检查：

- P1：Need (1,2,3) ≤ (3,3,3) → 满足；
- P2：Need (0,1,3) ≤ (3,3,3) → 满足。

两者都能满足，后两位可以是 P1→P2，也可以是 P2→P1，各构成一个安全序列，共 2 个。

### 易错点

- **看错列**：判定用的是「尚需资源数」，不是「已分配资源数」。
- **以为 P1、P2 起初就能入选**：C 类资源只剩 2 个，P1、P2 各尚需 3 个，必须等 P0 释放。
- **只数出一个序列**：两个进程都能满足时，两种先后顺序都安全，共 2 个而不是 1 个。

> 安全性检查：每轮找 Need ≤ Available 的进程运行并归还全部资源，能排空所有进程即安全。
