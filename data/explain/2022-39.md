## 本题讲解：四次挥手中 C、S 进入 CLOSED 的最短时间

**答案：D（C 1650 ms，S 75 ms）**

### 第一步：明确"最短"口径

求「至少」多久：CLOSE_WAIT 期间不再传数据、FIN_WAIT-2 不停留——S 收到 C 的 FIN 后**立即**把 ACK 和自己的 FIN 一并回过去，四次挥手压缩成"三段报文"。设 t = 0 为 C 发出 FIN 的时刻，RTT = 50 ms，MSL = 800 ms。

### 第二步：C 的时间线（主动关闭方）

| 时刻 | 事件 | C 的状态 |
|---|---|---|
| 0 ms | C 发出 FIN | FIN_WAIT-1 |
| 25 ms（半个 RTT） | S 收到 FIN，立即回 ACK + FIN | （仍在 FIN_WAIT-1） |
| 50 ms（1 个 RTT） | C 收到 ACK + FIN，回最后一个 ACK | 进入 TIME_WAIT，启动 2MSL 定时器 |
| 50 + 2×800 = **1650 ms** | 定时器到期 | **CLOSED** |

C 耗时 = 1 RTT + 2 MSL = 50 + 1600 = **1650 ms**。

### 第三步：S 的时间线（被动关闭方）

| 时刻 | 事件 |
|---|---|
| 25 ms | 收到 C 的 FIN，发 ACK + FIN，进入 LAST_ACK |
| 75 ms（0.5 RTT + 1 RTT） | 收到 C 最后的 ACK → **CLOSED** |

S 耗时 = 0.5 RTT + 1 RTT = 1.5 RTT = **75 ms**。

### 易错点

- **选 A/C（C 850 ms）**：把 TIME_WAIT 算成 1 个 MSL。TIME_WAIT 必须等 **2×MSL** = 1600 ms。
- **选 B（S 50 ms）**：S 要收到 C 对"自己那条 FIN 的确认"才能关闭，最后那个 ACK 从 C 出发再走半个 RTT（25 ms），所以是 75 ms。
- **忽略主动方的 2MSL 等待**：C 主动关闭，必须停在 TIME_WAIT 计满 2MSL 才进 CLOSED——这正是 C（1650 ms）远大于 S（75 ms）的原因。

> 口诀：主动方 = 1 RTT + 2MSL；被动方 ≈ 1.5 RTT。
