## 本题讲解：双向链表插入的指针操作次序

答案：**C**。已执行 `s->next = p->next; p->next = s;` 后，链上还欠两笔"账"：**s->prev 指向 p**、**后继结点 q 的 prev 改指 s**。选项 C 的两句恰好完成这两件事，且"读旧值"赶在"覆盖旧值"之前。

### 第一步：认清此刻的状态——正向已通、反向欠账

双向链表每个结点要同时维护前驱链（prev）与后继链（next）。设 p 原来的后继为 q。两句执行完：

- `s->next` 已指向 q，`p->next` 已改指 s —— 正向链 p → s → q 已接通；
- **s->prev 还没设置**——反向链缺一半；
- **q->prev 仍指向 p**——q 的前驱已经换成 s，这条 prev 是旧的，必须改写；
- 另一个隐蔽陷阱：**q 只能经 `s->next` 找到**——p->next 已被 s 占据。

所以只剩两笔账：`s->prev = p`、`q->prev = s`。四个选项就是四种还账方式——谁在读取旧值之前先覆盖了它，谁就出错。

### 第二步：逐项还账

| 选项 | 语句 | 执行后果 |
|---|---|---|
| A | `s->next->prev = p; s->prev = p;` | 第一句把 q->prev 写成 p——前驱应是 s，写错对象；s->prev = p 倒是对的 |
| B | `p->next->prev = s; s->prev = p;` | 两句都在写 s->prev：p->next 已是 s 自己，第一句执行成 s->prev = s（瞬态自环），第二句改正为 p——**q->prev 一次没被碰** |
| D | `p->next->prev = s->prev; s->next->prev = p;` | 第一句是 s->prev 自赋未知值，白做；第二句把 q->prev 写成 p——错对象，s->prev 也没设成 p |
| C | `s->prev = s->next->prev; s->next->prev = s;` | 第 1 句：s->next 是 q，q->prev 此刻仍是 p，恰好把旧值读给 s->prev ✓；第 2 句：q->prev = s ✓ |

B 最迷惑人：自环只是瞬态，随即被第二句覆盖，**它不是 B 出错的原因**；真正死因是 q->prev 漏改——反向遍历到 q 会直接跳过 s。

### 第三步：为什么 C 的次序不能颠倒

`s->prev = s->next->prev` 必须在 `s->next->prev = s` **之前**执行：一旦 q->prev 被改成 s，"p 的旧值"就再也取不到了。C 把「读旧值」放在前面、「覆盖旧值」放在后面，正好补全 p ⇄ s ⇄ q 的四条指针。

### 易错点

- **用 p->next 找后继**：执行过 `p->next = s` 后，p->next 已是 s 自己——B、D 都栽在第一句。
- **只顾 s->prev、漏改 q->prev**：只设 s->prev = p 会留下"假 prev 链"（q 仍指向前驱 p），这是 B 的真实死因。
- **次序颠倒**：先执行 q->prev = s，再想给 s->prev 赋 p 值就取不到了。

> 口诀：新结点先「认上亲」（从旧 q->prev 里取 p），后继再「认新邻」（q->prev = s）；读旧值要赶在覆盖之前。
