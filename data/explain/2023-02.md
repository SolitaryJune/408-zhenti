## 本题讲解：双向链表插入的指针操作次序

答案：**C**。已执行 `s->next = p->next; p->next = s;` 后，还差两件事：让 **s->prev 指向 p**、让**后继结点的 prev 指向 s**。选项 C 的两句恰好完成这两件事，且读取次序正确。

### 第一步：认清此刻的状态

设 p 原来的后继为 q。两句执行完：`s->next` 已指向 q；`p->next` 已改指 s。**关键陷阱：q 现在只能通过 s->next 找到，而 q->prev 仍指向 p，s->prev 还没设置。**

### 第二步：逐项排除

| 选项 | 语句 | 后果 |
|---|---|---|
| A | `s->next->prev = p; s->prev = p;` | 把 q->prev 写成 p，可 q 的前驱应是 s —— 错 |
| B | `p->next->prev = s; s->prev = p;` | 此时 p->next 就是 s 自己，第一句变成 s->prev = s 自环 —— 错 |
| D | `p->next->prev = s->prev; s->next->prev = p;` | s->prev 尚未设置，拿未知值赋给 q->prev，随后又写成 p —— 错 |
| C | `s->prev = s->next->prev; s->next->prev = s;` | 第 1 句：s->next 是 q，q->prev 此刻仍是 p，恰好就是 s 该认的前驱 ✓；第 2 句：q->prev = s ✓ |

### 第三步：为什么 C 的次序是对的

`s->prev = s->next->prev` 必须在 `s->next->prev = s` **之前**执行：一旦 q->prev 被改成 s，p 的旧值就再也取不到了。C 把「读旧值」放在前面，两句配合正好补全 `p ⇄ s ⇄ q` 的四条指针。

### 易错点

- **用 p->next 找后继**：执行过 `p->next = s` 后，p->next 已是 s 自己，B、D 都栽在第一句。
- **漏改 q->prev**：只设 s->prev = p，会留下一条「假 prev 链」（q 仍指向前驱 p）。
- **次序颠倒**：先执行 q->prev = s，再想给 s->prev 赋 p 值就取不到了。

> 口诀：先让新结点「认上亲」（s->prev 从旧 q->prev 取 p），再让后继「认新邻」（q->prev = s）。
