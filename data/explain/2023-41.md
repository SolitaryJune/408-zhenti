## 本题讲解：邻接矩阵求有向图的 K 顶点（出度 ＞ 入度）

答案要点：**K 顶点不需要任何图遍历算法——邻接矩阵已经把每个顶点的出度、入度"摊平"在行和列里，逐顶点对行、列各求一次和即可**，时间复杂度 O(n²)。

### 第 1 问：算法的基本设计思想——先看清矩阵里藏着什么

**机制：Edge[k][m] 的下标次序本身就是"方向"。** 邻接矩阵存的是边：`Edge[k][m]` 非零表示"存在一条从 k 指向 m 的边"。抓住这一点，度数就不再是需要"算"的东西，而是矩阵里现成的两类计数：

- 固定**行** k、让 m 扫一遍：枚举的是所有"从 k 出发"的边 → **第 k 行元素之和 = 顶点 k 的出度**；
- 固定 k 作**列**下标、让 m 扫一遍：枚举的是所有"指向 k"的边 → **第 k 列元素之和 = 顶点 k 的入度**。

**为什么"求和"就能数出边数？** 本题矩阵元素就是边的有无（非零即有边），每条出边对行和恰好贡献 1，每条入边对列和恰好贡献 1，所以行和、列和天然就是出度、入度，不需要再数"非零个数"。

于是设计思想一句话就能说清：**对每个顶点 k，把它所在的第 k 行、第 k 列各扫一遍求和，得到出度与入度；若出度 ＞ 入度，输出该顶点字符并计数；全部顶点处理完后返回计数值。**

**为什么不用 DFS/BFS？** 遍历算法回答的是"从某点能到哪些点"，而 K 顶点是一个**度数性质**——邻接矩阵把度数信息直接摊平成行和列，读出来就行；绕道遍历反而丢分。

**为什么是 O(n²)、空间 O(1)？** 每个顶点扫一行加一列共 2n 个元素，n 个顶点合计约 2n² 次；除几个计数变量外不占用任何辅助结构。

以题 41 图验证（第二层对号入座）：

| 顶点 | 出度（行和） | 入度（列和） | 出度＞入度？ |
|---|---|---|---|
| a | 2 | 0 | ✓ K 顶点 |
| b | 2 | 1 | ✓ K 顶点 |
| c | 1 | 1 | ✗ |
| d | 0 | 3 | ✗ |

与题面"顶点 a 和 b 为 K 顶点"吻合，算法口径正确。

### 第 2 问：算法实现（C 描述，与参考答案同一口径）

```
int printVertices(MGraph G){
    int indegree, outdegree, k, m, count = 0;
    for (k = 0; k < G.numVertices; k++) {   // 逐个顶点检查
        indegree = outdegree = 0;           // 每个顶点开始前先清零
        for (m = 0; m < G.numVertices; m++) // 第 k 行求和
            outdegree += G.Edge[k][m];      // 行方向累计 = 出度
        for (m = 0; m < G.numVertices; m++) // 第 k 列求和
            indegree += G.Edge[m][k];       // 列方向累计 = 入度（下标与上行相反）
        if (outdegree > indegree) {         // 出度大于入度才是 K 顶点
            printf("%c", G.VerticesList[k]);// 输出顶点字符
            count++;
        }
    }
    return count;                           // 返回 K 顶点个数
}
```

代码里三个容易追问的地方：

- **为什么 `indegree` 要在循环体开头清零？** 它记录的是"当前顶点"的入度，换顶点必须归零，否则把上一个顶点的计数累进来，比较必然出错；
- **为什么入度是 `Edge[m][k]` 而出度是 `Edge[k][m]`？** 这正是第 1 问的机制：第一个下标是"边的起点"，出度固定起点扫终点、入度固定终点扫起点，两者只是把 k 放在下标的不同位置；
- **为什么 `count` 在判断内部自增、最后返回？** 题目要求"输出所有 K 顶点**并返回个数**"，输出和计数必须绑定在同一判断里，`return` 放在双重循环之外。

### 易错点

- **行、列下标写反**：把入度写成 `Edge[k][m]`，等于把"指向 k"的边当成"从 k 出发"，K 顶点会判反——根子在于没记住"第一下标是边的起点"；
- **只求出度、漏了比较**：题目定义是"出度**大于**入度"，出度非零不等于 K 顶点，`if` 比较不可省；
- **忘记返回 count**：只 printf 不 return，白丢返回个数这半问的分；
- **绕道 DFS/BFS**：邻接矩阵下度数就是行列和，遍历是多余动作，还容易把复杂度写成 O(n²+e) 引起歧义。

> 一句话：`Edge[k][m]` 第一下标是起点 → 行和即出度、列和即入度，出度＞入度就输出计数，O(n²) 一趟完成。
