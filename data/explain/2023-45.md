## 本题讲解：用 swap 指令实现临界区互斥

约定：lock 是线程间共享的变量，**lock = TRUE 表示临界区被占用（不能进入），lock = FALSE 表示空闲（能进入）**。swap 是一条硬件原子指令：一步之内完成 key 与 lock 的互换。

### 第 1 问：找出错误语句并改正（不增加语句条数）

45(a) 图伪代码共有两处错误：

| 位置 | 学生写的（错误） | 应改为 |
|---|---|---|
| 进入区 | if (key == TRUE) swap key, lock; | while (key == TRUE) swap key, lock; |
| 退出区 | lock = TRUE; | lock = FALSE; |

**进入区为什么必须用 while**：key 初值为 TRUE。执行 swap key, lock 后，key 换入 lock 的旧值——若 lock = FALSE（空闲），key 变为 FALSE，可进入临界区；若 lock = TRUE（已被占用），key 仍为 TRUE。学生的 if 只交换一次就往下走：第二个线程会在 lock = TRUE 时照样闯入临界区，与持锁者同时访问共享资源，互斥失败。改成 while 后，线程反复执行 swap，直到把 FALSE 换进 key 才放行。

**退出区为什么是 lock = FALSE**：释放临界区要把「占用」状态清掉，即置 lock = FALSE，别的线程才能换到 FALSE 进入。写成 TRUE 等于永远宣告「我被占用」，其他线程将在 while 中无限等待。

### 第 2 问：能否用 newSwap(&key, &lock) 代替 swap 指令

**不能用 `newSwap(&key, &lock)` 代替 `swap key, lock`**。swap 是一条硬件指令，其内部的「读 lock、写 key、写 lock」等动作在一个指令周期内不可分割，天然**原子**。而 newSwap 是普通函数，函数体中的多条读写指令会逐条执行，**不具有原子性**：多线程并发执行时可能交叉进行。典型交错是——T2 执行到「key = lock（旧值 FALSE）」后被 T1 抢占；T1 完整执行完自己的 newSwap（lock 被写成 TRUE）；T2 恢复后写回 lock = temp。结果两个线程的 key 都变成了 FALSE，都「以为」自己拿到了锁，同时进入临界区，互斥被破坏。

### 易错点

- **把 if 与 while 混为一谈**：进入区必须「循环尝试」直到抢到 FALSE，一次判断不够。
- **记反 lock 的语义**：本题 TRUE = 占用、FALSE = 空闲，释放时置 FALSE，要按题面约定来。
- **以为函数调用也能原子**：原子性来自硬件单指令，不来自函数封装；这是 TSL/swap 类指令存在的意义。

> 进入区用 while 循环交换、退出区置 lock = FALSE；newSwap 是普通函数、多步读写不原子，不能替代硬件 swap 指令。
