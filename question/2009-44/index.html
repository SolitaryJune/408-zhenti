指令执行过程数据通路的功能和基本结构
essay 13 分

某计算机字长为 16 位，采用 16 位定长指令字结构，部分数据通路结构如下图所示，图中所有控制信号为 1 时表示有效、为 0 时表示无效。例如，控制信号 MDRinE 为 1 表示允许数据从 DB 打入 MDR，MDRin 为 1 表示允许数据从内总线打入 MDR。假设 MAR 的输出一直处于使能状态。加法指令 “ADD (R1)，R0”的功能为 (R0) + ((R1)) -> (R1)，即将 R0 中的数据与 R1 的内容所指主存单元的数据相加，并将结果送入 R1 的内容所指主存单元中保存。

下表给出了上述指令取指和译码阶段每个节拍（时钟周期）的功能和有效控制信号。

时钟功能有效控制信号
C1MAR←(PC)PCout, MARin
C2MDR←M(MAR)
PC←(PC)+1		MemR, MDRinE, PC+1
C3IR←(MDR)MDRout, IRin
C4指令译码无

请按表中描述方式，用表格列出该指令执行阶段每个节拍的功能和有效控制信号。

答案

【答案】

（1）指令执行阶段的基本方案（6个节拍）：

时钟节拍功能有效控制信号
C5MAR ← (R1)R1out, MARin
C6MDR ← M(MAR)MemR, MDRinE
C7A ← (MDR)MDRout, Ain
C8AC ← (A) + (R0)R0out, Add, ACin
C9MDR ← (AC)ACout, MDRin
C10M(MAR) ← (MDR)MDRoutE, MemW

（2）指令执行阶段的优化方案（5个节拍）：

时钟节拍功能有效控制信号
C5MAR ← (R1)R1out, MARin
C6MDR ← M(MAR), A ← (R0)MemR, MDRinE, R0out, Ain
C7AC ← (MDR) + (A)MDRout, Add, ACin
C8MDR ← (AC)ACout, MDRin
C9M(MAR) ← (MDR)MDRoutE, MemW

本题讲解：ADD (R1)，R0 执行阶段的节拍与控制信号

第 0 步：机制先行——单内总线数据通路的运行规则

先看清数据通路图的骨架：R0、R1、PC、IR、MAR、MDR、A、AC 都挂在一条内总线上；ALU 的一个输入端接暂存器 A，另一个输入端直接取自内总线，运算结果送 AC。访存走另一条外部通路：地址由 MAR 送出（题设 MAR 输出一直使能，地址可长期保持），数据经 DB 进出 MDR——所以 MDR 有两套门口：对内的 MDRin/MDRout，对外的 MDRinE/MDRoutE。

由「一条内总线」直接推出列节拍的三条铁律：

  1. 一拍一次总线传送：同一拍不能有两个部件同时往内总线送数，一个部件也不能「既被打入又被读走」。
  2. 访存前地址必须就位：读操作以 MAR 的当前内容为地址，MAR←(R1) 与 MDR←M(MAR) 有数据依赖，不能同拍。
  3. ALU 两端不能都等总线：两个源操作数必须有一个先锁进 A，另一拍另一个操作数才上总线进 ALU。

执行阶段的目标：(R0) + ((R1)) → (R1) 所指主存单元。取指与译码（C1~C4）已完成，剩下的活分三段：取内存操作数 → 相加 → 写回主存。逐拍问「这拍总线上走什么、谁被打入」，方案自然出来。

基本方案（6 拍）：一步一步走

节拍功能有效控制信号
C5MAR ← (R1)R1out, MARin
C6MDR ← M(MAR)MemR, MDRinE
C7A ← (MDR)MDRout, Ain
C8AC ← (A) + (R0)R0out, Add, ACin
C9MDR ← (AC)ACout, MDRin
C10M(MAR) ← (MDR)MDRoutE, MemW

逐拍为什么这样安排：

  • C5 → C6：先送地址再访存（铁律 2）。收数走外部通路，故用 MDRinE（从 DB 打入 MDR）配读命令 MemR。
  • C7：操作数已在 MDR，但若下一拍让 MDR 直接上内总线给 ALU，R0 就上不了总线（铁律 1）——所以先把 (MDR) 锁进 A 腾出总线（铁律 3）。
  • C8：三个信号同拍各司其职——R0out 把另一操作数经内总线送进 ALU，Add 命令 ALU 做加法，ACin 把结果打入 AC。
  • C9 → C10：结果先回 MDR（走内部通路 MDRin），再写主存。写内存必须用 MDR 的外部输出 MDRoutE（数据摆上 DB）加写命令 MemW——与 C7 用的 MDRout 不是同一个信号，这是本题最大的埋伏。
  • C10 为什么不必重送地址？ MAR 输出一直使能，(R1) 从 C5 起一直保持，写操作直接复用。

优化方案（5 拍）：C6 并行塞进第二件事

C6 的访存读走「存储器 ↔ DB」这条外部通路，而 R0 → A 走内总线，两条通路互不干扰，目标寄存器也不同（MDR 与 A），无数据依赖——满足相容性，可以同拍并行，省掉单独锁 A 的一拍：

节拍功能有效控制信号
C5MAR ← (R1)R1out, MARin
C6MDR ← M(MAR), A ← (R0)MemR, MDRinE, R0out, Ain
C7AC ← (MDR) + (A)MDRout, Add, ACin
C8MDR ← (AC)ACout, MDRin
C9M(MAR) ← (MDR)MDRoutE, MemW

为什么 C6 不能顺手把加法也做了？ 此刻 MDR 正从 DB 收数，同时又要 MDRout 读它给 ALU——「既打入又读出」违反铁律 1；加法只能等数据落定后的下一拍（C7），此时 A 里是 R0、MDR 里是内存操作数，MDRout 送数上总线即可。

易错点

  • 写回漏 MDRoutE / MemW：写主存必须用外部通路 MDRoutE + MemW；只给 MDRout 是往内总线送数，主存收不到。
  • C8 漏 Add：不给 Add，ALU 不知道本次做加法。
  • 合并依赖拍：把 MAR←(R1) 与 MDR←M(MAR) 并到一拍——读操作用的地址还没就位，违反铁律 2。
  • 乱并行：并行的前提是「不同通路、不同目标、无数据依赖」；C6 的合并恰因两条通路独立才成立，不是任意两件微操作都能塞进一拍。
一句话结论：基本方案 C5~C10 共 6 拍；利用「访存走外部通路、寄存器走内总线」的相容性把 A←(R0) 并入 C6，优化为 C5~C9 共 5 拍。
