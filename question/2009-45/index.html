2009-45

同步与互斥
综合应用题 7 分

（7分）三个进程 P1、P2、P3 互斥使用一个包含 N（N > 0）个单元的缓冲区。P1 每次用 produce() 生成一个正整数并用 put() 送入缓冲区某一空单元中；P2 每次用 getodd() 从该缓冲区中取出一个奇数并用 countodd() 统计奇数个数；P3 每次用 geteven() 从该缓冲区中取出一个偶数并用 counteven() 统计偶数个数。请用信号量机制实现这三个进程的同步与互斥活动，并说明所定义信号量的含义（要求用伪代码描述）。

答案

答案：

（1）信号量定义及含义：

  • mutex（初值1）：互斥信号量，保证对缓冲区的互斥访问。
  • odd（初值0）：同步信号量，表示缓冲区中奇数的个数，由P1生产后V操作，P2消费前P操作。
  • even（初值0）：同步信号量，表示缓冲区中偶数的个数，由P1生产后V操作，P3消费前P操作。
  • empty（初值N）：同步信号量，表示缓冲区中空单元的个数，由P1生产前P操作，P2/P3消费后V操作。

（2）进程伪代码：

semaphore mutex=1;
semaphore odd=0, even=0;
semaphore empty=N;

main() {
    cobegin {
        Process P1() {
            while (True) {
                x = produce();
                P(empty);          // 申请一个空单元
                P(mutex);          // 互斥进入缓冲区
                Put();             // 放入缓冲区
                V(mutex);          // 释放互斥锁
                if (x % 2 == 0)    // 判断奇偶性
                    V(even);       // 偶数，唤醒P3
                else
                    V(odd);        // 奇数，唤醒P2
            }
        }

        Process P2() {
            while (True) {
                P(odd);            // 等待一个奇数
                P(mutex);          // 互斥进入缓冲区
                getodd();          // 取出奇数
                V(mutex);          // 释放互斥锁
                V(empty);          // 释放一个空单元
                countodd();        // 统计奇数
            }
        }

        Process P3() {
            while (True) {
                P(even);           // 等待一个偶数
                P(mutex);          // 互斥进入缓冲区
                geteven();         // 取出偶数
                V(mutex);          // 释放互斥锁
                V(empty);          // 释放一个空单元
                counteven();       // 统计偶数
            }
        }
    } coend
}

（3）关键点：

  • 同步：P1通过odd和even信号量协调P2和P3的消费，确保生产与消费的奇偶匹配。
  • 互斥：所有进程通过mutex信号量互斥访问缓冲区，避免竞争条件。
  • 流量控制：empty信号量限制缓冲区占用，防止溢出。

本题讲解：生产者-消费者（奇偶分流）的信号量设计

问 1：定义哪些信号量——先数清题目里有几类「等待」

信号量的机制：P 申请资源，不够则阻塞等待；V 释放资源，唤醒等待者。定义几个信号量，取决于进程间存在几类「等待关系」。本题一共三类：

  1. 等空位：缓冲区共 N 个单元，P1 放数前必须有空单元。这是一种「资源计数」，初值 N。
  2. 等数据：P2 只取奇数、P3 只取偶数——只知道「缓冲区里有数」不够，必须按奇偶分别计数、分别唤醒。两个信号量，初值都是 0（开局无数据，消费者先等）。
  3. 等进入：缓冲区是被三个进程共享读写的数据结构，同一时刻只允许一人进出。互斥信号量，初值 1。

为什么 odd/even 省不掉、不能合成一个「产品数」？ 若只设一个「有数」信号量，P2 被唤醒后取出的可能是偶数，奇偶配对就乱了。本题比普通生产者-消费者多出的一层是产品分流：每种产品单独计数、单独唤醒对应消费者——这正是 odd 与 even 两个信号量的存在理由。

信号量初值含义
mutex1互斥信号量，保证各进程互斥访问缓冲区
emptyN同步信号量，缓冲区中空单元个数；P1 放数前 P，P2/P3 取完后 V
odd0同步信号量，缓冲区中奇数个数；P1 放奇数后 V，P2 取之前 P
even0同步信号量，缓冲区中偶数个数；P1 放偶数后 V，P3 取之前 P

问 2：伪代码（与参考答案同口径）

P1（生产者）：

步语句说明
1x = produce();生成一个正整数
2P(empty);先申请空单元
3P(mutex);再申请进入缓冲区
4put();放入缓冲区
5V(mutex);退出临界区
6if (x % 2 == 0) V(even); else V(odd);按奇偶唤醒对应消费者

P2（取奇数）：P(odd); P(mutex); getodd(); V(mutex); V(empty); countodd();

P3（取偶数）：P(even); P(mutex); geteven(); V(mutex); V(empty); counteven();

三个进程用 cobegin ... coend 并发执行。

为什么 P(empty) 必须在 P(mutex) 之前？ 这是「先同步后互斥」原则。若颠倒：缓冲区已满时，P1 先拿到 mutex，随后阻塞在 P(empty) 上——它抱着锁睡觉；P2/P3 要腾出空位得先进缓冲区取数，即先执行 P(mutex)，锁却握在 P1 手里。两边互等，死锁。同理，消费者也必须先 P(odd)/P(even) 再 P(mutex)：没有对应产品时同样不该占着锁等。

为什么 V(odd)/V(even) 放在 V(mutex) 之后？ 「数据已放入」这个事实在 put() 结束时就已成立，唤醒消费者不必占用临界区——临界区只包住真正读写缓冲区的语句，越短越好。消费者先 V(mutex) 再 V(empty) 同理：数据已取出，空单元数的增加才成立，再唤醒生产者。

易错点

  • P(empty) 与 P(mutex) 顺序颠倒：满缓冲区时抱锁互等 → 死锁。所有 P 操作都要「先同步、后互斥」，不可交换。
  • 漏掉 odd/even：只写 mutex 和 empty 就退化成普通生产者-消费者，实现不了「奇数给 P2、偶数给 P3」的分流。
  • 信号量含义没说清：每个信号量的初值、物理含义、「谁 P 谁 V」都要写明，这是本题的给分点。
  • empty 初值写错：它数的是空单元，初值是容量 N，不是 0 也不是 1。
一句话结论：mutex 管互斥，empty 管空位（容量），odd/even 管奇偶配对（同步）；P 操作先同步后互斥，V 操作出临界区后再唤醒。
