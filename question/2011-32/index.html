同步与互斥
选择题 2 分

有两个并发执行的进程 P1 和 P2，共享初值为1的变量 x。P1 对 x 加1，P2 对 x 减1。加1和减1操作的指令序列分别如下所示。

// 加1操作
load R1, x    // 取x到寄存器R1中
inc R1
store x, R1  // 将R1的内容存入x
// 减1操作
load R2, x
dec R2
store x, R2

两个操作完成后，x 的值__。

答案

答案：C

▶本题解析视频（B 站）
32

本题讲解：无同步措施时并发加/减 1 后 x 的取值

答案：C（可能为 0、1 或 2）。x 初值为 1，P1 对 x 加 1、P2 对 x 减 1，两条指令序列都由"读—改—写"三步组成，执行顺序被打乱时会发生"丢失更新"。

第一步：先看顺序执行（不打架）

  • P1 全做完再 P2：x = 1 → 2 → 1；
  • P2 全做完再 P1：x = 1 → 0 → 1。

两种串行情况下 x 都等于 1。

第二步：找 load 与 store 之间被插入的交错

关键在于 load 把 x 读进寄存器之后、store 写回之前，对方可能抢先完成一整轮，写回就会覆盖对方的成果：

交错情景过程结果
情景 A（得 0）P1 load 得 1；P2 load 得 1；P1 inc 后 store → x=2；P2 dec 后按寄存器旧值 1 写回x = 0
情景 B（得 2）P2 load 得 1；P1 load 得 1；P2 dec 后 store → x=0；P1 inc 后按寄存器旧值 1 写回x = 2

两个 load 都读到旧值 1，后写的那个把先写的成果"冲掉"，这就是丢失更新。

第三步：为什么不能是 −1 或 3

整个系统只有一次加 1 和一次减 1。每次 store 写回的值要么基于读到的 x=1（写回 0 或 2），要么是两轮操作完全串行叠加后的 1。x = 3 需要加两次，x = −1 需要减两次，操作次数固定，都不可能发生。

结论

x 的可能取值为 0、1、2，选 C。

易错点

  • 选 B（只能为 1）：忽略了 load 与 store 之间可被打断，丢失更新会让结果偏离串行值。
  • 选 A 或 D（出现 −1 或 3）：把"并发交错"夸大成"操作次数可能变多"——操作次数固定，只是读到的值可能过期。
记忆点：两条 load…store 序交错 → 丢失更新，x ∈ {0,1,2}；解题套路是枚举 store 相对对方各条指令的插入位置。
