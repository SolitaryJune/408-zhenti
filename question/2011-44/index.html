高速缓冲存储器虚拟存储器
综合应用题 12 分

某计算机存储器按字节编址，虚拟（逻辑）地址空间大小为 16MB，主存（物理）地址空间大小为 1MB，页面大小为 4KB；Cache 采用直接映射方式，共 8 行；主存与 Cache 之间交换的块大小为 32B。系统运行到某一时刻，页表的部分内容和 Cache 的部分内容分别如题 44-a 图、题 44-b 图所示，图中页框号及标记字段的内容为十六进制形式。

请回答下列问题。
（1）虚拟地址共有几位，哪几位表示虚页号？物理地址共有几位，哪几位表示页框号（物理页号）？
（2）使用物理地址访问 Cache 时，物理地址应划分成哪几个字段？要求说明每个字段的位数及在物理地址中的位置。
（3）虚拟地址 001C60H 所在的页面是否在主存中？若在主存中，则该虚拟地址对应的物理地址是什么？访问该地址时是否 Cache 命中？要求说明理由。
（4）假定为该机配置一个四路组相联的 TLB 共可存放 8 个页表项，若其当前内容（十六进制）如题 44-c 图所示，则此时虚拟地址 024BACH 所在的页面是否存在主存中？要求说明理由。

答案

（1）虚拟地址为24位，虚页号为高12位；物理地址为20位，页框号为高8位。

（2）物理地址划分为主存字块标记、Cache 行号和块内地址三个字段：主存字块标记占高 12 位（第 19～8 位），Cache 行号占 3 位（第 7～5 位），块内地址占低 5 位（第 4～0 位）。原“Cache字块标记（3位）”的说法不准确，这 3 位实际用于直接映射的 Cache 行索引。

（3）虚拟地址001C60H的虚页号为001H，对应页表项有效位为1，故页面在主存中；页框号为04H，页内偏移为C60H，物理地址为04C60H。访问该物理地址时，Cache索引为第3行，但行中标记（105H）与主存标记（04CH）不相等，故Cache不命中。

（4）虚拟地址024BACH的虚页号为024H，TLB组数为2，组号由虚页号最低1位决定（为0），TLB标记为高11位（012H）。TLB第0组中存在有效且标记匹配的项，故TLB命中，页面在主存中。

44

本题讲解：虚拟地址 → 物理地址 → Cache / TLB 全链路（综合题）

第 0 步：先立机制——一次访存要过三道关卡

把整条链路想成一趟"翻译 + 缓存"的流水线，四个小问全挂在这条链上：

  1. 分页翻译（虚→实）：虚拟地址 = 虚页号（高位）+ 页内偏移（低位）。页是搬动单位，一个虚页整页搬进某个主存页框，页内第几个字节的相对位置原封不动——所以偏移不参与翻译、原样拼接，页表只负责把虚页号换成页框号。
  2. 直接映射 Cache（用物理地址访问）：主存每块只能"对号入座"到固定一行。地址从低位起分三段：块内地址定块内第几个字节，行号定进哪一行，标记 tag 定这一行缓存的究竟是不是这一块——行号只负责选行，命中与否全看 tag 比较的结果。
  3. TLB（页表的缓存）：四路组相联 = 组间直接映射 + 组内全相联——虚页号低位定组号（对号入座到组），高位做 tag（组内逐项比较），有效位说明这项映射可用。

第 1 问：虚拟/物理地址各几位，页号取哪几位

位数由空间大小直接决定：16MB = 2²⁴ → 虚拟地址 24 位；1MB = 2²⁰ → 物理地址 20 位。页内偏移两边必须同宽：页大小 4KB = 2¹² → 低 12 位是偏移。于是虚页号 = 24 − 12 = 12 位（高 12 位），页框号 = 20 − 12 = 8 位（高 8 位）。

地址位数高位字段低位字段
虚拟地址24虚页号 12 位页内偏移 12 位
物理地址20页框号 8 位页内偏移 12 位

（为什么页框号恰好是 8 位：偏移 12 位在翻译前后不变，剩下的位数自然全给页框号——20 − 12 = 8，不是另算的一项。）

第 2 问：物理地址的三段划分

从低位起分：块大小 32B = 2⁵ → 块内地址 5 位（第 4~0 位）；8 行 = 2³ → Cache 行号 3 位（第 7~5 位）；剩下的高位全部归 tag → 主存字块标记 12 位（第 19~8 位）。

为什么必须从低位起分？块内偏移的粒度是字节，必须贴着最低位；行号要把所有主存块均匀分到 8 行，紧挨着块内地址；再往高的所有位统一交给 tag 做身份比较。把中间 3 位叫"Cache 字块标记（3 位）"是不准确的——它是行索引，用来选行；标记（tag）是高 12 位。

第 3 问：虚拟地址 001C60H 的完整查访

  1. 拆分：高 12 位 = 虚页号 001H，低 12 位 = 偏移 C60H；
  2. 查页表：虚页 001 的表项有效位 = 1，页框号 = 04H → 页面已调入主存；
  3. 拼物理地址：页框号 04H 顶到高位、偏移 C60H 原样放低位（第 0 步机制 1）→ 04C60H；
  4. 拆 Cache 地址：04C60H = 0000 0100 1100 0110 0000 → tag = 04CH，行号 = 011（第 3 行），块内 = 0；
  5. 比命中：第 3 行有效位为 1，但行内标记 = 105H ≠ 04CH → Cache 不命中。

有效位为 1 为什么还不命中？ 有效位只说明"这行装了东西"，tag 才说明"装的是谁"——第 3 行缓存的是主存标记 105H 那一块，而要找的是 04CH 块；直接映射下同一行两块只能轮流入住，此刻坐在里面的不是它。

第 4 问：虚拟地址 024BACH 查 TLB

  1. 虚页号 = 024H（偏移 BACH 不参与翻译）；
  2. TLB 共 8 项、四路组相联 → 组数 = 8 ÷ 4 = 2 组；组号取虚页号最低 1 位 = 0 → 查第 0 组；
  3. TLB 标记 = 虚页号其余 11 位：024H = 0000 0010 0100，去掉最低位 0，高 11 位 = 0000 0010 010 = 012H；
  4. 第 0 组中存在有效位为 1 且标记 = 012H 的表项（对应页框号 1FH）→ TLB 命中，虚页 024H 已映射到主存页框，页面在主存中，无需再访存查页表。

为什么组号只取最低 1 位、标记却有 11 位？ "组间直接映射"那 1 位已经把查找范围锁定到第 0 组，它不参与比较；组内是全相联，4 项逐个比标记——标记必须携带虚页号里除组号以外的全部信息，所以是 12 − 1 = 11 位。

易错点

  • 页号位数另起炉灶算：页号位数 = 地址位数 − 页内偏移位数（24−12、20−12），不存在"再减一"或"再加一"。
  • Cache 字段从高位起分：顺序只能从低位起——块内 5 位、行号 3 位、标记 12 位；行号是用来"选行"的索引，不是标记。
  • 把有效位当命中：有效位 1 且 tag 相等才叫命中，缺一不可——第 3 问的陷阱正设在这里。
  • TLB 组号用整个虚页号：2 组时组号只占虚页号最低 1 位，其余 11 位是 TLB 标记；组号那一位不参与比较。
一句话：24 位虚地址高 12 位查页表（001H → 04H），偏移不变拼出 04C60H；Cache 按"块内 5 + 行号 3 + 标记 12"拆开，第 3 行标记 105H ≠ 04CH 不命中；024BAC 的虚页 024H 在 TLB 第 0 组（标记 012H）命中，页面在主存。
