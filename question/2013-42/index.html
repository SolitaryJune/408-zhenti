顺序查找和折半查找
综合应用题 10 分

设包含4个数据元素的集合S={“do”, “for”, “repeat”, “while”}, 各元素的查找概率依次为p1=0.35, p2=0.15, p3=0.15, p4=0.35。将S保存在一个长度为4的顺序表中，采用折半查找法，查找成功时的平均查找长度为2.2。请回答：
（1）若采用顺序存储结构保存S，且要求平均查找长度更短，则元素应如何排列？应使用何种查找方法？查找成功时的平均查找长度是多少？
（2）若采用链式存储结构保存S，且要求平均查找长度更短，则元素应如何排列？应使用何种查找方法？查找成功时的平均查找长度是多少？

答案

（1）顺序存储：元素按查找概率降序排列（如“do”、“while”、“for”、“repeat”），采用顺序查找方法，查找成功时的平均查找长度为2.1。
（2）链式存储：构造二叉排序树（如以“for”为根，“do”为左孩子，“while”为右孩子，“repeat”为“while”的左孩子），采用二叉排序树的查找方法，查找成功时的平均查找长度为2.0。

本题讲解：让平均查找长度更短——顺序表与链表的两种改造（10 分）

第一步：先算基准——折半查找的 ASL = 2.2

4 个元素折半（low=1, high=4，mid=⌊5/2⌋=2）的判定树：位置 2（for）为根在第 1 层，位置 1（do）、位置 3（repeat）在第 2 层，位置 4（while）在第 3 层。ASL = 0.15×1 + 0.35×2 + 0.15×2 + 0.35×3 = 2.2，与题干一致。要更短，就必须让查找概率大的元素（do、while 各 0.35）处在更浅的层。

第（1）问：顺序存储——按概率降序排列 + 顺序查找

顺序查找的比较次数只由位置决定：第 k 个元素比较 k 次。折半的比较次数由判定树形状决定，怎么排都还是 2.2，所以要换查找方法：采用顺序查找，并把元素按查找概率降序排列：

位置1234
元素dowhileforrepeat
概率0.350.350.150.15
比较次数1234

ASL = 0.35×1 + 0.35×2 + 0.15×3 + 0.15×4 = 2.1，比 2.2 更短。

第（2）问：链式存储——构造二叉排序树查找

链表不支持随机访问，不能折半；改用二叉排序树（链式存储）查找。按字典序 do < for < repeat < while，把大概率元素放浅层，取 for 为根：do 为左孩子，while 为右孩子，repeat 为 while 的左孩子：

元素fordowhilerepeat
层号（=比较次数）1223
概率0.150.350.350.15

ASL = 0.15×1 + 0.35×2 + 0.35×2 + 0.15×3 = 2.0，又比 2.1 更短。

易错点

  • 顺序存储仍用折半：折半查找的比较次数取决于判定树形状，与元素排列顺序无关，怎么排都是 2.2，必须换用顺序查找。
  • BST 里把 repeat 放错层：repeat 的字典序介于 for 与 while 之间，插在 while 之下（第 3 层）才是合法 BST；while 是 for 的右孩子。
  • 比较次数与层号错位：BST 根的比较次数是 1（即第 1 层），每深一层多比较一次。
顺序表按概率降序 + 顺序查找得 2.1；链表建 BST（for 为根）得 2.0，两者都优于折半的 2.2。
