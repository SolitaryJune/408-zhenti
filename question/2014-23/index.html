本题讲解：调度算法与饥饿现象

答案：A。时间片轮转调度不可能导致饥饿。

第一步：明确"饥饿"的判断标准

饥饿（starvation）指进程长期等不到处理机或所需资源而无法推进。判断一个调度算法会不会饥饿，就看它"挑下一个进程"的规则是否可能让某一类进程永远排不上队。

第二步：逐项分析

  • A 时间片轮转：就绪进程排成 FIFO 队列，人人轮流上一个时间片，排到就上处理机。任何进程的等待时间都有上界——队头迟早轮到自己 → 不可能饥饿。
  • B 静态优先数调度：优先级固定不变、不随等待时间升高。只要高优先级进程源源不断，低优先级进程可能一直被压住 → 可能饥饿。
  • C 非抢占式短作业优先：每次调度都挑估计最短的作业；长作业虽不会被抢占，但每次轮到调度时仍可能被新来的更短作业推后 → 长作业可能饥饿。
  • D 抢占式短作业优先：更短的作业一到就抢占处理机，长作业被反复打断、一再推迟 → 更可能饥饿。

易错点

  • 认为"非抢占所以不会饥饿"：非抢占只保证正在运行的进程不被打断，不保证等待的进程会被选中，C 依然可能饥饿。
  • 混淆饥饿与死锁：饥饿的进程还在队列里等机会，只是轮不到；死锁是互相等待形成环路，谁都无法再推进。
一句话结论：时间片轮转按到达顺序轮流执行，等待时间有上界，不可能饥饿；凡按"优先级、长短"挑进程的算法都可能让某类进程永远排队。
