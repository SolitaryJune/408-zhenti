操作系统

2015-45

同步与互斥
综合应用题 9 分

有 A、B 两人通过信箱进行辩论，每个人都从自己的信箱中取得对方的问题。将答案和向对方提出的新问题组成一个邮件放入对方的邮箱中。假设 A 的信箱最多放 M 个邮件，B 的信箱最多放 N 个邮件。初始时 A 的信箱中有 x 个邮件（0 < x < M），B 的信箱中有 y 个（0 < y < N）。辩论者每取出一个邮件，邮件数减 1。A 和 B 两人的操作过程描述如下：

CoBegin

A{
    while (TRUE) {
        从 A 的信箱中取出一个邮件；
        回答问题并提出一个新问题；
        将新邮件放入 B 的信箱；
    }
}
B{
    while (TRUE) {
        从 B 的信箱中取出一个邮件；
        回答问题并提出一个新问题；
        将新邮件放入 A 的信箱；
    }
}

CoEnd

当信箱不为空时，辩论者才能从信箱中取邮件，否则需要等待。当信箱不满时，辩论者才能将新邮件放入信箱，否则需要等待。请添加必要的信号量和 P、V（或 wait、signal）操作，以实现上述过程的同步。要求写出完整过程，并说明信号量的含义和初值。

答案

【答案】

（1）信号量定义及初值：

  • semaphore Full_A = x; // A信箱中的邮件数
  • semaphore Empty_A = M - x; // A信箱中的空位数
  • semaphore Full_B = y; // B信箱中的邮件数
  • semaphore Empty_B = N - y; // B信箱中的空位数
  • semaphore mutex_A = 1; // 用于A信箱的互斥访问
  • semaphore mutex_B = 1; // 用于B信箱的互斥访问

（2）A的同步过程：

A {
    while (TRUE) {
        P(Full_A);        // 等待A信箱有邮件
        P(mutex_A);       // 进入A信箱临界区
        从A的信箱中取出一个邮件；
        V(mutex_A);       // 离开A信箱临界区
        V(Empty_A);       // A信箱空位加1
        回答问题并提出一个新问题；
        P(Empty_B);       // 等待B信箱有空位
        P(mutex_B);       // 进入B信箱临界区
        将新邮件放入B的信箱；
        V(mutex_B);       // 离开B信箱临界区
        V(Full_B);        // B信箱邮件数加1
    }
}

（3）B的同步过程：

B {
    while (TRUE) {
        P(Full_B);        // 等待B信箱有邮件
        P(mutex_B);       // 进入B信箱临界区
        从B的信箱中取出一个邮件；
        V(mutex_B);       // 离开B信箱临界区
        V(Empty_B);       // B信箱空位加1
        回答问题并提出一个新问题；
        P(Empty_A);       // 等待A信箱有空位
        P(mutex_A);       // 进入A信箱临界区
        将新邮件放入A的信箱；
        V(mutex_A);       // 离开A信箱临界区
        V(Full_A);        // A信箱邮件数加1
    }
}

本题讲解：双人信箱辩论的信号量同步（成对的生产者-消费者）

答题框架

先立模型再写代码：A、B 两个循环各自做"取信 → 处理 → 放信"，取信依赖自己信箱非空、放信依赖对方信箱不满——这是两组生产者-消费者；信箱本身是共享数据结构，一取一放不能同时改——再各配一把互斥锁。口诀：同步 P 在互斥 P 之前；同一信箱的取/放要互斥。

第一问：分析同步与互斥关系

  • 同步（数量约束）：A 从 A 信箱取邮件 → 依赖"A 信箱有邮件"；A 向 B 信箱放邮件 → 依赖"B 信箱有空位"。B 完全对称。这就是生产者-消费者里的"产品数"与"缓冲区空位数"。
  • 互斥（动作约束）：为什么有了"满/空"信号量还要 mutex——Full/Empty 只约束数量，不保护"取信/放信"这个修改信箱的动作本身：A 取信与 B 放信可能同时对 A 信箱动手（改计数、动队列），不互斥就会互踩。
  • 汇总：A 是"B 信箱的生产者、A 信箱的消费者"，B 反之；每个信箱 = 一对"满/空"信号量 + 一个互斥信号量。

第二问：信号量定义与初值

信号量初值含义
Full_AxA 信箱现有邮件数
Empty_AM − xA 信箱现有空位数
Full_ByB 信箱现有邮件数
Empty_BN − yB 信箱现有空位数
mutex_A1A 信箱的互斥访问
mutex_B1B 信箱的互斥访问

初值为什么这样定：Full 类由题设直接读出（A 现有 x 封、B 现有 y 封）；Empty 类是"容量减现有数"（M − x、N − y）；mutex 是互斥锁，取 1。

第三问：A 的完整过程

  1. P(Full_A); —— 等 A 信箱有邮件；
  2. P(mutex_A); —— 进 A 信箱临界区；
  3. 从 A 的信箱中取出一个邮件；
  4. V(mutex_A); —— 退出临界区；
  5. V(Empty_A); —— A 信箱空位加 1；
  6. 回答问题并提出一个新问题；
  7. P(Empty_B); —— 等 B 信箱有空位；
  8. P(mutex_B); —— 进 B 信箱临界区；
  9. 将新邮件放入 B 的信箱；
  10. V(mutex_B); —— 退出临界区；
  11. V(Full_B); —— B 信箱邮件数加 1。

第四问：B 的完整过程（与 A 对称）

  1. P(Full_B);
  2. P(mutex_B);
  3. 从 B 的信箱中取出一个邮件；
  4. V(mutex_B);
  5. V(Empty_B);
  6. 回答问题并提出一个新问题；
  7. P(Empty_A);
  8. P(mutex_A);
  9. 将新邮件放入 A 的信箱；
  10. V(mutex_A);
  11. V(Full_A);

为什么这套方案不会互相等死（初始条件的意义）

学习者最担心的是：A 等 B 的空位、B 等 A 的空位，会不会互相卡死？不会，而且题给的初始条件正是为排除死锁：

  • 每轮都是"先取出一封、再放回一封"，两信箱邮件总数恒等于 x+y，不变；
  • 两箱不可能同时空：x>0 且 y>0，总数 x+y ≥ 2 > 0；"两人都阻塞在取信上"要求两箱同时空、总数为 0，矛盾；
  • 两箱不可能同时满：x < M 且 y < N，总数 x+y < M+N；"两人都阻塞在放信上"要求两箱同时满、总数为 M+N，矛盾。

死锁只有这两条发生路径，都被初始条件排除，方案安全。反过来看条件缺一不可：若 x = y = 0，两人开局同时阻塞在取信上，永远无人投出第一封——这正是题目限定 x > 0、y > 0 的用意之一。

易错点

  • 同步 P 与互斥 P 顺序颠倒：若先 P(mutex_A) 再 P(Full_A)，信箱空时进程抱着临界区锁等邮件，对方也无法操作该信箱 → 可能死锁。
  • 漏掉互斥信号量：只写四个"满/空"信号量会丢分——Full/Empty 只管数量，管不住"取/放"动作互踩。
  • P、V 配对错位：取出后应 V(Empty_A)（空位 +1），放入后应 V(Full_B)（邮件 +1），不能对调。
  • 初值写错：Empty 类初值是"容量减现有数"（M − x、N − y），不是 M、N。
记忆锚点：一个信箱 = 一对"满/空"信号量 + 一个互斥信号量；先同步后互斥，取出 V 空、放入 V 满；总数不变 + 初始不空不满 ⇒ 不会互等死锁。
