综合应用题 9 分

某网络拓扑如下图所示，其中路由器内网接口、DHCP服务器、WWW服务器与主机1均采用静态IP地址配置，相关地址信息见图中标注；主机2～主机N通过DHCP服务器动态获取IP地址等配置信息。

请回答下列问题。

1）DHCP 服务器可为主机2～主机N动态分配IP地址的最大范围是什么？主机2使用DHCP协议获取IP地址的过程中，发送的封装DHCP Discover报文的IP分组的源IP地址和目
的 IP 地址分别是什么？
2）若主机 2 的 ARP 表为空，则该主机访问 Internet 时，发出的第一个以太网帧的目的 MAC 地址是什么？封装主机 2 发往 Internet 的 IP 分组的以太网帧的目的 MAC 地址是什么？
3）若主机 1 的子网掩码和默认网关分别配置为 255.255.255.0 和 111.123.15.2，则该主机是否能访问 WWW 服务器？是否能访问 Internet？请说明理由。

答案

1）DHCP服务器可为主机2～主机N动态分配IP地址的最大范围是111.123.15.5～111.123.15.254；主机2发送的DHCP Discover报文的源IP地址是0.0.0.0，目的IP地址是255.255.255.255。

2）主机2访问Internet时，发出的第一个以太网帧的目的MAC地址是FF-FF-FF-FF-FF-FF；封装主机2发往Internet的IP分组的以太网帧的目的MAC地址是00-a1-a1-a1-a1-a1（图中标注的路由器内网接口MAC地址）。

3）主机1能访问WWW服务器，但不能访问Internet。因为默认网关配置错误（配置为111.123.15.2，正确应为111.123.15.1），所以可以访问同一子网内的服务器，但访问Internet时IP分组会被错误路由。

本题讲解：DHCP 地址池、ARP 广播帧与网关配置错误

第 0 步：先读图立机制——三个角色、三条规则

拓扑（题图）：以太网交换机一侧接 WWW 服务器（111.123.15.3/24）、DHCP 服务器（111.123.15.2/24，MAC 00-b1-b1-b1-b1-b1）、主机 1（111.123.15.4/24）与主机 2～N（DHCP 动态获取），另一侧接路由器内网接口（111.123.15.1/24，MAC 00-a1-a1-a1-a1-a1），路由器外侧是 Internet。本题三问各对应一条通信规则：

  • DHCP 规则：主机 2 还没有 IP 时，Discover 报文只能"源 IP 全 0、目的 IP 全 1"在本网广播——不知道自己是谁，也不知道服务器在哪；
  • ARP/帧规则：以太网帧的目的 MAC 只认同一网段内的下一跳——跨网段时帧 MAC 写网关接口的 MAC，IP 分组头里的目的 IP 保持最终目的地不变；
  • 交付规则：主机用子网掩码判断目的是否同网段——同网段直接交付（不经过网关），跨网段才交给（正确的）默认网关。

第 1）问：DHCP 地址池与 Discover 的 IP 封装

先圈死不能分配的地址：.0 主机号全 0 是网络地址、.255 主机号全 1 是广播地址，都不能当单播地址用；静态占用的 .1（路由器内网口）、.2（DHCP 服务器）、.3（WWW 服务器）、.4（主机 1）已配置。剩下的才是动态池：

  • 可动态分配的最大范围：111.123.15.5 ～ 111.123.15.254。
  • Discover 的封装为什么是"全 0 源 + 全 1 目的"：主机 2 此刻没有 IP → 源 IP 填 0.0.0.0（"我还不知道我是谁"）；也不知道 DHCP 服务器在哪 → 只能对本网广播，目的 IP 255.255.255.255（"请本网所有主机都听我说"）。

第 2）问：两个「目的 MAC 地址」

关键机制：以太网帧必须有目的 MAC 才能发出去，而 ARP 表为空 → 第一个帧只能是广播的 ARP 请求。

  • 主机 2 访问 Internet，目的 IP 不在本子网 → 下一跳是默认网关（路由器内网口 111.123.15.1）；ARP 表空，不知道网关 MAC → 先发 ARP 请求广播帧，目的 MAC = FF-FF-FF-FF-FF-FF（问全网"谁是 111.123.15.1"）。
  • 学到网关 MAC 后再发数据：封装发往 Internet 的 IP 分组的以太网帧，目的 MAC = 下一跳的 MAC = 00-a1-a1-a1-a1-a1（路由器内网接口）。为什么帧 MAC 不写 Internet 服务器的 MAC：服务器与主机 2 不在同一网段，MAC 地址只在链路层网段内有效，出了网关就要换帧重新封装——帧层认下一跳，IP 层认终点，两者各司其职。

第 3）问：主机 1 能否访问 WWW 服务器 / Internet

  • 能访问 WWW 服务器：主机 1 掩码 255.255.255.0 与网络 /24 一致；WWW 服务器 111.123.15.3 与主机 1 同子网 → 按交付规则走直接交付，根本不查默认网关，网关配错也拦不住同网段通信。
  • 不能访问 Internet：默认网关被配成 111.123.15.2——那是 DHCP 服务器，不是路由器内网口（应为 111.123.15.1）。发往 Internet 的分组被交给 .2，而 DHCP 服务器不做路由转发，分组出不了这个子网。

易错点

  • 把 .255 或静态占用的 .1～.4 算进 DHCP 地址池：全 1 主机号是广播地址、静态地址已占用，均不可分配。
  • 第 2）问把「载 IP 分组的帧」也写成全 F：广播只用于 ARP 请求解析网关 MAC；传数据的帧目的 MAC 是下一跳（网关接口）的 MAC。
  • 第 3）问漏答 WWW 可达：同子网直接交付不依赖默认网关，网关错配只影响跨网段访问。
  • 混淆帧 MAC 与 IP 头：跨网段传输中 IP 头的目的 IP 始终是终点，帧的目的 MAC 逐跳更换。
记忆锚点：DHCP Discover = 0.0.0.0 → 255.255.255.255；ARP 请求 = 全 F 广播；跨网段的帧永远封装「下一跳」的 MAC；同网段直达不过网关。
