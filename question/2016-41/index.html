综合应用题 9 分

假设题 33～41 图中的 H3 访问 Web 服务器 S 时，S 为新建的 TCP 连接分配了 20KB（K = 1024）的接收缓存，最大段长 MSS = 1KB，平均往返时间 RTT = 200ms。H3 建立连接时的初始序号为 100，且持续以 MSS 大小的段向 S 发送数据，拥塞窗口初始阈值为 32KB；S 对收到的每个段进行确认，并通告新的接收窗口。假定 TCP 连接建立完成后，S 端的 TCP 接收缓存仅有数据存入而无数据取出。请回答下列问题。

（1）在 TCP 连接建立过程中，H3 收到的 S 发送过来的第二次握手 TCP 段的 SYN 和 ACK 标志位的值分别是多少？确认序号是多少？
（2）H3 收到的第 8 个确认段所通告的接收窗口是多少？此时 H3 的拥塞窗口变为多少？H3 的发送窗口变为多少？
（3）当 H3 的发送窗口等于 0 时，下一个待发送的数据段序号是多少？H3 从发送第 1 个数据段到发送窗口等于 0 时刻为止，平均数据传输速率是多少（忽略段的传输延时）？
（4）若 H3 与 S 之间通信已经结束，在 t 时刻 H3 请求断开该连接，则从 t 时刻起，S 释放该连接的最短时间是多少？

答案

（1）SYN=1，ACK=1，确认序号=101。
（2）接收窗口=12KB，拥塞窗口=9KB，发送窗口=9KB。
（3）下一个待发送数据段序号=20581，平均数据传输速率=20KB/s（或163.84kbps）。
（4）最短时间=300ms。

本题讲解：TCP 慢启动、窗口协商与连接释放全程推演

答题框架：第（1）问抓"握手段消耗序号"；第（2）（3）问沿"逐 RTT 推演"把 cwnd 与 rwnd 两条线走到窗口归零；第（4）问按 FIN→ACK→FIN→ACK 的最短时序数单程时延。四问共用一个模型：发送窗口 = min(拥塞窗口, 接收窗口)。

第 0 步：先立模型——发送窗口受两把"闸门"同时约束

  • 接收窗口 rwnd：S 通告"我的缓存还能装多少"。本题缓存 20KB 且只存不取，每收到 1 个 1KB 的段就少 1KB，故收到 n 段后 rwnd = 20 − n KB——这是背压式流量控制。
  • 拥塞窗口 cwnd：H3 对"网络能承受多少"的估计。慢启动规则：每收到 1 个确认，cwnd 加 1 个 MSS。一个 RTT 内发出多少段就收回多少个确认，所以 cwnd 每隔一个 RTT 翻倍（指数增长）。
  • 实际发送窗口取两把闸门中更紧的那把。题给阈值 ssthresh = 32KB 在整个推演中从未被触及（cwnd 最高 21KB），所以全程处于慢启动，不必考虑切换到拥塞避免。

第（1）问：第二次握手段的字段

TCP 规定 SYN 和 FIN 各消耗一个序号——这样对方的确认才有明确的对象（确认序号 = 对方序号 + 1），握手与挥手的可靠闭环才能成立。H3 的 SYN 段序号为 100，占掉 100 这个号，其数据从 101 起编。S 回的第二段必须同时确认这条 SYN：SYN=1、ACK=1，确认序号 = 100 + 1 = 101。

第（2）问：逐 RTT 推演，锁定第 8 个确认

推演逻辑：每个 RTT 开始时按当前发送窗口发段，RTT 结束时这些段的确认集中到达，每个确认把 cwnd 加 1 个 MSS——所以 cwnd 逐轮 1→2→4→8 翻倍；rwnd 则随收到的段数线性下降。列表对号：

时刻累计收到确认cwndrwnd本轮发送（累计）
t=0—1KB20KB段1（1）
1RTT12KB19KB段2、3（3）
2RTT34KB17KB段4~7（7）
3RTT78KB13KB段8~15（15）
4RTT8~159→16KB12→5KB段16~20（20）
5RTT16~2021KB0发送窗口=0

第 8 个确认是 4RTT 批次里第一个到达的：cwnd 从 8KB 起按"每确认加 1"变为 9KB；此时 S 已收到 8 段，rwnd = 20 − 8 = 12KB；发送窗口 = min(9, 12) = 9KB。注意 4RTT 轮里瓶颈已经换手：整批确认到齐后 cwnd 涨到 16KB，但 rwnd 只剩 5KB，本轮只发出段 16~20——限制从"网络"切换成了"接收缓存"。

第（3）问：窗口归零时的序号与平均速率

5RTT = 1s 时，第 16~20 个确认到达，S 收满 20 段，rwnd = 0，发送窗口 = 0。TCP 序号按字节编号：SYN 占掉 100，20 个 1KB 段从 101 连续排下去，故下一个待发送序号 = 101 + 20×1024 = 20581。平均数据传输速率 = 20KB ÷ 1s = 20KB/s（20480 B/s × 8 = 163.84kbps）；分母 1s 就是"从 t=0 发出第 1 个数据段到 5 个 RTT 后窗口归零"的时长。

第（4）问：S 释放连接的最短时间

S 是被动关闭方：收到 FIN 必须立即确认，但 S 只收不发、没有任何待发数据，可以把对 FIN 的 ACK 和自己的 FIN 合并成一个报文段发出——"最短"正是对应这种无数据、立即响应的理想情形：

  • t：H3 发 FIN；t+100ms：S 收到，回 ACK+FIN；
  • t+200ms：H3 收到，回 ACK；t+300ms：S 收到对自己 FIN 的确认，释放连接。

最短时间 = 3 × 半个 RTT = 300ms。若 ACK 与 FIN 分开发要多花一个单程；若误以为 S 也要等 2MSL 则更长——TIME_WAIT 只加在主动关闭方 H3 身上，S 收到确认即释放。

易错点

  • 第（3）问算成 20580：忘了 SYN 消耗一个序号，数据序号从 101 起排。
  • 第（2）问发送窗口取错：发送窗口 = min(拥塞窗口, 接收窗口)，本题前期由 cwnd 决定，后期被 rwnd 压到 0。
  • 忽略 ssthresh 的判断：阈值 32KB 全程未被触及，才允许"每确认加 1"的慢启动一路走到窗口归零。
  • 第（4）问算成 200ms 或 400ms：S 无数据可发时 FIN 可与 ACK 合并立即发出，全程只需 3 个单程时延。
四问答案：(1) SYN=1、ACK=1、确认序号 101；(2) 接收窗口 12KB、拥塞窗口 9KB、发送窗口 9KB；(3) 序号 20581、平均速率 20KB/s；(4) 最短 300ms。
