计算机网络体系结构与参考模型数据链路层设备IPv4域名系统
综合应用题 9 分

某网络拓扑如题47图所示，以太网交换机S通过路由器R与Internet互联。路由器部分接口、本地域名服务器、H1、H2的IP地址和MAC地址如图中所示。在t₀时刻H1的ARP表和S的交换表均为空，H1在此刻利用浏览器通过域名www.abc.com请求访问Web服务器，在t₁时刻（t₁>t₀）S第一次收到了封装HTTP请求报文的以太网帧，假设从t₀到t₁期间网络未发生任何与此此次Web访问无关的网络通信。

请回答下列问题。
1）从t₀到t₁期间，H1除了HTTP之外还运行了哪个应用层协议？从应用层到数据链路层，该应用层协议报文是通过哪些协议进行逐层封装的？
2）若S的交换表结构为<MAC地址，端口>，则t₁时刻S交换表的内容是什么？
3）从t₀到t₁期间，H2至少会接收到几个与此次Web访问相关的帧？接收到的是什么帧？帧的目的MAC地址是什么？

答案

（1）DNS 协议。封装顺序为：DNS 报文 → UDP 数据报 → IP 数据报 → 以太网帧。

（2）t1 时刻 S 的交换表为：

MAC 地址端口
00-11-22-33-44-CC4
00-11-22-33-44-BB1
00-11-22-33-44-AA2

（3）H2 至少接收到 2 个与此次访问相关的帧，均为 ARP 查询广播帧，目的 MAC 地址均为 FF-FF-FF-FF-FF-FF。

本题讲解：域名访问全过程中 DNS、ARP 与交换机自学习

答题框架

先在草稿上还原 t0 → t1 的完整事件序列：ARP 找 DNS 服务器的 MAC → DNS 查询/应答 → ARP 找默认网关的 MAC → 发 HTTP 请求。三问都从这条时间线上取材。

第一问：除了 HTTP 还用了哪个应用层协议？如何封装？

浏览器手里只有域名 www.abc.com，必须先向本地域名服务器（192.168.1.126）发 DNS 查询。DNS 基于 UDP，封装链为：

DNS 报文 → UDP 数据报 → IP 数据报 → 以太网帧

对照记忆：HTTP 报文走 HTTP → TCP → IP → 以太网帧，差别在传输层。

第二问：t1 时刻 S 的交换表

交换机自学习规则：从端口 X 收到帧时，把"帧的源 MAC → 端口 X"写入交换表。逐帧记录：

触发学习的帧进入端口学到表项
H1 的 ARP 查询广播4CC → 4
DNS 服务器的 ARP 应答1BB → 1
路由器 R 的 ARP 应答2AA → 2

（CC/BB/AA 即 00-11-22-33-44-CC/BB/AA。）此后的 DNS 查询/应答、HTTP 请求都是单播帧且表项已齐，只查表转发、不再新增。故 t1 时刻交换表为：CC→4、BB→1、AA→2。

第三问：H2 至少收到几个帧？

交换机对广播帧泛洪、对查到表项的单播帧定点转发。H2 挂在端口 3，只有泛洪才轮得到它。全程 H2 恰好赶上两次泛洪：H1 的两次 ARP 查询广播帧（一次找 DNS 服务器的 MAC，一次找网关 192.168.1.1 的 MAC），故至少收到 2 个帧，目的 MAC 均为 FF-FF-FF-FF-FF-FF。

易错点

  • 把封装链答成 DNS → TCP → IP：DNS 用 UDP 不用 TCP。
  • 交换表漏记 BB 或 AA：ARP 应答虽是单播，但它的源 MAC 同样触发学习。
  • 认为 H2 会收到 DNS/HTTP 帧：这些是单播帧，交换机定点转发，H2 收不到。
一句话：域名访问 = 先 DNS（UDP）后 HTTP（TCP）；交换表学的是"入端口的源 MAC"；H2 只能收到 ARP 查询广播帧，共 2 个，目的 MAC 全 F。
