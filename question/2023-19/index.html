指令流水线
选择题 2 分

在采用“取指、译码/取数、执行、访存、写回”5段流水线的 RISC 处理器中，执行如下指令序列（第一列为指令序号），其中 s0, s1, s2, s3 和 t2 表示寄存器编号。

I1      add    s2, s1, s0    // R[s2]←R[s1] + R[s0]
I2      load   s3, 0(s2)    // R[s3]←M[R[s2] + 0]
I3      beq    t2, s3, L1   // if R[t2] = R[s3] jump to L1
I4      addi   t2, t2, 20   // R[t2]←R[t2] + 20
I5  L1: ……

若采用转发（旁路）技术处理数据冒险，采用硬件阻塞方式处理控制冒险，则在指令 I1～I4 执行过程中，发生流水线阻塞的指令有（ ）。

答案

答案：C

本题讲解：5 段流水线中哪些指令会阻塞

答案：C（仅 I3、I4）。

第一步：I1 与 I2 —— 转发即可，不阻塞

I1 add s2, s1, s0 在 EX 段末就算出 R[s2]；I2 load s3, 0(s2) 要在自己的 EX 段用 s2 计算有效地址。两者相邻，I1 的 EX 末正好衔接 I2 的 EX，走 EX→EX 转发即可，I2 不阻塞。

第二步：I2 与 I3 —— load-use 冒险，I3 阻塞 1 拍

load 的数据要到 I2 的 MEM 段末才从主存读出，而 I3 beq t2, s3 需要在自己的 EX 段用 s3 做比较。I3 的 EX 与 I2 的 MEM 同时发生，数据来不及，必须先阻塞 1 拍，再由 I2 的 MEM 段结果转发到 I3 的 EX 段。

第三步：I3 与 I4 —— 控制冒险，I4 阻塞

I3 是转移指令 beq，采用硬件阻塞方式处理控制冒险：在 I3 的 EX 段末确认转移方向与目标之前，其后的 I4 不能继续前进，必须等待，所以 I4 也被阻塞。

第四步：核对选项

指令冒险类型处理方式是否阻塞
I2数据冒险（用 s2）EX→EX 转发否
I3load-use 数据冒险（用 s3）先阻塞 1 拍，再 MEM→EX 转发是
I4控制冒险（beq 后）硬件阻塞，等转移方向确定是

易错点

  • 误以为 I2 要阻塞：add 的结果在 EX 末就可用，EX→EX 转发来得及，不必等写回段。
  • 只盯数据冒险漏掉控制冒险：beq 之后必须等转移方向确定，I4 因此被卡住。
  • 把阻塞归给 I1：I1 是数据的产生者，不阻塞；被卡住的是需要数据/需要等待的指令。
一句话结论：I2 靠转发通过，I3 因 load-use 阻塞 1 拍，I4 因转移指令方向未定而阻塞，选 C。
