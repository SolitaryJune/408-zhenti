同步与互斥
综合应用题 8 分

计算机系统中的进程之间往往需要相互协作以完成一个任务。在某网络系统中，缓冲区B用于存放一个数据分组，对B的操作有C1、C2和C3。C1将一个数据分组写入B中，C2从B中读出一个数据分组，C3对B中的数据分组进行修改。要求B为空时才能执行C1，B非空时才能执行C2和C3。
请回答下列问题。

（1）假设进程 P1 和 P2 均需要执行 C1，实现 C1 的代码是否为临界区？为什么？（2分）
（2）假设 B 初始为空，进程 P1 执行 C1 一次，进程 P2 执行 C2 一次。请定义尽可能少的信号量，并用 wait()、signal() 操作描述进程 P1 和 P2 之间的同步或互斥关系，说明所用信号量的作用及其初值。（3分）
（3）假设 B 初始不为空，进程 P1 和 P2 各执行 C3 一次。请定义尽可能少的信号量，并用 wait()、signal() 操作描述进程 P1 和 P2 之间的同步或互斥关系，说明所用信号量的作用及其初值。（3分）

答案

（1）C1的代码是临界区，因为C1执行写操作时需要缓冲区B为空，该操作涉及对共享资源B的独占访问，必须互斥执行。

（2）使用同步信号量 S=0 表示 B 中是否已有 P1 写入的数据：

P1:                 P2:
C1;                 wait(S);
signal(S);          C2;

（3）使用互斥信号量 mutex=1 保护对 B 的修改：

P1:                 P2:
wait(mutex);        wait(mutex);
C3;                 C3;
signal(mutex);      signal(mutex);

本题讲解：一个缓冲区逼出两类信号量——互斥与同步的判别与最小实现

第 0 步：机制先行——wait/signal 在管什么，怎么判断该用哪种

信号量的本质是一个整型计数加两个原子操作：wait(S) 在 S>0 时把 S 减 1 并放行，否则阻塞等待；signal(S) 把 S 加 1，若有等待者则唤醒一个。计数的语义就是"当前可用资源（或已发生事件）的个数"。

判别该用哪种信号量，只看约束的形状：若约束是"不能同时上"——资源只有一个槽位，多个进程的操作互斥 → 用互斥信号量，初值 = 允许同时进入的进程数 = 1；若约束是"必须先后"——事件 A 不发生，B 就不能做 → 用同步信号量，初值 = 事件已发生的次数（通常为 0），A 结束处 signal，B 开始前 wait。

第（1）问：C1 是否临界区（2 分）

是临界区。 先看 C1 内部干了什么：B 只有一个槽位，C1 包含"确认 B 为空"与"写入分组"两个动作。P1、P2 的 C1 若并发交错，可能出现：两者都在对方写入之前查得"B 为空"，于是先后写入，后写者覆盖先写者的分组（丢数据）；或写入动作交错，破坏 B 中的数据。这段代码访问共享资源 B、并发执行时结果与推进次序有关、必须互斥执行——按定义，并发进程中必须互斥访问共享资源的那段代码就是临界区，所以实现 C1 的代码是临界区。

第（2）问：B 初空，P1 写一次、P2 读一次（3 分）

先分析约束的形状：B 初始为空，只有 P1 写一次、P2 读一次。"B 为空才能执行 C1"这一侧自动满足——P1 是唯一写者，它执行 C1 时 B 必为空（没有别的进程写过）；真正需要机制保证的只有一件事：C2 必须发生在 C1 之后（B 非空才能读）。这是"必须先后"的同步关系，按第 0 步的机制，一个初值为 0 的同步信号量就够：

进程代码
P1C1; signal(S);
P2wait(S); C2;

S 的作用：表示"B 中是否已有 P1 写入的数据"，初值 0 正是"B 初空、写事件发生 0 次"。机制上它如何强制先后：若 P2 先到，wait(S) 发现 S=0，被阻塞；P1 执行完 C1 后 signal(S) 把 S 增为 1 并唤醒 P2，P2 才能执行 C2——先后次序由计数器硬性保证，不是靠运气。为什么不用再加互斥信号量 mutex：读被同步信号量排他地压在写之后，对 B 的访问天然不会并发，再加 mutex 只会增加多余的同步开销，违背"信号量尽可能少"的要求。

第（3）问：B 初非空，P1、P2 各修改一次（3 分）

再看约束的形状：B 初始不为空，P1、P2 各执行一次 C3（修改）。两者没有先后次序要求——谁先谁后结果都对，所以不需要同步信号量；但两个 C3 都是"读 B—改 B—写回 B"的过程，同时进行会交错：一个进程的修改可能被另一个覆盖、或读到中间状态。这是"不能同时上"的互斥关系，用 1 个互斥信号量 mutex（初值 1，即 mutex=1）把各自的 C3 包起来：

进程代码
P1wait(mutex); C3; signal(mutex);
P2wait(mutex); C3; signal(mutex);

mutex 的作用：保护对共享资源 B 的修改操作，保证两个 C3 互斥执行。初值为什么是 1：初值 = 允许同时进入的进程数 = 1，第一个到达者直接进入（B 本来就可用），第二个到达者被挡在 wait(mutex) 上，等前者 signal(mutex) 释放后才能进入。为什么不用同步信号量：题面没有给出任何"必须先后"的约束，硬造一个先后关系反而改变题目语义。

易错点

  • 第（2）问多设 mutex：一写一读且读必在写后，S 本身已完成全部约束，加 mutex 违背"尽可能少"。
  • 第（2）问把 S 初值设为 1：S 的语义是"已有数据可读"（事件计数），不是"槽位空闲"；B 初空，初值必须是 0。
  • 第（3）问误用同步信号量：两个 C3 无先后要求，只有互斥要求，设同步信号量没有依据。
  • 第（1）问只答"是"不答为什么：得分点在"访问共享资源 B + 必须互斥执行"，缺了机制只给结论拿不到分。
记忆锚点：不能同时上 → 互斥信号量初值 1；必须先后 → 同步信号量初值 0，前事件后 signal、后事件前 wait；信号量个数以"约束最少表达"为准。
