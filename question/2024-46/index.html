同步与互斥
综合应用题 8 分

计算机系统中的进程之间往往需要相互协作以完成一个任务。在某网络系统中，缓冲区B用于存放一个数据分组，对B的操作有C1、C2和C3。C1将一个数据分组写入B中，C2从B中读出一个数据分组，C3对B中的数据分组进行修改。要求B为空时才能执行C1，B非空时才能执行C2和C3。
请回答下列问题。

（1）假设进程 P1 和 P2 均需要执行 C1，实现 C1 的代码是否为临界区？为什么？（2分）
（2）假设 B 初始为空，进程 P1 执行 C1 一次，进程 P2 执行 C2 一次。请定义尽可能少的信号量，并用 wait()、signal() 操作描述进程 P1 和 P2 之间的同步或互斥关系，说明所用信号量的作用及其初值。（3分）
（3）假设 B 初始不为空，进程 P1 和 P2 各执行 C3 一次。请定义尽可能少的信号量，并用 wait()、signal() 操作描述进程 P1 和 P2 之间的同步或互斥关系，说明所用信号量的作用及其初值。（3分）

答案

（1）C1的代码是临界区，因为C1执行写操作时需要缓冲区B为空，该操作涉及对共享资源B的独占访问，必须互斥执行。

（2）使用同步信号量 S=0 表示 B 中是否已有 P1 写入的数据：

P1:                 P2:
C1;                 wait(S);
signal(S);          C2;

（3）使用互斥信号量 mutex=1 保护对 B 的修改：

P1:                 P2:
wait(mutex);        wait(mutex);
C3;                 C3;
signal(mutex);      signal(mutex);

本题讲解：缓冲区 B 的同步与互斥设计

答题框架：先判断「谁和谁竞争、谁等谁」，再决定用互斥信号量还是同步信号量，最后检查「信号量个数是否最少、初值是否正确」。

第（1）问：C1 是否临界区

C1 的代码是临界区。P1、P2 都要执行 C1 往缓冲区 B 写分组，B 是一次只容纳一个分组的共享资源；C1 执行时要求 B 为空，涉及对共享资源 B 的独占访问，两个 C1 并发执行会互相冲突，必须互斥执行——并发进程中访问共享资源的那段代码就是临界区。

第（2）问：B 初空，P1 写一次、P2 读一次

这是「先后同步」：P2 必须等 P1 写完才能读。定义 1 个同步信号量 S=0，语义是「B 中是否已有数据」：

进程代码
P1C1; signal(S);
P2wait(S); C2;

S 初值为 0 表示 B 初空：P2 的 wait(S) 在 P1 未写入前会阻塞；P1 写完执行 signal(S) 把 S 增为 1，唤醒 P2 执行 C2。只需这 1 个信号量（「B 为空」由 S=0 天然表达，无需再设互斥信号量）。

第（3）问：B 初非空，P1、P2 各修改一次

两个 C3 都要修改 B，谁先谁后都可以，但不能同时进行——这是互斥关系。定义 1 个互斥信号量 mutex=1：

进程代码
P1wait(mutex); C3; signal(mutex);
P2wait(mutex); C3; signal(mutex);

mutex 初值 1：任一进程 wait(mutex) 进入后其余进程被挡在门外，修改完 signal(mutex) 释放。

易错点

  • 第（2）问多设 mutex：只有一写一读，S 本身就完成了「先写后读」的同步，再加 mutex 违背「信号量尽可能少」。
  • 第（2）问把 S 初值设为 1：S 的语义是「已有数据可读」，B 初空，初值必须为 0。
  • 第（3）问误用同步信号量：两个 C3 无先后次序要求，只有互斥要求，用 mutex=1 包裹各自的 C3 即可。
结论：第（1）问 C1 是临界区；第（2）问用 S=0，P1：C1→signal(S)，P2：wait(S)→C2；第（3）问用 mutex=1，双方 wait(mutex)→C3→signal(mutex)。
