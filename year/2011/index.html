第二步：用退出条件解出执行次数

  • 忽略退出条件是 n/2 而不是 n：这同样只差常数，但推导过程要写对；考场上先写 2 的 t+1 次方 ≥ n/2 再解，就不会错。
记忆锚点：循环变量每轮翻倍的循环，执行次数都是 O(log₂n)；每轮加常数才是 O(n)。

答案

答案：B

2

本题讲解：以 d 开头的出栈序列个数

答案：B（4 种）。

第一步：分析「d 第一个出栈」逼出的局面

进栈次序固定为 a、b、c、d、e。要 d 成为第一个出栈元素，出 d 之前必须已把 a、b、c、d 依次压栈（e 还没进栈，否则 e 会压在 d 上面），随后弹出 d。此刻栈内自底向上是 a、b、c（c 在栈顶），e 尚未进栈。

第二步：数清剩下的自由度

d 出栈之后，每一步只有两种动作可选：退栈或把 e 压进去。退栈的顺序被栈顶死死定住，只能依次弹出 c → b → a；而 e 一旦压入就压在栈顶，c、b、a 都出不来，所以「e 入栈后 e 出栈」必须作为一个整体插进某个空档。e 的出栈位置只有 4 个空档：c 出之前、c 与 b 之间、b 与 a 之间、a 出之后。

空档位置出栈序列
c 出之前e, c, b, a
c 与 b 之间c, e, b, a
b 与 a 之间c, b, e, a
a 出之后c, b, a, e

第三步：合计

共 4 种，选 B。

易错点

  • 漏掉「e 还没进栈」这个关键状态：若以为 e 已经在栈中，会去排列 a、b、c、e 四个元素，得到偏大的数目。
  • 以为 e 可以自由穿插：e 压入后挡住栈顶，c、b、a 在 e 出栈前一个也动不了，所以只能按上表 4 个空档整体插入，不能拆开。
记忆锚点：出栈序列中「第一个出栈的元素」之前的元素全部已入栈、其后的元素全部未入栈——先固定局面，再数自由度。

队列
选择题 2 分

已知循环队列存储在一维数组A[0..n-1]中，且队列非空时front和rear分别指向队头元素和队尾元素。若初始时队列为空，且要求第1个进入队列的元素存储在A[0]处，则初始时front和rear的值分别是。

答案

答案：B

▶本题解析视频（B 站）
3

本题讲解：循环队列初始 front 与 rear 的取值

答案：B（0, n−1）。

第一步：明确题目给定的两条口径

  • 队列非空时，front 指向队头元素、rear 指向队尾元素（都是指向元素本身，不是空位置）；
  • 入队动作是「指针先加 1 再存元素」：rear = (rear + 1) % n，然后写入 A[rear]；front 只在出队时移动。

第二步：由「第 1 个元素存到 A[0]」反推 rear

入队时 rear 先加 1 再存入，要让存入位置是 0，就必须 rear 加 1 后等于 0，即初始 rear = n−1（(n−1+1) mod n = 0）。

第三步：由「front 指向队头元素」定 front

入队过程不移动 front。第 1 个元素存入 A[0] 后，front 必须指向它，所以初始 front = 0。

验证口径自洽：入队后 front = 0 指向 A[0]（队头），rear = (n−1+1) mod n = 0 也指向 A[0]（队尾，单元素队列头尾重合）；再入队一个元素则存入 A[1]、rear 变为 1，front 不动，队头仍是 A[0]，一切吻合。

易错点

  • 选 A（0, 0）：rear = 0 时按「先加再存」，第一个元素会落到 A[1]，恰好违背题目要求；这是把口径混成「先存再加（rear 指向队尾元素的下一位置）」的结果。
  • 选 C、D（front = n−1）：front = n−1 时队头指针怎么都对不上 A[0]，与「front 指向队头元素」直接矛盾。
记忆锚点：指向元素本身 + 先加 1 再存入 ⇒ 想让第 1 个元素落在 A[0]，初始 front = 0、rear = n−1。

二叉树的概念
选择题 2 分

若一棵完全二叉树有768个结点，则该二叉树中叶结点的个数是。

答案

答案：C

▶本题解析视频（B 站）
4

本题讲解：完全二叉树的叶结点个数

答案：C（384）。

第一步：n0 = n2 + 1 不是口诀，数两遍边就能推出来

二叉树里除了根，每个结点头顶都有一条来自父结点的边，所以边数 = 结点数 − 1；而边只会从分支结点发出——度 1 结点发 1 条、度 2 结点发 2 条，边数 = n1 + 2n2。两式相等：

n0 + n1 + n2 − 1 = n1 + 2n2，两边消去 n1，得 n0 = n2 + 1——叶子永远比"双孩子结点"恰好多一个。

第二步：完全二叉树为什么 n1 只能取 0 或 1

完全二叉树按层编号 1..n，编号 i 的孩子是 2i 和 2i+1。度为 1 的结点若存在，只能是编号 ⌊n/2⌋ 的最后一个分支结点，且只可能"有左孩子、缺右孩子"——它若缺的是左孩子，左孩子编号 2i 比右孩子 2i+1 更小却不存在，违背按层连续填放的规则。于是：n 为奇数时 n1 = 0；n 为偶数时编号 n 恰是某个结点的左孩子，n1 = 1。

第三步：本题求解

768 是偶数 ⇒ n1 = 1。代入 n0 + n1 + n2 = 768 与 n0 = n2 + 1：2·n2 + 2 = 768，n2 = 383，n0 = 384。

第四步：编号法复核（第二层对号入座）

叶结点恰为编号 ⌊768/2⌋ + 1 = 385 到 768 的结点，共 768 − 384 = 384 个；编号 384 的结点左孩子（768 号）存在、右孩子（769 号）越界不存在——这正是 n1 = 1 在这棵树上的具体模样。

易错点

  • 漏用奇偶性：令 n1 = 0 会得到 2·n2 + 1 = 768，无整数解——方程无解本身就是"n1 必为 1"的信号。
  • 编号法差一：叶子从 385 号开始数；把 384 号（它是分支结点）也算进去会误选 D（385）。
记忆锚点：n0 = n2 + 1 靠数边两步推得；完全二叉树 n 为偶 ⇒ n1 = 1（最后一个分支结点只缺右孩子）。

答案：C

本题讲解：前序+后序能否唯一确定中序

答案：C（中序 3, 2, 4, 1 不可能）。

第一步：从两个序列里榨出全部信息

前序首 = 后序尾 = 根，故 根为 1。前序中根之后的 2, 3, 4 与后序中根之前的 4, 3, 2 是同一批结点，但前序、后序都无法区分左右子树的划分——划分要靠中序来定。检验方法：给定某个中序后，用「前序定根、中序分左右、后序验形」逐层还原，出现矛盾即为不可能。

第二步：逐项还原检验（都以 {2,3,4} 为根 1 的一侧子树，前序 2,3,4、后序 4,3,2）

  • A（1,2,3,4）：1 无左子树；右子树 {2,3,4} 根为 2，中序拆出左空、右 {3,4}，3 的右孩子是 4——右斜链，后序 4,3,2 吻合，可能。
  • B（2,3,4,1）：{2,3,4} 全在 1 的左子树，其根为 2；中序拆出左空、右 {3,4}（右斜链 2→3→4），后序 4,3,2 吻合，可能。
  • C（3,2,4,1）：左子树 {2,3,4} 根为 2，中序拆出左 {3}、右 {4}，则该子树后序应为 3,4,2；但实际后序是 4,3,2，矛盾，不可能。
  • D（4,3,2,1）：{2,3,4} 全在左，2 的左子树 {3,4}、3 的左孩子 4——左斜链 1←2←3←4，中序 4,3,2,1 吻合，可能。

第三步：结论

A、B、D 都能还原出与两个遍历序列吻合的二叉树，只有 C 的左子树后序对不上，选 C。

易错点

  • 以为前序+后序可唯一确定二叉树：只有在每个结点都有 0 或 2 个孩子（不存在度 1 结点）时才能唯一；本题的树有度 1 结点，所以中序有多种可能，题目正是考这一点。
  • 还原时忘记验后序：只检查中序与前序不冲突就判「可能」，会漏掉 C 这种中序能拆、后序对不上的情形。
记忆锚点：前序定根、中序分左右、后序验形——三序齐全才敢下结论。

已知一棵有2011个结点的树，其叶结点个数为116，该树对应的二叉树中无右孩子的结点个数是。

答案

答案：D

▶本题解析视频（B 站）
6

本题讲解：树转二叉树后无右孩子的结点数

答案：D（1896）。

第一步：抓住转换规则

树（孩子-兄弟表示法）转二叉树：左指针指向第一个孩子，右指针指向右兄弟。于是「二叉树中无右孩子」⟺「该结点在原树中没有右兄弟」。

第二步：数清谁没有右兄弟

没有右兄弟的结点恰好有两类：

  • 根结点——全树唯一，永远没有兄弟，转换后无右孩子，有 1 个；
  • 每个分支结点的最后一个孩子——兄弟链（第一个孩子 → 二弟 → 三弟 → …）上只有末尾那个孩子没有右兄弟。每个分支结点引出一条兄弟链，恰好贡献 1 个，共 2011 − 116 = 1895 个（分支结点数 = 总结点数 − 叶结点数）。

两类不重叠（根没有父结点，不会出现在任何兄弟链上），故总数 = 1895 + 1 = 1896。

第三步：结论与验证

无右孩子的结点共 1896 个，选 D。小样例验证规律：根带 3 个孩子 A、B、C，A 又有 2 个孩子 a1、a2（共 6 结点、4 叶、2 个分支结点）。转换后逐个检查：根 ✓（无兄弟）、C ✓（兄弟链的末尾）、a2 ✓（A 的孩子的末尾），而 A、B、a1 都有右兄弟（右孩子）✗——无右孩子的共 3 个，恰为分支结点数 2 + 根 1，与本题「1895 + 1」同构，规律成立。

易错点

  • 漏掉根结点：只数「最后一个孩子」得 1895，误选 C——根没有兄弟，转换后也没有右孩子。
  • 把叶结点当主角：116 个叶结点与「无右孩子」没有直接对应关系——叶结点也可能有右兄弟（如上例中 a1 是叶却有右兄弟），干扰项 A、B（115、116）正是往这个方向误导。
记忆锚点：孩子-兄弟转换中，无右孩子 = 根 + 每个分支结点的最后一个孩子。

图的基本概念图的存储及基本操作图的应用
选择题 2 分

下列关于图的叙述中，正确的是。
Ⅰ. 回路是简单路径
Ⅱ. 存储稀疏图，用邻接矩阵比邻接表更省空间
Ⅲ. 若有向图中存在拓扑序列，则该图不存在回路

答案

答案：C

▶本题解析视频（B 站）
8

本题讲解：图的三条论断辨析

答案：C（仅Ⅲ正确）。

第一步：逐条独立判断

Ⅰ.「回路是简单路径」——错。 简单路径要求序列中顶点不重复；回路（环）的第一个顶点与最后一个顶点相同，顶点必有重复，所以回路不是简单路径。可以说「回路是简单回路（除首尾外顶点不重复）」，但不能说它是简单路径。

Ⅱ.「存储稀疏图，用邻接矩阵比邻接表更省空间」——错，说反了。 邻接矩阵无论边多边少都要存 n² 个元素（大量 ∞/0 是死重）；邻接表的空间约为 O(n+e)。稀疏图 e ≪ n²，邻接表才省空间；邻接矩阵适合存储稠密图。

Ⅲ.「若有向图中存在拓扑序列，则该图不存在回路」——对。 拓扑排序每步要挑一个入度为 0 的顶点；图一旦有环，环上顶点入度永远不为 0，排序必然中途卡死。所以「存在拓扑序列 ⟺ 图无环（是 DAG）」。

第二步：组合选项

只有 Ⅲ 正确，选 C。

易错点

  • 把「回路」与「简单回路」混淆：回路只要求首尾相接，顶点可重复（如 v1→v2→v1）；简单回路才额外要求中间顶点不重复。
  • 稀疏/稠密与存储结构记反：边稀疏选邻接表、边稠密选邻接矩阵，判断依据是空间 O(n+e) 对 O(n²) 的对比。
记忆锚点：有向图无环 ⟺ 存在拓扑序列；回路 ≠ 简单路径；稀疏图省空间靠邻接表。

散列（Hash）表
选择题 2 分

本题讲解：提高散列表查找效率的措施

答案：D（仅Ⅱ、Ⅲ正确）。

第一步：先弄清效率由什么决定

散列查找的比较次数取决于冲突发生的多少：散列函数越均匀（冲突少）、冲突处理越不产生堆积（堆积少）、表越空（装填因子小），平均查找长度越短。

第二步：逐条判断

  • Ⅰ. 增大装填（载）因子——错。 装填因子 α = 表中填入的记录数 ÷ 表长。α 越大表越满，新元素撞上已有元素的概率越高，冲突越多，查找越慢。想提高效率应当适当减小 α，Ⅰ 方向完全反了。
  • Ⅱ. 设计冲突（碰撞）少的散列函数——对。 散列函数越均匀，关键字越分散地映射到各地址，冲突越少，查找时比较的次数越少。这是提高效率的根本手段之一。
  • Ⅲ. 处理冲突时避免产生聚集（堆积）现象——对。 以线性探测为例：非同义词之间会「抢地址」，形成连续占用块（堆积），后续任何散列到这块附近的元素都要一路探测过去，比较次数暴涨。换用二次探测、链地址法等避免堆积，能显著缩短查找路径。

第三步：组合选项

Ⅱ、Ⅲ 正确，选 D。

易错点

  • 记反装填因子的影响：α 越小表越空、冲突越少；α 越大冲突越多。Ⅰ 正是利用「增大 α」设的陷阱。
  • 忽视堆积的代价：堆积让非同义词也互相干扰，查找长度远超同义词冲突本身，是散列效率的第二大杀手。
记忆锚点：散列效率三板斧——散列函数均匀、处理冲突不堆积、装填因子适当小。

  • CF（进位/借位）：无符号减法不够减（A < B）时必须向更高位借位，CF 置 1；够减（A ≥ B）则 CF = 0。所以 CF = 0 ⟺ A ≥ B——这就是"减法判大小"的原理，也是无符号比较不用 SF/OF 的原因；
  • ZF（零标志）：差为 0（A = B）时置 1。CF = 0 只保证"A ≥ B"，要挑出严格大于，还须排除相等这一种。

两者合并：大于 ⟺ CF = 0 且 ZF = 0，写成表达式即 (CF + ZF) 取反 = 1——正是选项 C。

第二步：三种情形对号入座

比较结果CFZF(CF+ZF) 取反转移？
A > B（够减、差非零）001转移
A < B（不够减，借位）100不转移
A = B（差为零）010不转移

第三步：为什么不用 SF 和 OF

SF 记结果的符号位、OF 记带符号运算是否溢出，只有把操作数当带符号数解释时它们才有意义。无符号数没有"符号"概念，大小全凭借位与零这两个标志判定——混入 OF 的 A、混入 SF 的 B 和 D 方向就错了。

易错点

  • 漏掉 ZF：只写"CF = 0"会把 A = B 也误判为"大于"——大于必须排除相等。
  • 带符号、无符号标志混用：SF、OF 服务于带符号比较（如 jg 一类指令），CF、ZF 服务于无符号比较，两套体系不能混搭。
记忆锚点：无符号大于 = 无借位且非零 = CF 与 ZF 全 0 = "(CF + ZF)" 取反为 1。

答案：D（进程 P 中某线程的栈指针）。同一进程内的线程共享进程级资源，但每个线程私有自己的栈和寄存器组（含栈指针），否则无法独立并发执行。

第一步：回忆线程的共享/私有清单

  • 共享（进程级）：代码段、数据段/全局变量、堆、打开的文件、信号等。
  • 私有（线程级）：线程控制块 TCB、寄存器组（程序计数器、栈指针等）、独立的用户栈。

第二步：逐项判断

选项资源类别结论
A 进程 P 的代码段进程级共享各线程执行同一份代码

C 进程 P 的全局变量数据段共享全局区对所有线程可见

第三步：为什么栈必须私有

线程是独立调度和执行的基本单位：函数调用、局部变量都压在各自的栈里，栈指针指示当前栈顶位置。若栈指针被多线程共享，两个线程同时压栈/退栈会互相破坏调用现场，线程就无法独立运行了。

易错点

  • 误选 C：全局变量在数据段，恰恰是线程间通信最常用的共享区。

确认号 ack 的语义是"期望对方发来的下一个字节序号"：某样东西要被确认，就必须在序号空间里占一个位置。SYN 虽不携带数据，但它本身是要被对方确认的"事件"，所以规定 SYN = 1 的报文段消耗一个序号（FIN 同理）。于是"我确认了你的 SYN"只能表达为 ack = 对方 seq + 1——这就是本题确认号的全部来源。

int M_Search(int A[], int B[], int n) {
    // 分别本轮搜索中A、B的起始位置和结束位置
    int start1 = 0, end1 = n - 1, start2 = 0, end2 = n - 1;
    // 分别本轮搜索中A、B的中位数
    int m1, m2;
    // 直到一个数组被遍历完
    while (start1 != end1 || start2 != end2) {
        m1 = (start1 + end1) / 2;
        m2 = (start2 + end2) / 2;
        // 满足情况(1)
        if (A[m1] == B[m2])
            return A[m1];
        // 满足情况(2)
        if (A[m1] < B[m2]) {
            // 考虑奇偶为保证子数组元素个数相同
            if ((start1 + end1) % 2 == 0) {
                start1 = m1;
                end2 = m2;
            } else {
                start1 = m1 + 1;
                end2 = m2;
            }
        }
        // 满足情况(3)
        if (A[m1] > B[m2]) {
            // 考虑奇偶为保证子数组元素个数相同
            if ((start1 + end1) % 2 == 0) {
                end1 = m1;
                start2 = m2;
            } else {
                end1 = m1;
                start2 = m2 + 1;
            }
        }
    }
    // 返回较小的
    return A[start1] < B[start2] ? A[start1] : B[start2];
}

本题讲解：等长升序序列的中位数（折半舍弃法）

第 1 问：算法的基本设计思想

分别取当前两个等长升序子序列 A′、B′ 的中位数 a 和 b（各取第 ⌈n/2⌉ 个元素，n 为当前子序列长度）：

  1. 若 a = b，它就是两序列全体元素的中位数，直接返回；
  2. 若 a < b，中位数只可能更大：舍弃 A′ 最前面的 ⌊n/2⌋ 个元素和 B′ 最后面的 ⌊n/2⌋ 个元素；
  3. 若 a > b，对称地：舍弃 A′ 最后面的 ⌊n/2⌋ 个元素和 B′ 最前面的 ⌊n/2⌋ 个元素。

（谁留谁丢有讲究：较大的中位数每轮都保留，较小的中位数只在长度为奇数时保留——为什么，见下面的三个"为什么"。）

每轮两个子序列长度都减半且仍等长，重复上述过程；当两个子序列各剩一个元素时，取两者中较小者即为所求中位数。

这套"比一比、丢一半"为什么不会丢掉真答案？把最可能追问的三个"为什么"提前答掉：

  • 为什么 a < b 就敢丢 A′ 前半段、B′ 后半段？ 全局中位数 m 一定被夹在 [a, b] 之间：严格小于 a 的元素，A′ 里只有"中位数以前"那半段，B′ 里也至多"中位数以前"那半段（它们都 < b），两侧合计至多 n−1 个，而第 n 小的 m 前面必须排满 n−1 个元素，故 m ≥ a；对称地 m ≤ b。于是被丢的 A′ 前 ⌊n/2⌋ 个都严格小于 a ≤ m，被丢的 B′ 后 ⌊n/2⌋ 个都严格大于 b ≥ m——全都不可能是 m。
  • 为什么较大的中位数每轮必留、较小的看奇偶？ m 可能恰好等于某个中位数（样例第 3 轮的 11 就是被保留的那个），丢掉它答案就没了。长度为奇数时两个中位数的内侧恰好各隔 ⌊n/2⌋ 个元素，丢半伤不到它们，都保留；长度为偶数时较小中位数内侧只有 ⌊n/2⌋−1 个元素，要两侧丢得一样多就得把它捎上（对应代码 start1 = m1 + 1 / start2 = m2 + 1）。此时丢它安全：严格小于它的元素两侧合计至多 n−2 个，它的名次到不了第 n；可能等于 m 的较大中位数已被保留。
  • 为什么"等长"是前提？ 整个算法依赖"每轮两侧丢弃个数相等、剩余长度仍相等"，m 的位置关系才逐轮保持；一旦不等长，⌊n/2⌋ 的对称舍弃就错位了——这正是易错点第一条的根源。

收尾为什么取较小者：两序列各剩 1 个时全体只剩 2 个元素，中位数是第 ⌈2/2⌉ = 1 小的那个——正是两者中较小的。

第 2 问：算法实现要点（C/C++）

用四个下标变量维护两个「子序列」：start1, end1, start2, end2，中位数下标取 m1 = (start1 + end1) / 2、m2 = (start2 + end2) / 2。关键语句：

  • 循环条件 while (start1 != end1 || start2 != end2)：两序列各剩一个元素时退出；
  • if (A[m1] == B[m2]) return A[m1]; ——情况 1 直接命中；
  • a < b：奇偶要区分——(start1 + end1) % 2 == 0（长度奇数）时 start1 = m1（中位数保留），否则 start1 = m1 + 1；同时一律 end2 = m2（b 保留在 B′ 尾部）；
  • a > b：对称——长度奇数时 end1 = m1、start2 = m2，长度偶数时 end1 = m1、start2 = m2 + 1；
  • 循环结束后 return A[start1] < B[start2] ? A[start1] : B[start2]; 取较小者。

第 3 问：时间复杂度与空间复杂度

每轮循环两个子序列长度同时减半，共 O(log₂n) 轮、每轮 O(1) 次比较：时间复杂度 O(log₂n)；只用常数个下标辅助变量，未搬动任何元素：空间复杂度 O(1)。

易错点

  • 舍弃后不等长：长度为奇数时若把中位数也丢掉（start1 = m1 + 1 一刀切），两个子序列长度不再相等，后续 ⌊n/2⌋ 舍弃会错位——必须按 (start + end) % 2 区分奇偶，保证中位数留在保留侧。
  • 收尾取错方向：两序列各剩一个元素时应取较小者，不是任取或取平均。
  • 混淆「第 ⌈L/2⌉ 个」的下标：L 个元素的升序序列中位数下标是 ⌊(start+end)/2⌋，与参考代码一致。
结论：等长中位数用「比中位数、舍两半」——每轮等长减半，O(log₂n) 时间、O(1) 空间，是本题的最优解法。

本题讲解：8 位机上的无符号/带符号加减运算（综合题）

第 0 步：先立机制——8 位寄存器是"模 256"的世界，位模式 ≠ 数值

三句话把四个小问全部打通：

  1. 位模式与解释是两回事：8 位共 256 个状态，unsigned int 读成 0~255，int（补码）读成 −128~127。赋值 int m = x 只是原样复制 8 个位，机器不做任何数值换算——变的只是解释方式。
  2. 加减硬件只做模 256 加法：加法照加，第 9 位进位自然丢弃；减法等于加上减数在模 256 下的相反数（补数）。无符号、补码都活在同一套规则下。
  3. 溢出是解释层面的报警：位模式照样产生，只是真值超出了当前解释方式的表示范围，读回的数不再是算术上的和/差。

第 1 问：R1、R5、R6 的内容（十六进制）

先把 x、y 装入寄存器（8 位二进制）：

  • x = 134 = 1000 0110B = 86H → R1；
  • y = 246 = 1111 0110B = F6H → R2。

无符号加减在 8 位机上是模 256运算（超出 8 位的进位自然丢弃）：

  • R5：z1 = x − y = 134 − 246 = −112，按模 256 加 256 回到 144 = 1001 0000B = 90H；
  • R6：z2 = x + y = 134 + 246 = 380，380 − 256 = 124 = 0111 1100B = 7CH。

寄存器只存 8 位结果，进位丢弃，内容分别为 90H、7CH。

为什么"±256"是合法操作？ 这是模运算的定义在兜底：8 位只有 256 个状态，−112 与 144 在模 256 下是同一个余数（−112 ≡ 144 (mod 256)），380 与 124 同理。从"数学和/差"落到"寄存器内容"，就是除模取余——加一次或减一次模即可。

第 2 问：m 与 k1 的值（十进制）

  • m = x：为什么 m 不等于 134？ 赋值只复制位模式（第 0 步机制 1）：m 的 8 个位与 x 完全相同，都是 86H，但 m 按 int（补码）解释——补码按权展开时最高位的权重是 −128，1000 0110 = −128 + 4 + 2 = −122；
  • n = y：F6H = 1111 0110 = −128 + 118 = −10；
  • k1 = m − n = −122 − (−10) = −112。

机器上用补码加法做：k1 = m + (−n 的补码) = 1000 0110 + 0000 1010 = 1001 0000，仍是 90H，按补码解释即 −112，未溢出。

第 3 问：四种运算能否共用一个加法器

能。 无论无符号还是补码表示的带符号整数，加减法在机器里都归结为按模的加法：n 位加法器天然就是一个"模 2ⁿ 加法器"，第 n 位进位本来就是要丢弃的余数部分。减法为什么能变成加法？因为在模 2ⁿ 下"减 b"等价于"加 −b"，而 −b 的编码恰好是"按位取反加一"——一套加法器加一条取反通路就齐了。四种运算共用这套电路，区别只在结果的解释方式和溢出/进位判断标准，不在电路本身。本题就是铁证：R6（z2）与 k2 的位模式同为 7CH——同一次模 256 加法，无符号侧读出 124、记下进位 CF=1；带符号侧读出 +124、但真值 −132 越界，溢出标志 OF=1。

第 4 问：带符号溢出的判断与本题的溢出语句

判断方法（两种等价）：

  1. 两个操作数符号相同而结果的符号不同 → 溢出；
  2. 次高位向最高位的进位 ≠ 最高位向前的进位 → 溢出。

为什么"两个进位不同"就等于溢出？ 次高位的进位是数值部分算出来、要送进符号位的进位；最高位的进位是符号位算完要丢出寄存器的进位（模运算里它本来就该丢）。两者一致时，数值部分没有"越权"改写符号位，真值落在 [−128, 127] 内；一旦两者不同，说明数值部分的进位把符号位顶翻了，真值必然越界。方法 1 是方法 2 的现象版：符号被顶翻，恰好表现为"同号相加得异号"。

逐条检查带符号运算：

  • k1 = m − n：两操作数符号相异（−122 与 −10 相减转化为 m + 10，一正一负），不可能溢出，结果 −112 在 8 位补码范围 [−128, 127] 内；
  • k2 = m + n：两操作数同为负（−122 与 −10），真值和为 −132 < −128，超出范围 → 溢出。机器过程：1000 0110 + 1111 0110 = 1 0111 1100，最高位进位 1、次高位进位 0，两者不同；且结果符号位变 0（"负 + 负 = 正"），按补码解释为 +124，与真值 −132 不符。

易错点

  • R5 漏加模：134 − 246 的"真值"是负的，但寄存器内容按模 256 折回，是 90H 而不是"−112H"。
  • m 直接写 134：m 是 int，把 86H 重解释为补码才是 −122。
  • 漏判 k2：只看到 k1 不溢出就以为带符号运算都没事；负 + 负得"正"（124）正是双同号溢出的典型特征。
一句话：模 256 下 z1 = 90H、z2 = 7CH；补码重解释 m = −122、k1 = −112；同模加法电路可通吃四种运算；溢出看"同号得异号/双进位不同"，本题只有 k2 = m + n 溢出。

本题讲解：虚拟地址 → 物理地址 → Cache / TLB 全链路（综合题）

第 0 步：先立机制——一次访存要过三道关卡

把整条链路想成一趟"翻译 + 缓存"的流水线，四个小问全挂在这条链上：

  1. 分页翻译（虚→实）：虚拟地址 = 虚页号（高位）+ 页内偏移（低位）。页是搬动单位，一个虚页整页搬进某个主存页框，页内第几个字节的相对位置原封不动——所以偏移不参与翻译、原样拼接，页表只负责把虚页号换成页框号。
  2. 直接映射 Cache（用物理地址访问）：主存每块只能"对号入座"到固定一行。地址从低位起分三段：块内地址定块内第几个字节，行号定进哪一行，标记 tag 定这一行缓存的究竟是不是这一块——行号只负责选行，命中与否全看 tag 比较的结果。
  3. TLB（页表的缓存）：四路组相联 = 组间直接映射 + 组内全相联——虚页号低位定组号（对号入座到组），高位做 tag（组内逐项比较），有效位说明这项映射可用。

第 1 问：虚拟/物理地址各几位，页号取哪几位

位数由空间大小直接决定：16MB = 2²⁴ → 虚拟地址 24 位；1MB = 2²⁰ → 物理地址 20 位。页内偏移两边必须同宽：页大小 4KB = 2¹² → 低 12 位是偏移。于是虚页号 = 24 − 12 = 12 位（高 12 位），页框号 = 20 − 12 = 8 位（高 8 位）。

地址位数高位字段低位字段
虚拟地址24虚页号 12 位页内偏移 12 位
物理地址20页框号 8 位页内偏移 12 位

（为什么页框号恰好是 8 位：偏移 12 位在翻译前后不变，剩下的位数自然全给页框号——20 − 12 = 8，不是另算的一项。）

第 2 问：物理地址的三段划分

从低位起分：块大小 32B = 2⁵ → 块内地址 5 位（第 4~0 位）；8 行 = 2³ → Cache 行号 3 位（第 7~5 位）；剩下的高位全部归 tag → 主存字块标记 12 位（第 19~8 位）。

为什么必须从低位起分？块内偏移的粒度是字节，必须贴着最低位；行号要把所有主存块均匀分到 8 行，紧挨着块内地址；再往高的所有位统一交给 tag 做身份比较。把中间 3 位叫"Cache 字块标记（3 位）"是不准确的——它是行索引，用来选行；标记（tag）是高 12 位。

第 3 问：虚拟地址 001C60H 的完整查访

  1. 拆分：高 12 位 = 虚页号 001H，低 12 位 = 偏移 C60H；
  2. 查页表：虚页 001 的表项有效位 = 1，页框号 = 04H → 页面已调入主存；
  3. 拼物理地址：页框号 04H 顶到高位、偏移 C60H 原样放低位（第 0 步机制 1）→ 04C60H；
  4. 拆 Cache 地址：04C60H = 0000 0100 1100 0110 0000 → tag = 04CH，行号 = 011（第 3 行），块内 = 0；
  5. 比命中：第 3 行有效位为 1，但行内标记 = 105H ≠ 04CH → Cache 不命中。

有效位为 1 为什么还不命中？ 有效位只说明"这行装了东西"，tag 才说明"装的是谁"——第 3 行缓存的是主存标记 105H 那一块，而要找的是 04CH 块；直接映射下同一行两块只能轮流入住，此刻坐在里面的不是它。

第 4 问：虚拟地址 024BACH 查 TLB

  1. 虚页号 = 024H（偏移 BACH 不参与翻译）；
  2. TLB 共 8 项、四路组相联 → 组数 = 8 ÷ 4 = 2 组；组号取虚页号最低 1 位 = 0 → 查第 0 组；
  3. TLB 标记 = 虚页号其余 11 位：024H = 0000 0010 0100，去掉最低位 0，高 11 位 = 0000 0010 010 = 012H；
  4. 第 0 组中存在有效位为 1 且标记 = 012H 的表项（对应页框号 1FH）→ TLB 命中，虚页 024H 已映射到主存页框，页面在主存中，无需再访存查页表。

为什么组号只取最低 1 位、标记却有 11 位？ "组间直接映射"那 1 位已经把查找范围锁定到第 0 组，它不参与比较；组内是全相联，4 项逐个比标记——标记必须携带虚页号里除组号以外的全部信息，所以是 12 − 1 = 11 位。

易错点

  • 页号位数另起炉灶算：页号位数 = 地址位数 − 页内偏移位数（24−12、20−12），不存在"再减一"或"再加一"。
  • Cache 字段从高位起分：顺序只能从低位起——块内 5 位、行号 3 位、标记 12 位；行号是用来"选行"的索引，不是标记。
  • 把有效位当命中：有效位 1 且 tag 相等才叫命中，缺一不可——第 3 问的陷阱正设在这里。
  • TLB 组号用整个虚页号：2 组时组号只占虚页号最低 1 位，其余 11 位是 TLB 标记；组号那一位不参与比较。
一句话：24 位虚地址高 12 位查页表（001H → 04H），偏移不变拼出 04C60H；Cache 按"块内 5 + 行号 3 + 标记 12"拆开，第 3 行标记 105H ≠ 04CH 不命中；024BAC 的虚页 024H 在 TLB 第 0 组（标记 012H）命中，页面在主存。

本题讲解：银行叫号问题——互斥与同步的信号量设计

这是"生产者—消费者"的变体：顾客生产"等待服务的顾客"，营业员消费之；10 个座位是缓冲区容量；取号机是被竞争使用的临界资源；叫号是一对一的同步关系。答题框架：先列信号量及初值，再写两个进程的 P/V 序列，最后说明顺序理由。

第一步：确定信号量及初值

信号量初值含义
mutex1互斥使用取号机，一次仅允许一位顾客取号
empty10空座位数，限制同时等待的顾客不超过 10 人
full0已占座位数，即等待服务的顾客数
service0叫号同步信号，营业员叫号后唤醒一位顾客

第二步：顾客进程——先占座、再取号、等叫号

  1. P(empty)：没有空座位就在门外等，不进等候区；
  2. P(mutex)；从取号机获取号码；V(mutex)：取号动作互斥完成；
  3. V(full)：通知营业员"多了一位等待的顾客"；
  4. P(service)：等待叫号，被叫到才获取服务。

process 顾客 i { P(empty); P(mutex); 从取号机获取号码; V(mutex); V(full); P(service); 获取服务; }

第三步：营业员进程——等顾客、放座位、叫号

  1. P(full)：没有等待顾客就休息，有则请一位；
  2. V(empty)：该顾客离开等候区，空出一个座位；
  3. V(service)：叫号，唤醒对应顾客；
  4. 为顾客服务，循环往复。

process 营业员 { while(TRUE) { P(full); V(empty); V(service); 为顾客服务; } }

第四步：顺序为什么不能乱

  • P(empty) 必须在 P(mutex) 之前：先确保有座位再去碰取号机，否则占着取号机却因无座位阻塞，其他顾客也无法取号；
  • 顾客的 V(full) 必须在自己的 P(service) 之前：先"挂号"再等叫号，若先 P(service) 后 V(full)，营业员可能叫号时还没有登记在等的顾客（丢失信号）；
  • P/V 必须成对出现：mutex 的 P 和 V 只夹住"取号"这一小段临界区。

易错点

  • 漏掉 service 信号量：只写 mutex、empty、full 无法实现"叫到号才服务"的一对一同步。
  • empty 初值写成 0：空座位数初值是 10，full（等待顾客数）才是 0。
  • 营业员先 V(service) 后 P(full)：顺序颠倒会叫到不存在的顾客。
框架记忆：empty/full 对应容量为 10 的缓冲区，mutex 互斥取号机，service 实现一对一叫号同步。

本题讲解：一次性写入文件系统的分配方式与 FCB 组织

先抓题干三个关键词：一级目录结构、数据一次性写入、写入后不可修改（但可多次创建新文件）。每一个结论都要能从这三个条件推出来。

第（1）问：选哪种数据块组织方式，FCB 设计哪些字段

  1. 连续分配方式最合适。文件一次性写入后不再修改、不再增长，连续分配就不存在"追加需预留空间、插入删除要移动数据"的缺陷；10 个块连续存放，顺序读取时磁头几乎不用寻道，定位第 i 块也只需一次计算（起始块号 + i），顺序与随机访问效率都最高。
  2. 链式分配随机访问要从头沿链逐块查找，效率低；索引分配要多读一次索引块，且是为"文件可动态增长"设计的——本题文件不可修改，用不上这些能力，反而多付代价。
  3. FCB 相关字段：位置固定、长度已知，只需设计起始块号与块数（或起始块号与结束块号/文件长度）即可定位全部数据块。

第（2）问：FCB 集中存储好，还是与文件数据块连续存储好

结论：集中存储更好。

  • 查找文件的过程是"先比对 FCB（如文件名），命中后再访问数据块"。FCB 集中存放在目录区，检索时可把多个 FCB 一次性读入内存逐个比较，磁头移动少、磁盘 I/O 次数少，文件检索快。
  • 若 FCB 与各自的数据块连续存放，逐个试探文件时每比较一个文件就要跳回数据区，磁头来回寻道，检索速度明显下降。

易错点

  • 第（1）问选索引分配：索引的优势是支持文件动态增长和快速随机访问，但本题"一次性写入、不可修改"恰恰用不到动态增长，多读索引块反而亏。
  • 第（1）问漏写字段：只写"起始块号"不够，必须同时给出块数（或结束块号）才能确定文件边界。
  • 第（2）问选与数据连续存放：只看到文件访问的局部性，忽略了"查找文件时要频繁比较多个 FCB"这一目录检索场景。
答题框架：条件（一次性写、不可改）→ 连续分配最优 → FCB 记起始块号 + 块数；FCB 集中存放可减少寻道与 I/O 次数、加快检索。

  2. 目的 IP 属于另一个网络，主机不能直接填服务器的 MAC——帧的目的 MAC 填的是默认网关的 MAC。从帧首部读出：00-21-27-21-51-ee。
  3. 区分：帧里的源 MAC 是本主机自己的 00-15-C5-C1-5E-28，别把两者填反。

（2）问：用什么协议确定目的 MAC

  1. 主机只知道下一跳（默认网关）的 IP 地址，要解析出对应的 MAC，用 ARP 协议：在本网络内广播 ARP 请求。
  2. ARP 请求是广播的，封装它的以太网帧目的 MAC 为全 1：FF-FF-FF-FF-FF-FF。

（3）问：持续非流水线方式需要多少 RTT

  1. 计时起点是"发出 Web 请求"（GET rfc.html），此时 TCP 连接已建立，不另计建连的 RTT。
  2. HTTP/1.1 持续连接 + 非流水线：收到前一个对象的响应后才能发下一个请求，每个对象独占 1 个 RTT。
  3. rfc.html 用 1 个 RTT；5 个 JPEG 小图逐个请求-响应，5 × 1 = 5 个 RTT。
  4. 合计 1 + 5 = 6 个 RTT。

（4）问：路由器 R 转发时修改 IP 分组头的哪些字段

  1. 源 IP 地址：主机用的是私有地址 10.2.128.100，出公网时被 R 改写为公有地址（NAT）。
  2. 生存时间 TTL：每经过一台路由器 TTL 减 1。
  3. 首部校验和：源 IP 与 TTL 都变了，IP 首部校验和必须重新计算。

注意题目只问 IP 分组头：以太网帧的源/目的 MAC 虽然每段链路都在换，但不属于 IP 头；传输层端口与校验和也不列入答案。

易错点

  • （1）把网关 MAC 当成服务器 MAC：MAC 地址只在一段链路内有效，跨网段的帧目的 MAC 永远是网关的。
  • （2）把两种"全 1"混为一谈：FF-FF-FF-FF-FF-FF 是 MAC 广播地址；IP 广播地址是 255.255.255.255，本题问的是帧的目的 MAC。
  • （3）多算成 7 个 RTT：多加了 TCP 建连的 1 个 RTT——题干起点已是"发出 Web 请求"。
  • （4）漏掉首部校验和：改了源 IP 和 TTL 却不重算校验和，分组会在下一跳被丢弃。
一句话结论：（1）64.170.98.32 与 00-21-27-21-51-ee；（2）ARP，FF-FF-FF-FF-FF-FF；（3）6 个 RTT；（4）源 IP（NAT 改写）、TTL 减 1、首部校验和重算。
