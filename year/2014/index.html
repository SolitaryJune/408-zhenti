选择题 2 分

下列程序段的时间复杂度是_。

count = 0;
for (k = 1; k <= n; k *= 2)
    for (j = 1; j <= n; j++)
        count++;
答案

答案：C

▶本题解析视频（B 站）
1

本题讲解：双层循环的时间复杂度（乘法法则）

答案：C，时间复杂度为 O(n log2 n)。

第一步：拆出每一层循环各自的执行次数

嵌套循环的总执行次数 = 外层次数 × 内层次数（乘法法则）。

外层：k 从 1 开始，每轮乘 2：k = 1, 2, 4, 8, …, 2^t。条件是 k <= n，所以执行次数是满足 2^t <= n 的最大 t 再加 1，即 log2 n 下取整 + 1 次，量级为 O(log2 n)。

内层：j 从 1 到 n 每轮加 1，固定执行 n 次，量级为 O(n)。

第二步：相乘并只保留最高阶

count++ 的总执行次数 ≈ n × (log2 n + 1) = n·log2 n + n。去掉常数和低阶项 n，只保留最高阶：O(n log2 n)。

用一个具体数验证：设 n = 16，外层 k 取 1,2,4,8,16 共 5 次，内层每轮 16 次，总 80 次 ≈ 16×4，与 n·log2 n 同量级。

易错点

  • 把两层循环相加：误写成 O(n + log2 n) 得 B。嵌套循环是"乘"不是"加"——外层每走一步，内层都要完整跑 n 次。
  • 只看外层：误选 A O(log2 n)，漏掉了内层循环的 n。
  • 看到两层循环就选 O(n^2)（D）：内层循环次数 n 与外层无关，但外层次数不是 n 而是 log2 n，不能机械套用"双层循环 = 平方"。
记忆锚点：循环变量乘 2（或除 2）地跳，循环次数就是 log2 n；嵌套循环复杂度 = 各层次数相乘。

队列
选择题 2 分

循环队列放在一维数组 A[0…M-1]中，end1 指向队头元素，end2 指向队尾元素的后一个位置。假设队列两端均可进行入队和出队操作，队列中最多能容纳 M-1 个元素。初始时为空。下列判断队空和队满的条件中，正确的是_。

答案

答案：A

▶本题解析视频（B 站）
3

本题讲解：循环队列的队空与队满判定

答案：A，队空 end1 == end2；队满 end1 == (end2 + 1) mod M。

第一步：把"元素个数"翻译成指针关系

题设：数组 A[0…M-1]，end1 指向队头元素，end2 指向队尾元素的后一位置。于是队列中的元素个数为

(end2 - end1) mod M

初始为空时两个指针重合，所以队空判定就是 end1 == end2——C、D 把队空写成"相差 1"，初始状态就不成立，直接排除。

第二步：队满为什么是"相差 1（取模）"

若允许放满 M 个元素，则放满时 end2 绕圈追上 end1，end1 == end2——与队空条件撞车，无法区分空和满。所以题目限定最多放 M-1 个元素（牺牲一格）。此时元素个数 = M-1，即

(end2 - end1) mod M = M - 1　⇔　end2 = end1 - 1 (mod M)　⇔　end1 = (end2 + 1) mod M

这正是 A 的队满条件。用 M=6 验证：5 个元素占 A[0..4]，end1=0、end2=5，(end2+1) mod 6 = 0 = end1，判满成立。

易错点

  • 选 B/D 的模数写错：下标范围是 0…M-1，模数只能是 M；写成 mod (M-1) 会让指针越界，B、D 均错。
  • 忘了牺牲一格：如果不限定 M-1 个元素，空与满都是 end1 == end2，条件失效——"牺牲一格区分空满"是循环队列的标准套路。
  • 指针含义记反：若 end2 指向队尾元素本身，队满条件会差一个位置；本题 end2 是"队尾后一位置"，才能得出"相差 1 即满"。
记忆锚点：end1 == end2 空；(end2 + 1) mod M 追上 end1 满；满时空出一格，正是空满互斥的代价。

序号123456
结点debxac

记忆锚点：先排中序序列，前驱=前一位、后继=后一位；树结构验证口径：左空找"右上挂的最近祖先"，右空找"左下挂的最近祖先"。

本题讲解：森林转二叉树后，叶结点个数对应什么

答案：C，F 中叶结点的个数等于 T 中左孩子指针为空的结点个数。

第一步：抓住转换规则

森林 → 二叉树用"左孩子、右兄弟"表示法：结点的左指针存放它在森林里的第一个孩子，右指针存放它的下一个兄弟。

森林 F：树1 为 A（孩子 B、C），树2 为 D（孩子 E）。转成 T 后：A 的左孩子 B、右孩子 D；B 的右孩子 C；D 的左孩子 E。

T 中的结点左指针右指针在森林 F 中的身份

B空C叶
C空空叶
DE空内部结点
E空空叶

  • 误选 A（T 的叶结点数）：T 的叶结点要求左右指针都空，对应森林中"无孩子且无下一兄弟"的结点（上例只有 C、E 两个），比 F 的叶结点少。

本题讲解：判断哪组编码不是前缀编码

答案：D，因为 110 是 1100 的前缀。

第一步：明确前缀编码的定义

前缀编码：任何一个编码都不是另一个编码的前缀。这样译码时从左往右扫描，每个码字读到哪里结束都不会产生歧义（哈夫曼编码天然满足）。判别方法就是两两比较：看短码是否恰好是某个长码的开头。

第二步：逐组检查

选项编码检查结果
A01, 0000, 0001, 001, 10000/0001/001 都以 00 开头、互不为前缀；01 不是任何码的开头；1 开头的只有它自己 → 是前缀编码
B011, 000, 001, 010, 1三个 3 位码 000/001/010 互不为前缀，011、1 也不做别人的开头 → 是前缀编码
C000, 001, 010, 011, 100等长编码，长度相同就谁也做不了谁的前缀 → 是前缀编码
D0, 100, 110, 1110, 1100110 恰好是 1100 的前 3 位 → 冲突，不是前缀编码

D 选项的冲突：收到码流 …1100…，译码器读完 110 就会判断出一个字符，而它其实可能是码字 1100 的开头——歧义就出在这里。

易错点

  • 只检查相邻两个码：前缀冲突可能出现在任意两个码之间，要两两比对（D 的冲突对是 110 与 1100）。
  • 以为"短码=1 位"才危险：本题只有 D 出问题，但起冲突的是 3 位码与 4 位码，不是单码 0——0 开头的码在 D 里并不存在。
  • 误以为等长编码特殊：等长（选项 C）天然互不为前缀，是前缀编码的特例。
记忆锚点：前缀编码 = 任何码字不做其他码字的"开头"；判别就是逐对找"短码是长码前缀"的冲突对。

选择题 2 分

用哈希（散列）方法处理冲突（碰撞）时可能出现堆积（聚集）现象。下列选项中，会受堆积现象直接影响的是。

答案

答案：D

▶本题解析视频（B 站）
8

本题讲解：哈希堆积（聚集）现象直接影响什么

答案：D，平均查找长度。

第一步：先弄清"堆积"是什么

用开放定址法（尤其线性探测）处理冲突时，若干非同义词也会争抢同一个后继地址：比如 hash(k1) 与 hash(k2) 本不冲突，但 k1 抢占了 k2 本该落的位置，把 k2 挤到更后面。这样探测序列越滚越长，"堆"成一片——这就是堆积（聚集）现象。

第二步：堆积的直接后果

查找或插入一个元素时，必须沿探测序列逐个比较，直到碰到空位或命中为止。堆积使探测序列变长 → 比较次数（探测次数）增多 → 而"查找时平均比较次数"正是散列表的平均查找长度（ASL）。所以受堆积直接影响的是 D。

第三步：逐项排除

  • A 存储效率：堆积只改变元素"落在哪一格"，表还是那张表、元素还是那些元素，存储效率不受直接影响。
  • B 散列函数：堆积由冲突处理方法（线性探测等）引起；散列函数一经选定就固定不变，堆积不会反过来改变它。
  • C 装填因子：装填因子 α = 表中记录数 ÷ 表长，由数据量和表长决定，与冲突怎么处理、堆积多严重无关。
  • D 平均查找长度：探测序列变长直接抬高 ASL，正确。

易错点

  • 误选 C：ASL 随 α 增大而增大、随堆积加剧而增大，两件事常被混为一谈；但"堆积直接影响"的只有 ASL，α 本身是个比值，不因堆积而变。
  • 误选 B：堆积确实是"散列性能变差"的表现，但它是探测再散列的副作用，不是散列函数被改变了。
记忆锚点：堆积 → 探测序列变长 → 比较次数变多 → 平均查找长度（ASL）变大。装填因子只看"元素数/表长"。

32 位定长指令字像一块蛋糕：每一位都必须派上用场，字段切完要正好用完。16 个通用寄存器 → 寄存器编号需要 4 位（2^4 = 16）。Store 指令的字段占用：

本题讲解：调度算法与饥饿现象

答案：A。时间片轮转调度不可能导致饥饿。

第一步：明确"饥饿"的判断标准

饥饿（starvation）指进程长期等不到处理机或所需资源而无法推进。判断一个调度算法会不会饥饿，就看它"挑下一个进程"的规则是否可能让某一类进程永远排不上队。

第二步：逐项分析

  • A 时间片轮转：就绪进程排成 FIFO 队列，人人轮流上一个时间片，排到就上处理机。任何进程的等待时间都有上界——队头迟早轮到自己 → 不可能饥饿。
  • B 静态优先数调度：优先级固定不变、不随等待时间升高。只要高优先级进程源源不断，低优先级进程可能一直被压住 → 可能饥饿。

  • D 抢占式短作业优先：更短的作业一到就抢占处理机，长作业被反复打断、一再推迟 → 更可能饥饿。

易错点

  • 认为"非抢占所以不会饥饿"：非抢占只保证正在运行的进程不被打断，不保证等待的进程会被选中，C 依然可能饥饿。
  • 混淆饥饿与死锁：饥饿的进程还在队列里等机会，只是轮不到；死锁是互相等待形成环路，谁都无法再推进。
一句话结论：时间片轮转按到达顺序轮流执行，等待时间有上界，不可能饥饿；凡按"优先级、长短"挑进程的算法都可能让某类进程永远排队。

本题讲解：求二叉树带权路径长度 WPL 的算法设计

先立机制：WPL 到底在算什么

WPL = 所有叶结点的（结点深度 × 权值）之和。它把"成本"拆成两半：权值存在叶结点里，深度却不存在任何结点里——深度等于从根走到该结点经过的边数，只随遍历过程"顺路"产生。所以本题的核心是：遍历走到哪儿，深度就得跟到哪儿。两条路线都能做到：

  • 先序递归：递归每下降一层，就给参数 deep 加 1 再传下去——深度天然"挂在"递归参数上；
  • 层次遍历：队列逐层出队，用 lastNode 哨兵标记"本层最后一个结点"，跨过它就把 deep 加 1。

有了这条主线，三问就是把它落实成代码。

第 1 问：算法基本设计思想

方法一（先序递归，推荐）：从根出发先序遍历，参数 deep 记当前结点深度，根为 0。访问到结点时：若是叶结点（左、右孩子均为空），把 deep × weight 累加进 wpl；否则递归左、右子树且 deep + 1。

  • 为什么深度能当参数传：树中结点的深度由"根到它的唯一路径"决定，先序递归正是沿这条路径走，每层递归调用对应路径上多走一条边——参数 deep 就是这条路径的长度，不需要任何额外存储。
  • 为什么只在叶结点累加：WPL 的定义只统计叶结点，内部结点的权值不计入。

方法二（层次遍历）：用队列逐层遍历，deep 记当前层数。为什么要 lastNode 哨兵：普通出队是一个"结点流"，队列里相邻两个出队结点可能属于不同层，光看出队顺序分不清层边界；让 lastNode 指向本层最后入队的结点，出队遇到它就说明本层走完，把它更新为本层出队期间最后入队的 newlastNode（即下一层最后一个），deep 加 1。遇到叶结点同样累加 deep × weight。

第 2 问：结点的数据类型定义

二叉链表结点只需"权值 + 左右孩子指针"两个字段族：

typedef struct BiTNode { int weight; struct BiTNode *lchild, *rchild; } BiTNode, *BiTree;

int wpl_PreOrder(BiTree root, int deep) 的逻辑：

  1. root == NULL 返回 0——空指针没有权值也没有深度，贡献为 0（同时防止空指针访问崩溃）；
  2. 左右孩子均为空（叶结点）时返回 deep * root->weight；
  3. 否则返回 wpl_PreOrder(root->lchild, deep+1) + wpl_PreOrder(root->rchild, deep+1)。

调用入口 WPL(root) = wpl_PreOrder(root, 0)。关键注释点：根深度为 0、仅在叶结点累加、递归下探时深度加 1。

本题讲解：Cache 命中率、异常判定与访盘/TLB 次数（按问展开）

先立机制：三种"资源账本"怎么记

本题在三套机制上记账，它们串成一条链：访存 → 查 TLB → 查页表 →（缺页才）读盘。

  • Cache 侧：取指/取数先看 Cache，命中与否取决于地址是否落在已调入的块里；
  • 虚存侧：取指和数据访存都要做"虚地址 → 物理地址"变换，页不在内存就触发缺页异常，由操作系统把页从磁盘调入；
  • TLB 侧：TLB 是页表项的缓存，每次地址变换都要用到它，查它决定变换走快路还是慢路。

条件：循环执行 N = 1000 次（(R6) = 1000），(R1) = (R2) = 0；机器代码已调入主存但不在 Cache 中；数组 A 未调入主存，所有元素在同一页、存放在磁盘同一扇区。

第 1 问：R2 的内容

R2 存循环变量 i，每轮加 1；bne 在 R2 ≠ R6 时跳回循环头，所以循环体恰好执行 1000 次——i 从 0 数到 1000 时与 R6 相等、退出循环。P 执行结束时 R2 = 1000（十六进制 3E8H）。

第 2 问：指令 Cache 数据区容量与命中率

  • 容量：数据区 = 行数 × 块大小 = 16 × 32 B = 512 B（标记位、有效位等不算在数据区内）。
  • 命中率分三步推导。第一步，24 B 代码落在哪个块：块大小 32 B → 地址低 5 位是块内偏移。起始地址 08048100H 的低 5 位为 0，恰好是某 32 B 块的块首；6 条指令占 08048100H ~ 08048117H 共 24 B ≤ 32 B，全部落在同一个块内。第二步，总共取指多少次：1000 轮 × 每轮 6 条 = 6000 次。第三步，缺多少次：题干明说"机器代码不在 Cache 中"，第 1 次取指必然缺失（并把整块调入）；此后整块都在 Cache 里，其余 5999 次全部命中。

命中率 = 5999 ÷ 6000 ≈ 99.98%。

第 3 问：异常与访盘、TLB 次数

  • 溢出异常 → 指令 4（add R1, R1, R5）。它是把 A[i] 累加进 sum 的加法：累加值随循环不断增大，可能超出机器数表示范围。为什么不是指令 2（add R4, R4, R3）：它算的是元素地址 = 首地址 + i × 4，最大不过"首地址 + 3999"，离 32 位补码的表示上限很远，不会溢出——会溢出的是数值累加，不是地址计算。
  • 缺页异常 → 指令 3（load R5, 0(R4)）。它是唯一访问数组 A 的访存指令，而 A 未调入主存，首次访问必然缺页。为什么取指不会缺页：题干说机器代码"已调入主存"，指令所在页常驻内存。
  • 读磁盘次数 = 1。缺页时调入的是整页；题干说 A 的所有元素在同一页且在磁盘同一扇区，一次 I/O 就把该页（该扇区）读了进来，之后 999 次访问都在内存完成。
  • TLB 次数 = 1001。TLB 初始为空：第 1 次取指查 TLB 1 次（缺失后把代码页的页表项装入，此后 6 条指令同页、取指直接命中）；每轮循环执行指令 3 取 A[i] 都要做一次虚实地址变换、查 TLB 一次，共 1000 次。合计 1 + 1000 = 1001 次。（官方口径：取指侧只计首次查表，数据访存侧每次都查。）

易错点

  • 命中率算成 100%：题干明说"机器代码不在 Cache 中"，第一次取指必然缺失，要计入 1 次。
  • 溢出写成指令 2：地址加法的上界很小不会溢出；可能溢出的是数值累加的指令 4。
  • 把读盘算成 1000 次：缺页调入的是整页，所有元素同页同扇区，一次 I/O 即可。
  • TLB 漏掉取指那 1 次：只算 1000 次 load 的地址变换，漏了 TLB 初始为空时第 1 次取指的查表。
记忆锚点：同块 24B 一次调块 → 5999/6000；溢出看数值累加、缺页看访存（取指不缺页因代码已调入）；同页同扇区读盘 1 次；TLB = 1 次首取指 + 1000 次取数变换。

本题讲解：连续/链接分配下插入一条记录（7 分）

先立机制：两种分配方式下"记录位置"从哪来

同一次插入，为什么在两种方式下代价天差地别？根源在于记录的位置怎么确定：

  • 连续分配：文件占据一段物理连续的磁盘块，第 k 条记录的位置 = 起始块号 + (k−1)——位置是算出来的。要在中间插一条，物理次序必须重排：要么后 171 条整体后移，要么前 29 条整体前移，没有第三条路。
  • 链接分配：块的物理位置任意，逻辑顺序靠块里的链接指针串起来——位置是顺着链走出来的。插入只需把新块"接"进链里、改两个指针，旧记录一块都不用挪。

题干特意强调"文件存储区域前后均有足够的空闲磁盘空间"，就是在提示：连续分配的两条路都通，选动得少的。

第 1）问：连续分配，最少访盘次数与 FCB 变化

步骤访盘次数
前 29 条各"读出 + 写回"前移一格29 × 2 = 58
新记录写入腾出的空位1

步骤访盘次数

本题讲解：多生产者多消费者 + "连续取 10 件"的信号量设计（9 分）

先立机制：这道题要管住哪两件事

生产者-消费者问题的底层是两类约束，各自对应一种信号量：

  • 同步（数量约束）：满不能放、空不能取。计数信号量天然匹配——empty 数空位、full 数产品；生产者 P(empty) 消耗一个空位，消费者 P(full) 消耗一个产品，谁的前提条件不满足，谁就在对应信号量上排队。
  • 互斥（一次一人）：缓冲区是共享数据结构，放入/取出必须原子完成 → 互斥信号量 mutex2，所有进程动缓冲区前先拿它。

本题在这两类之上多加一条规则："一个消费者必须连续取 10 件，期间其他消费者不得取"。这是消费者群体内部、以"10 件"为单位的更大粒度互斥——于是再立一把大锁 mutex1。两把锁分工明确：mutex1 管"轮到哪个消费者取"，mutex2 管"动缓冲区那一下的原子性"。

信号量一览（对号入座）

信号量含义初值
mutex1一个消费者连续取 10 件期间的互斥1
mutex2各进程单次互斥访问缓冲区1
empty缓冲区空位数（生产者的同步信号量）1000
full缓冲区产品数（消费者的同步信号量）0

生产者进程

  1. 生产一个产品;
  2. P(empty);——先等空位
  3. P(mutex2);——再申请缓冲区
  4. 把产品放入缓冲区; V(mutex2); V(full);

为什么 P(empty) 必须在 P(mutex2) 之前：反过来就是"抱着缓冲区锁等空位"——缓冲区满时生产者握着 mutex2 睡觉，而消费者必须拿到 mutex2 才能腾出空位，互相等待即死锁。先同步后互斥：等不到空位时手里没有锁，别人可以继续动缓冲区。

消费者进程（关键在 mutex1）

  1. P(mutex1);——拿到"连续取 10 件"的控制权，其他消费者在此排队
  2. 循环 10 次：P(full); → P(mutex2); → 从缓冲区取出一件产品; → V(mutex2); → V(empty); → 消费这件产品;
  3. V(mutex1);——10 件取完才释放，其他消费者才能开始

为什么 mutex1 要包住整个 for 循环：若放进循环体内，每取 1 件就放锁，其他消费者随时可以插进来，"连续 10 件"就被拆散了。

为什么持 mutex1 等产品不会死锁：mutex1 只拦其他消费者，生产者不需要它就能补货，产品迟早到位、P(full) 迟早通过。这也正是 mutex1 与 mutex2 必须分开的原因——若两把锁合一，取 10 件期间生产者被完全挡住，一旦缓冲区取空，消费者抱着唯一的锁等产品、生产者等锁，就僵死了。

易错点

  • 同步 P 写在互斥 P 之后：先 P(mutex2) 再 P(empty)，进程可能抱着缓冲区锁等空位而死锁。
  • 漏掉 mutex1：只有 mutex2 时每取一件就放锁，其他消费者可以插进来，"连续取 10 件"被破坏。
  • 把 mutex1 写进生产者：mutex1 只约束消费者之间；生产者只碰 empty、mutex2、full。
  • empty 初值写成 0 或 1：它是空位计数，初值 = 缓冲区容量 1000。
一句话结论：empty/full 管数量同步，mutex2 管单次互斥，mutex1 把"连续取 10 件"当一个整体锁起来——且 mutex1 不拦生产者，才能边取边补、不会死锁。
