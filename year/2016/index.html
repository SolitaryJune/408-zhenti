线性表的链式表示
选择题 2 分

已知表头元素为 c 的单链表在内存中的存储状态如下表所示。

现将 f 存放于 1014H 处并插入到单链表中，若 f 在逻辑上位于 a 和 e 之间，则 a、e、f 的“链接地址”依次是__。

答案

答案：D

▶本题解析视频（B 站）
1

本题讲解：单链表的“链接地址”与结点插入

答案：D（a、e、f 的链接地址依次为 1014H、1004H、1010H）。

第一步：弄清“链接地址”是什么

表中“链接地址”就是该结点 next 指针里存放的后继结点的地址，不是结点自己的存放地址。表头元素为 c，即逻辑上的第一个结点是 c。

第二步：从表头 c 顺链走，确定逻辑顺序

结点所在地址链接地址走到谁
c1008H1000Ha
a1000H1010He
e1010H1004Hb
b1004H100CHd
d100CHNULL结束

所以原逻辑顺序为 c → a → e → b → d。

第三步：把 f（1014H）插到 a 和 e 之间

新逻辑序应为 c → a → f → e → b → d，只需改两条指针：

  • a 的链接地址改为 f 的存放地址 1014H（原来指向 e 的 1010H）；
  • f 的链接地址填 e 的存放地址 1010H；
  • e 的链接地址不变，仍是 1004H（e 的后继还是 b）。

故 a、e、f 的链接地址依次为 1014H、1004H、1010H，选 D。

易错点

  • 把“链接地址”当成结点自身地址：例如以为 e 的链接地址是 1010H，其实那是 e 自己的存放地址，会误选 C。
  • 以为插入要改 e 的链接：f 插在 a、e 之间，e 的后继仍是 b，e 的指针动不到。
  • 不沿链接走、按地址顺序串：逻辑顺序必须靠“链接地址”逐个跳出来，按地址大小排会得到完全不同的序列。
口诀：链表插入只动两条链——前驱改指新结点，新结点指原后继，后继的指针不用动。

线性表的链式表示
选择题 2 分

已知一个带有表头结点的双向循环链表 L，结点结构为 [ prev | data | next ]，其中，prev 和 next 分别是指向其直接前驱和直接后继结点的指针。现要删除指针 p 所指的结点，正确的语句序列是__。

答案

答案：D

▶本题解析视频（B 站）
2

本题讲解：双向循环链表中删除 p 结点的语句序列

答案：D。

第一步：明确删除要达成什么

删去 p 之后，p 的前驱和后继要直接牵手：

  • p 的后继的 prev 域改成 p 的前驱；
  • p 的前驱的 next 域改成 p 的后继；
  • 最后释放 p。

第二步：写出正确的语句序列

  • p->next->prev = p->prev; —— 后继认前驱做前驱
  • p->prev->next = p->next; —— 前驱认后继做后继
  • free(p);

这正是选项 D。双向循环链表的“循环”不影响此处的改法：p 的前驱、后继无论是否表头结点，指针修改方式都相同。

第三步：找出干扰项错在哪

  • A：第一句正确；第二句写成 p->prev->next = p->prev —— 前驱的 next 指向它自己，p 的后继从此脱链。
  • B：第二句正确；第一句写成 p->next->prev = p->next —— 后继的 prev 指向它自己，向前方向断链。
  • C：两句全是“自己指自己”，链表双向都断裂。

易错点

  • 前驱后继记混：画“前驱 ⇄ p ⇄ 后继”三框图，按“删除后谁与谁相邻”逐条推，比死记可靠。
  • 赋值顺序顾虑：两条赋值都用 p 未释放前的值，先后顺序不影响结果；但必须都在 free(p) 之前完成。
  • 只改一个方向：双向链表要 next、prev 两个方向都接上，漏改一边链就断。
口诀：删 p = 让“后继的前驱”和“前驱的后继”都绕过 p。

本题讲解：火车调度——让递增驶出所需的最少轨道数

答案：C（4 条）。

第一步：认清每条轨道的性质

行进方向都是从左至右，车驶入一条轨道后只能继续向前驶出，所以每条轨道相当于一个队列（先入先出）。要让出口依次驶出 1~9，每条轨道里的车号必须递增排列。

驶入分配各轨道现状
8全空，进轨道 11:【8】
48 大于 4 接不上，新开轨道 22:【4】

第三步：证明 3 条不够

8、4、2、1 这四辆车依次驶入且号码递减。同一轨道先入先出，若其中任意两辆同轨，号码大的一定先驶出，与要求的递增出口矛盾——这四辆必须两两不同轨，所以至少 4 条轨道。结论：n 至少是 4，选 C。

  • 以为 9 号车要新开轨道：只要车尾 8 小于 9 就能接上，新开轨道只发生在“所有车尾都比当前车大”时（如 1 号车）。
  • 只会模拟不会证下界：找到“依次递减的子序列”长度，就是轨道数的下界，这一步常被漏掉。
记忆锚点：最少轨道数 = 驶入序列中最长递减子序列的长度（本题 8→4→2→1，长 4）。

本题讲解：三对角矩阵按行压缩存储的下标计算

答案：B（下标 87）。

第一步：认清三对角矩阵的形状

三对角矩阵只有 3 条对角线可能非零：第 i 行只有 m[i,i-1]、m[i,i]、m[i,i+1]。第 1 行缺左斜元素只有 2 个，第 100 行缺右斜元素只有 2 个，其余行每行 3 个。

第二步：数出第 30 行之前共有多少元素

按行优先依次压缩存放：

行元素个数
第 1 行2
第 2~29 行（共 28 行）每行 3 个，合计 84
合计86

即第 30 行之前的元素占据 N[0..85]。

第三步：在第 30 行内定位

第 30 行元素依次是 m[30,29]、m[30,30]、m[30,31]，目标 m[30,30] 排行内第 2 个，前面还要让出 1 个位置 → 下标 = 86 + 1 = 87（数组下标从 0 开始）。

  • 下标起点搞混：按“从 1 开始”计会得 88（C），再多算一次就成 89（D）。
  • 把第 1 行也当 3 个元素：前面元素会多数 1 个，全盘错位。
公式记忆（i 大于 1 时）：前 i−1 行共 3(i-1)-1 个，行内偏移 j-i+1，下标 = 两者之和（0 起）。

树森林
选择题 2 分

若森林 F 有 15 条边、25 个结点，则 F 包含树的个数是__。

答案

答案：C

▶本题解析视频（B 站）
5

本题讲解：由边数与结点数求森林中树的棵数

答案：C（10 棵）。

第一步：抓住树的边数恒等式

任何一棵树都满足：边数 = 结点数 − 1（除根外，每个结点都恰好对应一条来自父亲的边）。

第二步：推广到森林

森林 = 若干棵互不相交的树。对每棵树分别写“边 = 结点 − 1”，再相加：

森林总边数 = 森林总结点数 − 树的棵数

第三步：代入求解

树的棵数 = 25 − 15 = 10，选 C。

第四步：画图自检

两棵各有 3 个结点的树：结点共 6、边共 4，棵数 = 6 − 4 = 2，与公式一致。

易错点

  • 公式方向记反：写成“结点 = 边 − 1”会得到负数，说明方向反了。
  • 把森林整体又当一棵树：在 25 − 15 之后再多减 1 得 9（B），错在给森林“补了根”，森林不是树，没有这条 −1。
  • 无出处地凑数：D（11）= 25 − 15 + 1，多加的 1 没有任何依据。
记忆锚点：树是“边数 = 结点数 − 1”，森林是“棵数 = 结点数 − 边数”。

本题讲解：判断哪一个不是深度优先搜索序列

答案：D。

第一步：把图读成邻接表

从配图（有向图）读出各顶点的出边：

顶点能直接到达
V1V2, V3, V5
V2V5
V3V2
V4V3
V5V4

第二步：明确 DFS 的行进规则

从 V1 出发的深度优先搜索：每访问一个顶点，下一步只能沿它的出边走向一个尚未访问的邻接点；四周无未访问邻接点时才回溯。序列中相邻两顶点之间必须有边相连。

第三步：逐项检验

  • A：V1, V5, V4, V3, V2 —— V1→V5、V5→V4、V4→V3、V3→V2，步步有边，合法。
  • B：V1, V3, V2, V5, V4 —— V1→V3、V3→V2、V2→V5、V5→V4，步步有边，合法。
  • C：V1, V2, V5, V4, V3 —— V1→V2、V2→V5、V5→V4、V4→V3，步步有边，合法。
  • D：V1, V2, V3, V4, V5 —— V1→V2 可行，但 V2 的出边只有 V2→V5，V2 与 V3 之间没有边，DFS 不可能从 V2 直接访问 V3，非法。

（V3 只能由 V1 或 V4 进入，而 V4 又必须等 V5→V4 之后，所以 V1、V2 之后只能是 V5，那正是选项 C 的走法。）

易错点

  • 把 DFS 当成按编号顺序访问：DFS 严格沿边走，不按顶点编号推进，D 恰是这个误区。
  • 忽略边的方向：图里是 V3→V2、V5→V4，方向看反就会误判 D 合法。
  • 只查“有没有边”不查方向：无向图的序列检查与有向图不同，本题是有向图。
记忆锚点：判 DFS 序列，就逐对检查“相邻两顶点之间有没有方向正确的边”。

若将 n 个顶点 e 条弧的有向图采用邻接表存储，则拓扑排序算法的时间复杂度是__。

答案

答案：B

▶本题解析视频（B 站）
7

本题讲解：邻接表上拓扑排序的时间复杂度

答案：B（O(n+e)）。

第一步：回顾拓扑排序（入度法）的流程

  1. 求每个顶点的入度；
  2. 把所有入度为 0 的顶点压入栈（或队列）；
  3. 依次弹出顶点，把它的每条出边终点的入度减 1，减到 0 就入栈；重复直到栈空，输出次序即拓扑序列。

第二步：按邻接表逐项算开销

步骤操作开销
求入度完整扫一遍邻接表：n 个顶点表头 + e 条弧各看一次O(n+e)
建 0 入度栈检查 n 个顶点的入度值O(n)
主循环每个顶点出栈一次；每条弧只在它起点出栈时被处理一次O(n+e)

第三步：合计

三步相加：O(n) + O(n+e) + O(n+e) = O(n+e)，选 B。

易错点

  • 选 A（O(n)）：只盯着顶点进出栈，漏掉了“每条弧都要被检查一次”的松弛开销。
  • 选 C（O(n^2)）：这是邻接矩阵存储下的代价——矩阵中找一个顶点的出边要扫整行 n 次；邻接表恰好省掉了这一层。
  • 选 D（O(ne)）：拓扑排序中顶点与弧都是“各处理一次”，不存在双重嵌套扫描。
记忆锚点：邻接表下“顶点各一次、弧各一次” = O(n+e)；换成邻接矩阵才退化为 O(n^2)。

顺序查找和折半查找

在有 n（n>1000）个元素的升序数组 A 中查找关键字 x。查找算法的伪代码如下所示。

k = 0;
while (k < n 且 A[k] < x)
    k = k + 3;
if (k < n 且 A[k] == x)
    查找成功;
else if (k - 1 < n 且 A[k - 1] == x)
    查找成功;
else if (k - 2 < n 且 A[k - 2] == x)
    查找成功;
else
    查找失败;

本算法与折半查找算法相比，有可能具有更少比较次数的情形是__。

答案：B

▶本题解析视频（B 站）

本题讲解：步长为 3 的跳跃查找与折半查找的比较次数

答案：B（当 x 接近数组开头处）。

第一步：先算清两种算法各花多少次比较

折半查找：每比一次区间减半，n 大于 1000 时约需 log2(n) ≈ 10 次左右，且与 x 的位置关系不大。

本题算法：while 循环每轮比较一次 A[k] 与 x 并令 k 加 3；循环结束后最多再比较 A[k]、A[k-1]、A[k-2] 三次。设 while 跑了 t 轮，总比较次数约为 t + 3。t 由 x 的位置决定：x 越靠前 t 越小。

第二步：逐项估算

情形while 轮数 t总比较次数与折半（约 10 次）相比
x 接近开头0~1约 1~5 次更少

层号 j123…h
最多结点数1kk^2…k^(h-1)

（1）算法基本设计思想
要使两个子集元素个数差最小且和的差最大，应将最小的⌊n/2⌋个元素放入A₁，其余放入A₂。采用快速排序中的划分思想，基于枢轴进行划分，通过非递归方式逐步将数组划分为两部分，使得左半部分恰好包含最小的⌊n/2⌋个元素，右半部分包含剩余元素。最后分别计算两部分的和并返回其差值。

（2）算法描述（C语言）

int setPartition(int a[], int n) {
    int pivokey = 0, low = 0, low0 = 0, high = n - 1, high0 = n - 1, flag = 1, k = n / 2, i;
    int s1 = 0, s2 = 0;
    while(flag) {
        pivokey = a[low]; // 选择枢纽
        while(low < high) {
            while(low < high && a[high] >= pivokey) --high;
            if(low != high) a[low] = a[high]; // 替换较大的数
            while(low < high && a[low] <= pivokey) ++low;
            if(low != high) a[high] = a[low]; // 替换较小的数
        }
        a[low] = pivokey; // 完成交换枢纽
        if(low == k - 1) {
            flag = 0;
        } else {
            if(low < k - 1) {
                low0 = ++low;
                high = high0;
            } else {
                high0 = --high;
                low = low0;
            }
        }
    }
    for(i = 0; i < k; i++) s1 += a[i];
    for(i = k; i < n; i++) s2 += a[i];
    return s2 - s1;
}

（3）时间复杂度与空间复杂度

  • 平均时间复杂度：O(n)，期望线性时间完成划分。

第（1）问：算法基本设计思想

答题框架：先定个数，再定成员，最后选手段。

  • 手段：不必完整排序（O(nlogn) 不是最优），借用快速排序的一次划分——枢轴归位后若恰好落在下标 k-1，则 a[0..k-1] 就是全数组最小的 k 个数；若落在 k−1 左侧就到右段继续划分，落在右侧就到左段继续划分（非递归，只收缩区间），直到枢轴命中下标 k−1。最后分别累加两部分，返回 s2 - s1。

本题讲解：动态优先数调度与饥饿

第（1）问：为什么 priority = nice 会饥饿

答题框架：指出 nice 静态不变 → 就绪队列里可能总有人优先数更小 → 大优先数进程永远轮不上 → 饥饿。

具体分析：nice 由用户在进程创建时指定，是静态优先数，一经设定不再改变。调度策略是每次选就绪队列中 priority 最小的进程运行。若系统中不断出现 nice 更小（优先级更高）的进程在就绪队列中排队，则 nice 较大的进程虽然也在就绪队列里，却始终排在后面、长期得不到 CPU——这就是饥饿现象。

第（2）问：动态优先数设计

答题框架：给出公式 → 说明三项各朝哪个方向拉扯优先级 → 点明 waitTime 的作用。

设计方法：priority = nice + k1 × cpuTime - k2 × waitTime，其中 k1 > 0，k2 > 0 为可调参数。

  • 进程处于执行态时 cpuTime 定时加 1、waitTime 置 0：连续占用 CPU 越久，priority 越大（优先级越低），会被其他进程顶下去，防止长期霸占 CPU；
  • 进程处于就绪态时 cpuTime 置 0、waitTime 定时加 1：等待越久，priority 越小（优先级越高），迟早成为队列中最小者而获得调度。

waitTime 的作用：对长时间等待的进程做动态补偿——随等待时间减小优先数、提升优先级，保证就绪已久的进程在有限时间内一定能被调度到 CPU，从而避免饥饿。

一句话记忆：cpuTime 惩罚"跑得久"的进程，waitTime 补偿"等得久"的进程。
