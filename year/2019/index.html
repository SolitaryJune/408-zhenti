算法和算法评价
选择题 2 分

设n是描述问题规模的非负整数，下列程序段的时间复杂度是__。

x = 0;
while (n >= (x + 1) * (x + 1))
    x = x + 1;
答案

答案：B

▶本题解析视频（B 站）
1

本题讲解：数循环次数求时间复杂度

答案：B（O(n^1/2)）。 思路：先弄清"循环体到底执行多少次"，再看这个次数随 n 增长的阶。

第一步：读懂循环条件

x = 0 起步，每轮先判断 n >= (x+1)*(x+1)，成立才执行 x = x + 1。循环体没有任何别的动作，所以 x 能涨到多大，循环就执行多少次——只要求出 x 的终值即可。

第二步：解出 x 的终值

循环一直进行到 (x+1)² > n 为止，即退出时 x + 1 > √n，故 x 的终值约为 √n，循环体执行 ⌊√n⌋ 次。

用 n = 100 验证：x = 0 时判断 100 ≥ 1² ✓，一路执行到 x = 9 时判断 100 ≥ 10² = 100 ✓ 仍执行，x 变成 10 后判断 100 ≥ 11² = 121 ✗ 退出。共执行 10 次，恰好 √100 = 10。

第三步：写出复杂度

基本操作 x = x + 1 执行 f(n) = ⌊√n⌋ 次，判断语句多执行 1 次但同阶，所以 T(n) = O(√n) = O(n^1/2)。

易错点

  • 把 x 当成翻倍增长：若循环体是 x = x * 2 才是 O(logn)（A 项的误区来源），本题是每次加 1。
  • 只看循环形式猜阶：见到单个 while 就猜 O(n)（C 项）或被条件里的平方吓到选 O(n²)（D 项），都必须先解出循环变量终值。
  • 纠结判断多执行一次：最后一次失败的判断不计入循环体次数，且与循环体同阶，不影响 O 记号。
口诀：循环变量终值是多少，循环就跑多少次；本题终值约 √n。

选择题 2 分

若将一棵树T转化为对应的二叉树BT，则下列对BT的遍历中，其遍历序列与T的后根遍历序列相同的是__。

答案

答案：B

▶本题解析视频（B 站）
2

本题讲解：树的后根遍历对应二叉树的哪种遍历

答案：B（中序遍历）。 树转二叉树用"左孩子、右兄弟"规则，记住两条对应关系：树的先根遍历 = 二叉树的先序遍历；树的后根遍历 = 二叉树的中序遍历。

第一步：写出转换规则

树 T 的每个结点 X：第一个孩子变成 BT 中 X 的左孩子，其余孩子依次链接为第一个孩子的右兄弟链。因此 BT 的根只有左子树（装着 T 根的所有孩子），右子树为空。

第二步：推导"后根 = 中序"

树的后根遍历：先依次后根遍历 T 的各棵子树，最后访问根 R。在 BT 中看这件事：

  • T 的各子树整体挂在 R 的左子树里（第一棵子树作左孩子，兄弟链向右延伸）；
  • BT 中序 = 左子树中序 → 根 → 右子树（空）。对左子树递归下去，访问次序正好是"先各子树、最后根"。

所以 BT 的中序遍历序列与 T 的后根遍历序列逐个相同。

第三步：小树验证

T 为 R(A(D,E), B, C)，转换后按两种方式各遍历一遍：

遍历序列
T 的后根遍历D E A B C R
BT 的中序遍历D E A B C R
T 的先根遍历R A D E B C
BT 的先序遍历R A D E B C

两组序列完全一致，验证了结论。

易错点

  • 看名字像就选"后序遍历"（C 项）：BT 的后序是"左→右→根"，右兄弟链的访问位置与树的后根对不上，是最常见陷阱。
  • 混淆先/后根：与 BT 先序对应的是树的先根遍历（A 项），不是后根。
  • 以为按层遍历（D 项）也保序：层序在两种结构之间没有这种对应关系。
记忆：左孩子右兄弟——先根对应先序，后根对应中序。

选择题 2 分

对n个互不相同的符号进行哈夫曼编码。若生成的哈夫曼树共有115个结点，则n的值是__。

答案

答案：C

▶本题解析视频（B 站）
3

本题讲解：哈夫曼树的结点总数公式

答案：C（58）。 哈夫曼树是"没有度为 1 的结点"的二叉树，抓住这条性质列方程即可。

第一步：哈夫曼树的结构性质

建哈夫曼树时每次取出两棵最小的子树合并，新结点必有两个孩子；n 个叶子两两合并，任何结点都不可能只有 1 个孩子。所以树中只有两类结点：度为 0 的叶子（即 n 个符号）和度为 2 的分支结点。

第二步：列方程求解

设叶子数 n0 = n，度为 2 的结点 n2 个。

  1. 二叉树通用性质：n0 = n2 + 1（叶子比二分支结点多一个），故 n2 = n − 1。
  2. 结点总数：n0 + n2 = 115。

代入：n + (n − 1) = 115 → 2n − 1 = 115 → n = 58。

（可直接背公式：哈夫曼树总结点数 = 2n − 1，n 为叶子数。115 + 1 = 116，÷2 = 58。）

第三步：验证

n = 58 时：叶子 58 个、分支结点 57 个，合计 115 ✓。从 58 个叶子开始两两合并，58 个叶子变成 1 棵树需要 57 次合并，每次合并恰好新增 1 个分支结点，吻合。

易错点

  • 以为存在度为 1 的结点：按普通二叉树三种子结点情况去算会卡住，哈夫曼树没有度为 1 的结点。
  • 公式记错方向：总结点数 = 2n − 1，不是 2n 或 2n + 1；选项 D（60）可用 2×60−1 = 119 ≠ 115 排除。
  • 把 115 当叶子数：115 是总结点数，n 才是叶子数，别反着代入。
结论：哈夫曼树结点总数 = 2 × 叶子数 − 1。

树形查找
选择题 2 分

在任意一棵非空平衡二叉树（AVL 树）T1 中，删除某结点 v 之后形成平衡二叉树 T2，再将 v 插入 T2 形成平衡二叉树 T3。下列关于 T1 与 T3 的叙述中，正确的是__。

I. 若 v 是 T1 的叶结点，则 T1 与 T3 可能不相同
II. 若 v 不是 T1 的叶结点，则 T1 与 T3 一定不相同
III. 若 v 不是 T1 的叶结点，则 T1 与 T3 一定相同

答案

答案：A

▶本题解析视频（B 站）
4

本题讲解：AVL 删除结点后再插入，树形会复原吗

答案：A（仅 I 正确）。 关键认识：删除可能触发旋转改变树形；插入按二叉排序树规则落到叶位，不会把旋转过的树转回去，所以删除与插入不互逆。

第一步：拆命题 I（v 是叶结点，T1 与 T3 可能不相同）

"可能不相同"是存在性命题，举出一个不相同的例子即可成立。设 T1 中 v 是叶结点，其父结点 p 的另一棵子树更高：删除 v 后 p 失衡，AVL 旋转调整，树形改变；再把 v 插回，插入位置沿查找路径落到叶层，插入后平衡因子恢复合法，不会再发生旋转把树转回原样，于是 T3 ≠ T1。当然，若删除不引起旋转，T3 也可以与 T1 相同。所以 I 正确。

第二步：拆命题 II 与 III（互为"一定"，但都可能被反例打倒）

  • II（非叶 → 一定不相同）错：反例——v 只有一个孩子，删除时用该孩子接替 v 的位置，全程无旋转；再插入 v，按 BST 性质恰好落回原来的叶位置，树形完全复原，T3 = T1。
  • III（非叶 → 一定相同）错：反例——v 是内部结点，删除时用前驱/后继填补引发旋转；插入 v 后不再转回，T3 ≠ T1。

两个"一定"各被一个反例否定。

第三步：结论

仅 I 正确，选 A。

易错点

  • 忽略"插入不撤销旋转"：插入引发的旋转只服务于插入路径，不会恢复删除时改变的结构，这是本题的机制核心。
  • 把"可能不相同"读成"一定不相同"：存在性命题只需一个例子，措辞审题要细。
  • 以为删除内部结点一定旋转：用前驱/后继填补后可能并不失衡，旋转是"可能"不是"必然"。
记忆：删除会"变形"，插入只"长叶"，二者不互逆。

  • ve(2) 算成 3：只看 1→2 的 a=3，漏掉经由 1→3→2 的 c+b=12 才是最大值。
口诀：最早看弧尾 ve，最迟 = 弧头 vl − 活动时长。

选择题 2 分

用有向无环图描述表达式((x+y)*((x+y)/x))，需要的顶点个数至少是__。

答案

答案：A

▶本题解析视频（B 站）
6

本题讲解：表达式共享 DAG 的最少顶点数

答案：A（5 个）。 把表达式画成 DAG 的核心：相同的操作数与公共子表达式只画一个顶点，多处引用共享它。

第一步：先看不共享的表达式树

表达式 ((x+y)*((x+y)/x)) 完全展开成二叉树需要：运算符 4 个（*、/、+、+），操作数 5 个（x、y、x、y、x），共 9 个结点——这正是选项 D 的干扰来源。

第二步：合并公共子表达式

  • 子表达式 (x+y) 出现 2 次 → 两个 + 结点合并为 1 个；
  • 操作数 x 出现 3 次、y 出现 2 次 → 各合并为 1 个结点。

第三步：数合并后的 DAG 顶点

顶点说明
x3 处共用 1 个
y2 处共用 1 个
+两处 (x+y) 共用 1 个
*根，1 个
/1 个

共 5 个顶点。结构：t = +(x,y)；根 * 的左孩子是 t、右孩子是 /；/ 的左孩子也是 t、右孩子是 x。读回验证：*( t, /(t, x) ) = ((x+y)*((x+y)/x))，与原表达式一致。

易错点

  • 选 D（9）：画成不共享的表达式树，忘了 DAG 的本职就是合并公共子式。
  • 选 B（6）：只合并了两个 (x+y)，忘了 x、y 本身也是重复出现的操作数结点，合并必须做到底。
  • 题目问"至少"：只要还存在重复顶点，就还能继续共享减结点，不能提前停手。
记忆：DAG 顶点 = 不同操作数种类 + 不同子式个数；本题 x、y、+、*、/ 各一个 = 5。

各种内部排序算法的比较及应用
选择题 2 分

选择一个排序算法时，除算法的时空效率，下列因素中，还需要考虑的是__。
I. 数据的规模
II. 数据的存储方式
III. 算法的稳定性
IV. 数据的初始状态

答案

答案：D

▶本题解析视频（B 站）
7

本题讲解：选择排序算法要考虑哪些因素

答案：D（I、II、III、IV 全部需要考虑）。 这是教材结论型考点：没有万能的排序算法，选型是多因素权衡。

第一步：逐项核对

  • I 数据的规模：要考虑。n 很小时直接插入排序、简单选择排序就够用（实现简单、常数小）；n 很大必须用快速排序、堆排序、归并排序等 O(nlog₂n) 算法。
  • II 数据的存储方式：要考虑。快速排序需要两端相向移动、堆排序靠数组下标映射父子关系，都依赖顺序存储；链式存储只适合插入、选择、归并类算法。
  • III 算法的稳定性：要考虑。关键字上挂着成绩、金额等附加信息时，稳定排序能保证同关键字记录的原有先后次序不乱（如按分数排完再按学院排的场景）。
  • IV 数据的初始状态：要考虑。序列基本有序时直接插入排序可达 O(n)、冒泡排序可提前结束；而快速排序在基本有序时枢轴总落在端点，退化到 O(n²)。

第二步：结论

四个因素都是选择排序算法的现实依据，全选，答案 D。

易错点

  • 漏选 II：以为存储方式与算法无关——快排、希尔、堆排都默认顺序存储，链式结构下难以高效实现。
  • 漏选 IV：以为复杂度只由 n 决定——快排最坏情况恰恰由初始排列（基本有序/基本逆序）触发。
  • 漏选 III：以为稳定与否无所谓——对含附属信息的记录，稳定性是硬需求，且它是很多真题判定"哪趟结果"的工具。
记忆：选型四看——规模、存储、稳定性、初始状态。

散列（Hash）表
选择题 2 分

现有长度为11且初始为空的散列表 HT，散列函数是 H(key) = key % 7，采用线性探查（线性探测再散列）法解决冲突。将关键字序列 87,40,30,6,11,22,98,20 依次插入 HT 后，HT查找失败的平均查找长度是__。

答案

答案：C

▶本题解析视频（B 站）
8

本题讲解：线性探测散列表的查找失败平均查找长度

答案：C（6）。 分两件事：先把 8 个关键字插进表里，再对每个可能的散列地址模拟一次"注定失败"的查找。

第一步：依次插入（H(key) = key % 7，冲突则线性向后探查）

关键字H(key)探查路径落位探测次数
8733 空31

3022 空21
666 空61
1144 空41

最终 HT：0=98，1=22，2=30，3=87，4=11，5=40，6=6，7=20，8~10 空。

第二步：查找失败的 ASL

查找失败的判定标准是"探测遇到空单元"。散列函数可能取到 0~6 共 7 个地址（分母是模数 7，不是表长 11），从每个地址出发探到第一个空位：

  • H=0：探 0,1,…,8（8 号才空）→ 9 次
  • H=1：8 次；H=2：7 次；H=3：6 次；H=4：5 次；H=5：4 次
  • H=6：探 6、7，8 号空 → 3 次

合计 9+8+7+6+5+4+3 = 42，ASL(失败) = 42 / 7 = 6。

易错点

  • 分母用表长 11：失败查找只可能从 H(key)=0~6 这 7 个初始地址开始，除以 7 才得 6；除以 11 是最经典错误。
  • 漏掉 20 的冲突：20 落位 7 号用了 2 次探测，且正是 7 号被占，才把各地址的失败探测一路拖到 8 号空位。
  • 失败判定停早了：线性探测要一直走到"空"才算失败结束，不能只查一趟散列函数的位置。
口诀：失败 ASL = Σ(每个散列地址走到第一个空位的步数) ÷ 模数。

DMA（直接存储器存取）传送分三步：预处理（初始化）→ 数据传送 → 后处理。数据传送本身由 DMA 控制器掌管总线完成，CPU 只在前后两端介入。拿这个框架逐条核对四句话。

答题框架

"原地重排链表"题的固定套路是三步走：快慢指针找中点 → 原地逆置后半段 → 前后半段交替合并。三步各扫一遍链表，只用几个指针变量，正好满足"空间 O(1)、时间尽可能高效"。以 n=6 为例：中点 a3，后半段逆置为 a6,a5,a4，交替合并得 (a1,a6,a2,a5,a3,a4)，正是要求的 L'。

  • 交替合并：s=h->next; q=p->next; p->next=NULL; while(q!=NULL){ r=q->next; q->next=s->next; s->next=q; s=q->next; q=r; }，把后半段结点逐个插进前半段的缝隙里。

  • 尽可能多就餐：若 m < n−1，碗是更紧的资源，bowl 初值取 m 可把碗用满；若 m ≥ n−1，取 n−1 即可，再多只会重新引入死锁风险。

易错点

  • 只设筷子信号量、不设 bowl：n 人各抓一根筷子仍会全体阻塞，m 个碗也没有使用限制。
  • bowl 初值直接写 m：当 m ≥ n 时起不到限流作用，必须取 min(m, n−1)。
  • P、V 顺序随意：标准写法是先拿碗再拿筷、先还筷后还碗。
一句话结论：chopstick[n] 初值 1 管互斥，bowl 初值 min(m, n−1) 管限流，一限一互斥，既不死锁又让尽可能多的哲学家同时就餐。
