本题讲解：链表指针语句的执行效果（结点搬移）

第一步：画链定标，逐句模拟

先画出链：头结点 → A（首元）→ P（p 所指）→ Q → R → ⋯，p 指向中间结点 P。四条语句逐句执行，每句只改一两个指针域：

语句改了什么效果
q = p->nextq 定向q 指向 P 的后继结点 Q
p->next = q->nextP 的 nextP 跨过 Q 直接链向 R，Q 脱离主链
q->next = h->nextQ 的 nextQ 的 next 指向原首元结点 A
h->next = q头结点的 next头结点改链 Q，Q 成为第一个数据结点

第二步：写出最终链

沿头结点走一遍：头结点 → Q → A → ⋯ → P → R → ⋯。可见 q 所指结点被摘下并移动到头结点之后，p 始终指向原结点 P 没有动。答案选 D。

易错点

  • 选 C（把 p 移到头结点后）：被搬运的是 q 所指结点；p 的指针值从头到尾没被赋值语句改过。
  • 选 A/B（以为在做插入）：全程没有新结点产生，也没有把 p 插到 q 后，只是把已有的 Q 结点搬到了表头。
  • 忽略语句次序：必须先用 q->next（此时它还是 Q 的原后继）更新 p->next，若次序颠倒，Q 的后继就丢了，链会断。
一句话结论：后两条语句合起来就是「头插法搬结点」——先把 q 从链中抽走，再插到头结点之后，选 D。

第一步：先定优先级和结合性

中缀式 x+y*(z-u)/v：括号最优先，*、/ 高于 +；* 与 / 同级、从左到右结合。后缀式的写法是：运算符紧跟在它的两个操作数之后。推荐思路：从最内层括号向外逐层「剥」。

第二步：逐层转换

层中缀片段后缀
1括号 (z-u)zu-
2y * (z-u)yzu-*
3(y*(z-u)) / v（同级左结合，先乘后除）yzu-*v/
4x + (…)xyzu-*v/+

第 3 层是题眼：* 与 / 同级左结合，必须先算 y*(z-u) 再除以 v，所以除号跟在整个 yzu-* 之后。

第三步：排除干扰项

  • B xyzu-v/*+：先算 (z-u)/v 再乘 y，乘除次序与左结合不符，是另一棵运算树。
  • C +x/*y-zuv、D +x*y/-zuv：运算符在操作数前面，是前缀式，不是后缀式。

答案选 A。反向验证：扫 xyzu-*v/+，zu-→z-u，*→y*(z-u)，/→y*(z-u)/v，+→x+y*(z-u)/v，与原式一致。

易错点

  • 同级不按左结合：把除法当成先算，误选 B。
  • 前缀后缀不分：看到 + 在最前面就选，掉进 C/D 的坑。
  • 漏括号：* 的右操作数是整个 (z-u)，不是 z。
一句话结论：从最内层括号往外剥、同级先左后右，得 xyzu-*v/+，选 A。

本题讲解：中序序列 …,p,v,q,… 的隐含条件

第一步：认清 p 和 q 的身份

中序序列形如 …, p, v, q, …，说明 p 是 v 的中序前驱、q 是 v 的中序后继。题干又给了关键条件：v 有两个孩子。

第二步：定位前驱和后继

v 有两个孩子时，标准结论是：

  • 中序前驱 = 左子树中最右边的结点（从左子树根一路向右走到底）；
  • 中序后继 = 右子树中最左边的结点（从右子树根一路向左走到底）。

第三步：推出孩子的有无

  • p 是「一路向右」的终点：若 p 还有右孩子，就能继续向右，p 就不是最右结点、当不了前驱 —— 矛盾。所以 p 必定没有右孩子（有无左孩子都可能）。
  • q 是「一路向左」的终点：若 q 还有左孩子，就能继续向左，q 就不是最左结点、当不了后继 —— 矛盾。所以 q 必定没有左孩子（有无右孩子都可能）。

答案选 A。小树验证：v 左子树为 a→右孩子 b 时中序为 a, b, v，前驱 b 无右孩子；右子树为 c→左孩子 d 时中序为 v, d, c，后继 d 无左孩子。

易错点

  • 选 B（q 有左孩子）：把「后继在右子树里」错记成「右子树任意结点」，忽视了要走到最左。
  • 选 C/D（p 有右孩子）：只看到 p 在 v 之前，没想到「有右孩子就能再往右」会推翻前驱身份。
  • 忽略前提：本题结论依赖「v 有两个孩子」；若 v 只有一个孩子，前驱/后继可能沿祖先链找，结论不成立。
一句话结论：有双孩子的结点，其前驱是左子树最右结点（无右孩子），后继是右子树最左结点（无左孩子），选 A。

本题讲解：折半查找的适用条件

第一步：折半查找靠什么工作

折半查找每次取区间中点 mid，用 key 与中点比较后舍弃一半。这要求两个前提同时成立：

  1. 关键字有序 —— 否则比较完 mid 也判断不出该往哪一半找；
  2. 支持随机存取 —— 必须能 O(1) 直接取到第 mid 个元素，这只有顺序存储（数组）做得到。

第二步：逐个结构检查

Ⅰ 有序链表✓✗（取 mid 要沿链走 O(n)）不适合
Ⅱ 无序数组✗✓不适合
Ⅲ 有序静态链表✓✗（游标链式，定位仍是 O(n)）不适合
Ⅳ 无序静态链表✗✗不适合

易错点

  • 漏掉静态链表（误选 A）：静态链表虽用下标存放，但逻辑次序靠游标维持，物理下标≠逻辑位次，取「第 mid 个」不能一步到位，与普通链表同样不适合。
  • 只看有序（误选 A）：有序不等于能折半，链式存储是硬伤。
  • 只看存储（误选 B）：数组即便能随机存取，无序时折半逻辑根本不成立。
一句话结论：折半 = 「有序」且「随机存取」，缺一不可；四个结构全不合格，选 D。

第一步：回顾一趟划分

快排一趟 = 一次划分：选定枢轴 pivot，把其余 n−1 个元素分成两块，左块 P 中元素 ≤ 枢轴，右块 Q 中元素 ≥ 枢轴，划分结束时枢轴落到最终位置。题设 P、Q 均非空。判断性质只用这个事实，别多想。

int uniquely(MGraph G) {
    int *degree, i, j, count = 0;
    degree = (int *)malloc(G.numVertices * sizeof(int));
    for (j = 0; j < G.numVertices; j++) {
        degree[j] = 0;
        for (i = 0; i < G.numVertices; i++) {
            degree[j] += G.Edge[i][j];
        }
    } // 建立入度表degree[]
    int zero_count, zero_vertex;
    while (count < G.numVertices) {
        zero_count = 0;
        zero_vertex = -1;
        for (j = 0; j < G.numVertices; j++) {
            if (degree[j] == 0) {
                zero_count++;
                zero_vertex = j;
                if (zero_count > 1) break; // 超过一个入度为0的点，退出
            }
        }
        if (zero_count != 1) { // 有多个或没有入度为0的结点
            free(degree);
            return 0;
        }
        count++;
        degree[zero_vertex] = -1;
        for (j = 0; j < G.numVertices; j++) {
            if (G.Edge[zero_vertex][j] > 0) {
                degree[j]--;
            }
        }
    }
    free(degree);
    return 1;
}

本题讲解：数组访问指令序列、地址计算与小端读数

答题框架

sum += a[i] 编译为四条指令：算元素字节偏移（slli）→ 加数组首地址（add）→ 取元素（lw）→ 累加（add）。三问的落点分别是：寄存器分工、地址/页/小端机器数的十六进制计算、指令编码拼装。

第（1）问：三个变量各在哪个寄存器（3 分）

  • slli r4, r2, 2：R[r4] = R[r2] << 2 = R[r2] × 4——int 占 4 字节，"下标 × 4"是字节偏移，所以 r2 存变量 i；

第（2）问：地址、机器数、页号与页数（5 分）

已知 i = 5，R[r1] = 0000 1332H（sum），R[r3] = 0013 DFF0H（首地址）。

S 初值为 0 表示 B 初空：P2 的 wait(S) 在 P1 未写入前会阻塞；P1 写完执行 signal(S) 把 S 增为 1，唤醒 P2 执行 C2。只需这 1 个信号量（「B 为空」由 S=0 天然表达，无需再设互斥信号量）。

第（3）问：B 初非空，P1、P2 各修改一次

两个 C3 都要修改 B，谁先谁后都可以，但不能同时进行——这是互斥关系。定义 1 个互斥信号量 mutex=1：

进程代码
P1wait(mutex); C3; signal(mutex);
P2wait(mutex); C3; signal(mutex);

mutex 初值 1：任一进程 wait(mutex) 进入后其余进程被挡在门外，修改完 signal(mutex) 释放。

易错点

  • 第（2）问多设 mutex：只有一写一读，S 本身就完成了「先写后读」的同步，再加 mutex 违背「信号量尽可能少」。
  • 第（2）问把 S 初值设为 1：S 的语义是「已有数据可读」，B 初空，初值必须为 0。
  • 第（3）问误用同步信号量：两个 C3 无先后次序要求，只有互斥要求，用 mutex=1 包裹各自的 C3 即可。
结论：第（1）问 C1 是临界区；第（2）问用 S=0，P1：C1→signal(S)，P2：wait(S)→C2；第（3）问用 mutex=1，双方 wait(mutex)→C3→signal(mutex)。

本题讲解：RIP/OSPF 选型、TTL、RIP 收敛与 BGP 选路（2024 大题）

题目背景：AS1 内部网关协议为 RIP（每 30 s 交换一次距离向量）；AS3 内任意两主机通信经过路由器数不超过 15 个；AS4 内可能超过 20 个。网络 136.5.16.0/20 由 AS2 的 R22、AS3 的 R33、AS4 的 R44 一侧可达。

第（1）问：AS4 应选哪个内部网关协议

答题框架：先看协议的适用规模限制，再对照 AS4 的规模描述。

RIP 规定最大距离为 15（16 表示不可达），只适合小网络；OSPF 没有跳数限制。AS4 内任意两主机通信经过的路由器数可能超过 20 个，超出 RIP 的 15 跳上限，故 AS4 应选择 OSPF。

第（2）问：AS3 内通信的初始 TTL 至少多少

答题框架：TTL 每经过一个路由器减 1，减为 0 就丢弃；用「最多经过的路由器数 + 1」定下限。

AS3 内通信最多经过 15 个路由器。若初始 TTL = 15，经过 15 个路由器后 TTL 减为 0，分组会在到达目的主机前被丢弃；因此初始 TTL 至少要 16，最坏情况下也能正常到达被接收。

第（3）问：R11～R16 均获正确路由至少需要多久

答题框架：RIP 每 30 s 交换一次距离向量，且每轮交换发送的是更新前的路由表，信息一轮只前进一跳；对每个目的网络分别推演扩散轮数。

  • 210.2.3.0/24 直连 R14：初始距离向量交换（t = 0）后，邻居 R11、R15 即获得正确路由；t = 30 s 第一次周期交换后，R12（经 R11）、R13（经 R15）、R16（经 R15）也获得。此时 R11～R16 均正确 → 至少 30 s。
  • 210.2.4.0/24 直连 R16：初始交换后 R13、R15 获得；t = 30 s 交换后 R12（经 R13）、R14（经 R15）获得，但 R11 的邻居 R12、R14 在那一轮交换的仍是各自旧表，R11 仍未获得；到 t = 60 s 第二次周期交换时 R11 才获得 → 至少 60 s。

第（4）问：BGP 会话类型与报文

答题框架：先分清通信双方是否同属一个 AS，再对应外部/内部会话与报文类型。

R44（AS4）与 R13（AS1）分属不同 AS，向 R13 通告到达网络 136.5.16.0/20 的路由由 BGP 外部会话（eBGP） 完成；通告使用 UPDATE 报文。R13 与 R14、R15 同属 AS1，R13 通过 BGP 内部会话（iBGP） 把该可达性信息通告给 R14 和 R15。

第（5）问：R14、R15 更新后的下一跳

答题框架：BGP 选路先比 AS 路径条数（最短优先）；等长时再比到下一跳的 IGP 开销（AS1 内即 RIP 距离）。

三条可达信息：经 R11 的 AS 路径 AS2 AS8 AS19（3 个 AS）；经 R13 的 AS4 AS10 AS19（3 个 AS）；经 R12 的 AS3 AS7 AS11 AS19（4 个 AS）——经 R12 的路径最长，先被淘汰。经 R11 与经 R13 的 AS 路径等长，比较到下一跳的 RIP 距离：

路由器到 R11到 R13选择的下一跳
R141（直连）2（经 R15）R11
R152（经 R14）1（直连）R13

所以 R14 路由表中下一跳是 R11，R15 路由表中下一跳是 R13。

易错点

  • 第（1）问答 RIP：忽略了「可能超过 20 个路由器」撞上 RIP 15 跳上限。
  • 第（2）问答 15：TTL 减到 0 就丢弃，等于最多路由器数时可能送不到目的主机，要再加 1。
  • 第（3）问两网都答 30 s：只推演了 210.2.3.0/24；R11 距 R16 三跳，210.2.4.0/24 要两轮周期交换（60 s）才能传到 R11。
  • 第（3）问忽略"交换旧表"：同一轮交换中各路由器发出的是更新前的距离向量，信息一轮只前进一跳。
  • 第（5）问直接按字典序或 IP 大小选：BGP 比的是 AS 路径条数，等长再比到下一跳的 IGP 开销。
一句话结论：AS4 用 OSPF；初始 TTL 至少 16；210.2.3.0/24 全部正确至少 30 s、210.2.4.0/24 至少 60 s；R44→R13 走 eBGP（UPDATE 报文），R13→R14/R15 走 iBGP；R14 下一跳 R11、R15 下一跳 R13。
